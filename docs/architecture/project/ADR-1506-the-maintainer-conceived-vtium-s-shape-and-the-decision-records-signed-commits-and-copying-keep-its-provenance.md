# ADR-1506: The maintainer conceived vtium's shape, and the decision records, signed commits and COPYING keep its provenance

## Summary

- **Decided:** The maintainer conceived vtium's shape: vtium itself, frits, the configuration as one flow, the way character sets compose in a frit, and the unified image pipeline. The decision records hold each of these in the maintainer's direction, and this record names where. vtium keeps the provenance of its work in places it already has. The decision records keep the maintainer's direction in the maintainer's own words, dated, with the channel each answer came through, as they do now. The maintainer stays the git author of every commit and, from 2026-11-10 on, signs every commit with an SSH key. COPYING says plainly that agents write vtium's code under the maintainer's direction and review. vtium adds no transcript archive, no commit trailer and no separate mark for text the maintainer writes by hand.
- **Trades away:** The stronger evidence that the research names: quotes kept only verbatim, hashed archives of the session transcripts, a mark on the maintainer's hand-written text, and a git identity for agents. 61% of the maintainer's entries in the records are agents' paraphrases, and the practice that produces them stays.
- **One-way?** No. Each practice the record leaves out can be added later. A signature on a pushed commit stays in the history, and the commits made before 2026-11-10 stay unsigned.
- **Probes:** *Confident:* the maintainer wants the records kept as they are now, with no new marking or archive. *Settled 2026-11-10:* the maintainer added four parts to the five D1 first named.
- **Inversion:** Between "the law decides who conceived vtium" (the record would rest on case law that has not settled the question) and "the conception speaks for itself" (nothing dated would show where it came from). The answer names what the maintainer conceived, points to the dated records that hold it, and keeps the law to a short note of its limits.

## Context

One person, the maintainer, owns vtium and directs it. AI agents write almost all of its code and documents under that direction. The maintainer wants vtium's records to show the maintainer's creative control and authorship of the work.

In vtium, ADR means Agent Decision Record. The project borrowed the familiar acronym of the Architecture Decision Record and gave it its own meaning. An Agent Decision Record holds a decision and its provenance. Provenance here means the record of where the work came from: who decided, in what words, through which channel, and when. Agents draft each record, and the maintainer directs and approves it. The maintainer's words sit in a record's `basis` and `considered` entries, each with its date and channel.

A signed commit is a commit that carries a cryptographic signature made with the maintainer's SSH key. Because each git commit names its parent by hash, a signed commit also fixes the exact content of the whole history before it.

## Decision

### D1: The maintainer conceived vtium's shape, and the records hold it

The maintainer conceived the ideas below, and named them in the account this record keeps in its `considered` entries. Each line names the record that holds the idea, and quotes the maintainer's words from that record where the record has them.

- **vtium itself**, a Rust terminal that runs on a Linux virtual terminal in place of getty: ADR-1000 records its target set, from the maintainer's comment of 2026-10-26, "in general, vtium should cover what other terminals support".
- **Frits**, the font set files that list the fonts a console draws from, in order: ADR-1200 D1 defines them, and ADR-1200 quotes the maintainer's direction, posted from the maintainer's GitHub account in an agent's wording: "frits, the definition the engine draws from (`NAME.vtfrit`)".
- **The configuration as one flow**, from the displays to the input devices: ADR-1403 holds it, and quotes the maintainer's model, posted from the maintainer's GitHub account: "vtium's configuration describes one flow, from the displays to the input devices".
- **The way character sets compose**, where each later font in a frit fills only the characters the earlier fonts lack, and a `cover=` line limits a font to a named character set such as GB2312 or Big5: ADR-1200 D1 holds the rule, and no record quotes the maintainer's own words on it.
- **The choice of image pipeline, and the single unified image pipeline**, where every image protocol feeds one store of placements: ADR-1100 holds it, and quotes the issue posted from the maintainer's GitHub account: "One image pipeline, shared by both protocols". ADR-1101 puts the decoding of images in a sandboxed helper program of its own.
- **Parts, templates and paths**, the way vtium-config builds a configuration: the parts the system finds, made from templates, composed into paths, then added to the configuration. ADR-1403 D7 holds it, with the maintainer's words: "parts, from the system -> composed into a flow, configurable -> added to the config, to be integrated with other flows" and "I think this pattern resolves some of the hard coding we have, and gives the parts purpose."
- **Terminals tied to VTs**, so one display and keyboard can carry several terminals, placed by one state machine under the maintainer's policy table: ADR-1401 D2 and D3 hold it, with the maintainer's words: "the terminals in the middle, are variants - they're not bound to each VT, but VT3, VT4, and VT5 - that's what allows all three flows to exist in CONFIGURATION (so they're unique)" and "we are, slowly through description, building the policy state machine basically".
- **Effects inside the terminal**, where filters and shaders are a subflow of the terminal and a display is only an output: ADR-1403 D7 holds it, with the maintainer's words: "So, this means that the terminal itself defines the effects, and the display is just a display output."
- **The records as provenance**, where the Agent Decision Records keep the maintainer's words, dated, beside signed commits: D2 to D5 of this record hold it, with the maintainer's words: "it records provinence as well as decisions". It changes no behaviour, in the maintainer's words: "generally, the records as provenance doesn't need any changes to behavior. I just wanted to make sure we've recorded it."

An agent given only the request "Make a KMSCON replacement in rust make no mistakes" would have had none of these ideas to build from.

### D2: The decision records are vtium's provenance record

Each decision record keeps the maintainer's direction in the maintainer's own words, with the date and the channel the words came through. This is how vtium works now, and it stays that way. vtium adds no archive of the session transcripts, no hashes of them, and no rule that every entry be verbatim. An agent that records the maintainer's words follows the record tool as it does now: it quotes a written channel verbatim, and it marks a summary with `paraphrase: true`.

### D3: The quotes in the records mark the maintainer's own expression

When the maintainer writes or rewrites something, the quote kept in a record is the mark of the maintainer's own expression. vtium adds no commit trailer and no separate marking for it.

### D4: The maintainer stays the git author, and COPYING discloses how the code is written

The maintainer stays the author and the signer of every commit, as the person who directs, reviews and signs the work. Agents do not get a git identity of their own, and their commits carry no trailer. COPYING and this record say plainly that agents write vtium's code under the maintainer's direction and review. COPYING points to this record.

### D5: Every commit is signed with the maintainer's SSH key from 2026-11-10 on

Signing began at 2026-11-10T13:19:37-06:00, and the first signed vtium commit is 2589ab1e. The maintainer's git configuration signs each commit and tag. A pre-push hook in `tools/git-hooks/` refuses a push that carries an unsigned commit made after signing began. Commits made before that moment keep their history as it is.

## The law, briefly

A steering session researched the law on 2026-11-10. Its report, `authorship/research.md` in the steering session's scratchpad, is research, not legal advice. The record does not rest on it. In short, with the report's confidence:

- Copyright in the United States needs a human author, and work made with an AI's help can still be protected. No court has said how much human direction is enough, and the Copyright Office has no guidance specific to code. Confidence: high. The sources are Thaler v. Perlmutter (D.C. Circuit, 18 March 2025) and the Office's report Copyright and Artificial Intelligence, Part 2: Copyrightability (29 January 2025).
- Code that agents wrote and the maintainer only chose or approved is probably not protected in the United States. Confidence: medium-high, from the same report.
- Copyright protects expression, not ideas or systems (17 U.S.C. § 102(b)). Confidence: high.
- The MIT license works either way. Where a part of vtium has no copyright, the license has nothing to grant for that part, and users lose nothing. Confidence: high.
- The research counted the entries attributed to the maintainer in vtium's 29 decision records. 395 of the 648 entries, 61%, are agents' paraphrases, not the maintainer's words. The maintainer chose to keep the practice as it is.
- Two questions need a lawyer: the wording of the copyright notice in LICENSE and COPYING, and whether to register vtium, with the registration's duty to disclose AI-generated material.

## Options the maintainer has not taken up

The research names two more practices. This record decides neither.

- **A third-party timestamp:** a service such as RFC 3161 or OpenTimestamps would fix the date of the signed history independently of the maintainer's clock.
- **The agent's proposal beside each decision:** each record would keep what the agent proposed next to what the maintainer decided, so that the records show where the maintainer departed from it.

## Consequences

### Positive

- The records name what the maintainer conceived and where each part was decided, in dated entries.
- No change gains a step. Agents keep recording the maintainer's words as they do now, and git signs each commit by itself.
- Every commit from 2026-11-10 on carries the maintainer's signature, and each signature fixes the history before it.
- COPYING says how vtium's code is written.
- The record stands on its own. No other record changes with it.

### Negative

- 61% of the maintainer's entries stay paraphrases, which are weaker evidence of the maintainer's words than quotes.
- Git's author field names the maintainer on commits that agents wrote. A reader of the history alone, without COPYING, could be misled.
- The session transcripts that hold the maintainer's typed words sit outside the repository, unsigned and unversioned.
- A signature's date rests on the maintainer's own clock, and the history before 2026-11-10 carries no signature.

### Neutral

- AGENTS.md's section on signed commits gives agents the rules for D5: an agent never turns signing off and never skips the hooks.
- COPYING gains one sentence that points to this record.

## Alternatives Considered

- **Keep only verbatim quotes, archive and hash the session transcripts, or publish them.** Rejected by the maintainer, who keeps the records as they are now.
- **Mark the maintainer's hand-written text, with a `Written-by:` trailer or the record tool's `authored` level.** Rejected by the maintainer: the quotes kept in the records are the mark.
- **Name agents in git, as the commit author or in a trailer on each agent commit.** Rejected by the maintainer, who stays the author and signer and discloses in COPYING.
- **Leave commits unsigned.** Rejected by the maintainer, who directed that commits be signed from 2026-11-10 on.
