# VTium 0.1.0-alpha.12

This is vtium's twelfth pre-release. vtium is a terminal for the Linux virtual console, written in Rust. It runs on a VT in place of getty, and it renders each frame itself, on the CPU or on the GPU. [Why VTium](../why-vtium.md) explains why you might choose it.

This release is about running most of vtium without root, and about faster scrolling on the CPU. The packages now build vtium as two processes. A small root process keeps the jobs that need root, and a drawing process reads your programs' output without root. When vtium renders on the CPU, a scroll moves the picture instead of redrawing every line.

## What is new

### Most of vtium runs without root

- **Two processes.** The packages build vtium with the `split` feature, the privilege split. A small root process holds the VT, opens the displays and the input devices, and starts `/bin/login` and the helpers. It also runs the power keys. Everything else runs in a drawing process as the system account `vtium`, which the package creates. The drawing process reads your programs' output, keeps each console's screen, and renders. See [Root for the console, fewer rights for the helpers](../concepts/security.md#root-for-the-console-fewer-rights-for-the-helpers) and [the privilege split issue](https://github.com/vtium/vtium/issues/406).
- **The drawing process holds no root powers.** It has none of root's capabilities, and it cannot gain any by starting another program. When you switch to another VT, the root process takes the displays and the keyboards away from it. When the drawing process ends for any reason, the root process puts the VT back in text mode.
- **Your sessions still survive a restart.** The root process keeps each session's terminal in systemd's store, as vtium in one process does. So a logged-in shell survives `systemctl restart`. See [Sessions that survive a vtium restart](../systemd.md#sessions-that-survive-a-vtium-restart).
- **check-config checks that the drawing process can read vtium.conf.** Both processes read `/etc/vtium/vtium.conf`. The root process takes each console's command and the power keys from its own reading, so the drawing process cannot change them. `vtium check-config` warns when the account `vtium` cannot read the file.
- **The accounts.** The package installs `/usr/lib/sysusers.d/vtium-split.conf`, from which `systemd-sysusers` creates the accounts `vtium` and `vtium-session`. Nothing runs as `vtium-session` yet. Without systemd, create the account `vtium` yourself. See [The privilege split's accounts](../systemd.md#the-privilege-splits-accounts).

### Faster scrolling on the CPU

- **A scroll moves the picture.** With the `scroll-pan` feature, which the packages build, vtium keeps each display buffer about two screens tall. A scroll moves the part of the buffer that the screen shows, so vtium draws only the new lines. Where the display's driver does not allow that, vtium copies the screen's part from drawn lines it keeps in memory. See [the faster scrolling issue](https://github.com/vtium/vtium/issues/432).
- **The `scroll-draw` key.** `auto`, the default, pans where the driver allows it and copies elsewhere. `pan` does the same, and logs a warning when the driver refuses the pan. `copy` always copies, and `redraw` redraws every line, as earlier releases did. A head that renders on the GPU always redraws. vtium's log says how each display shows a scroll. See [Configuration keys](../config.md).

### Where the text sits

- **Smooth scrolling's layout.** In a build with the `smooth-scroll` feature, `smooth-scroll = on` keeps the text's last row against the bottom of the screen. Screens rarely hold a whole number of rows, so some pixel lines are left over above the text. `partial-row` sets what they show: `history`, the bottom of the row above in the scrollback, or `blank`, or `fade`. A look and a head can each set `smooth-scroll`, and a look can set `partial-row`. The packages leave this feature out. See [the smooth scrolling issue](https://github.com/vtium/vtium/issues/427).
- **The text stays centred by default.** With smooth scrolling off, and in every build without the feature, vtium centres the text on the screen. The pixels left over show the border's color on both sides, as in earlier releases.
- **The log names the pixels left over.** For each display whose size is not a whole number of character cells, vtium logs one line. An example is `Display DP-3 is 5120×1440 and holds 465 columns of 11 pixels and 65 rows of 22 pixels, so 5 pixel columns and 10 pixel lines are left over.`

### Fonts

- **A program can switch to a font by its path.** OSC 50 takes the absolute path of a font that root has installed and trusts, and vtium builds a font set of that one font. The query then reports the path, so a program can switch back to it. OSC 50 also takes the name of a font family that a head's configuration gives. See [OSC 50, the font change](../sequences/text.font-change.md).
- **`font-name` takes any font file's path.** The value can be the absolute path of a PSF, BDF, `.hex`, TrueType or OpenType font. vtium chooses how to read the file by its extension, so `font-engine = psf` is no longer needed for a PSF font.
- **Box lines and blocks from a font fill their cell.** Where a font set takes box drawing and block elements from an outline font, they reach the cell's edges and meet their neighbors. They also stay upright under synthetic italic. See [the block elements issue](https://github.com/vtium/vtium/issues/469).
- **Bold text and symbols show sooner.** After the first screen's text, vtium asks the font helper for bold printable ASCII at once. Punctuation, arrows and geometric shapes now arrive with the first screen's letters.
- **A font set's unknown lines are skipped alone.** vtium ignores an unknown or misplaced key in a font set or one of its layers, and logs it with its file and line. The rest of the font set still draws. `vtium config new-frit` prints a warning for each such line.

### vtium-config

- **The Fonts tab tries one font.** In a vtium console, `t` tries the highlighted font on the console for 10 seconds, and `k` keeps it until you quit. The console takes only a font that root has installed, activated and trusted, so on any other font `t` says why it cannot try it. See [The Fonts tab](../configure.md#the-fonts-tab) and [the issue about trying a single font](https://github.com/vtium/vtium/issues/452).
- **`t` on a look tries the whole look.** The trial now sends the look's font set, its color scheme and, with `allow-window-ops` on, its size. When the trial ends, vtium-config gives the console back the colors it had, including colors a program set before. A font or color scheme file that is not active gets an offer to activate it.
- **`u` puts the console back.** When a font or size you tried leaves the console too small for the TUI, `u` puts back the font and size the console started with.
- **The key line says what Esc keeps.** On a card, a part's detail or a settings section, the key line now reads `back, keep changes`. Esc goes back with your changes, and `s` saves them into the draft.
- **More keys on the command line.** `vtium config look add` and `look set` take `--vtlook`, `--smooth-scroll` and `--partial-row`.

### vtium.conf

- **An unknown key in a section drops only its line.** vtium ignores a key it does not know in a head or a look, and reads the rest of the section. So does a known key in a section that does not take it. Before, the whole head or look was dropped. So a vtium.conf written for a newer vtium still runs on this one. `vtium check-config` still reports the key. See [The head file](../head-file.md) and [the formats issue](https://github.com/vtium/vtium/issues/343).
- **The `helper-sandbox` key.** `helper-sandbox = off` turns off the seccomp filters and landlock of the font and image helpers. Use it only when vtium runs inside another sandbox whose kernel refuses the filters. The rest of the helpers' limits stay, and `vtium check-config` notes the setting. See [Root for the console, fewer rights for the helpers](../concepts/security.md#root-for-the-console-fewer-rights-for-the-helpers).
- **Kernels without seccomp filters.** On a kernel built without them, both helpers run without the filters, and vtium logs why once a boot.

### Releases

It also checks the tag's signature and the draft's whole set of files. See [the release files issue](https://github.com/vtium/vtium/issues/348).

Tier 2 gains a screen of Legacy Computing characters ([#457](https://github.com/vtium/vtium/issues/457)), and tier 3 stops seatd while vtium holds the seat ([#456](https://github.com/vtium/vtium/issues/456)). ## What this release does not do yet

- **Smooth scrolling does not slide yet.** `smooth-scroll = on` sets where the text sits, but a scroll still moves the text by whole rows. vtium ignores DECSCLM, the sequence a program sends to switch smooth scrolling. See [the smooth scrolling issue](https://github.com/vtium/vtium/issues/427).
- **The GPU path does not show the rows above the text.** With smooth scrolling on, a head that renders on the GPU shows the border's color in the pixel lines above the text, whatever `partial-row` says. In a build with `scroll-pan`, the CPU path shows them as `partial-row` says. The same issue tracks the GPU path's part.
- **The split does not work with a seat manager yet.** Where seatd serves vtium's seat, or in seat mode under logind, vtium runs as one process, as root. It logs a line that says why. See [the privilege split issue](https://github.com/vtium/vtium/issues/406).
- **One drawing process holds every console of its VT.** If crafted output took over the drawing process, it could read and type into every session on that VT. A later part of the split gives each console a process of its own, under the account `vtium-session`. The same issue tracks it.

## Fixes

- **Right-to-left text on double-size lines.** A double-width or double-height line now orders its text over the cells it shows. Before, a right-to-left paragraph could draw past the line's half. See [the double-size order issue](https://github.com/vtium/vtium/issues/454).
- **Pictures on double-size lines.** A picture placed on a double-size line starts where its cell is drawn. A kitty placeholder picture keeps its aspect there, and a child placement starts from where its parent is drawn.
- **Underlines on a cleared screen.** On a screen that shows only spaces, an underline stays at the font's own position. Before, it could drop to the cell's bottom row. See [the underline issue](https://github.com/vtium/vtium/issues/462).
- **Unifont's double underline.** At twice its size, Unifont's double underline draws below the letters. See [the double underline issue](https://github.com/vtium/vtium/issues/463).
- **Displays unplugged from older drivers.** A display removed from a card without atomic modesetting is now turned off at once. See [the CRTC issue](https://github.com/vtium/vtium/issues/455).
- **DRM master.** vtium drops DRM master only where it holds it, so the log no longer says `cannot drop DRM master: Invalid argument`. A card that could not report its master state takes master at its first wake-up.
- **Keyboards in seat mode.** When a display server takes the seat while vtium probes a keyboard, vtium probes it again at the next wake-up. Before, the keyboard never typed. See [the device probe issue](https://github.com/vtium/vtium/issues/468).
- **A stray log line.** The log no longer says `Received an event for non-existent source` after a flip or a removed card. See [the event loop issue](https://github.com/vtium/vtium/issues/467).
- **A font whose cell answer comes late.** When the font helper reported a font's character cell late, vtium could give up on that font. It then drew its built-in font for the rest of the boot. vtium now waits for the answer.
- **Size trials of bitmap font sets.** In vtium-config, a size trial of a bitmap font set now asks for the grid the console draws at that size. Before, some sizes tried nothing.
- **The panic screen's words.** The panic screen now says `No display head can run`, so a reader who does not know the word "head" sees that it means a display.

## Upgrading from 0.1.0-alpha.11

On Arch, upgrade as usual. The package creates the accounts `vtium` and `vtium-session`.

Five changes can alter what you see after the upgrade:

- vtium runs as two processes on each VT that no seat manager serves. `ps` shows both, and the drawing process runs as `vtium`. Keep `/etc/vtium/vtium.conf` readable by every account, as a fresh install leaves it.
- A head that renders on the CPU pans or copies a scroll. At 1920×1080 with three buffers, as the packages use, that takes about 24 MiB more memory. `scroll-draw = redraw` scrolls as before.
- A head or a look with an unknown key no longer drops out. vtium runs it without that key's line.
- A font set with a key after a `layer=` line, or with a `strike=` line under a built-in font, now draws. vtium ignores those lines, where it used to refuse the font set.
- The panic screen's second line reads `No display head can run`.

An upgrade never restarts a running vtium. Each VT runs the new build from its next start, for example after `sudo systemctl restart vtium@tty3.service` for VT 3, run from another VT or over ssh. A logged-in shell on that VT survives the restart.

makepkg checks this tag's signature against the same key as before, `33F9B54FD2A4B6A4110749B3BA464FC9847A832A`.

Please report what you find at https://github.com/vtium/vtium/issues, with the output of `vtium-config report`. Reports from people who run the privilege split, or who scroll a lot on a CPU-rendered head, are especially welcome.
