# VTium 0.1.0-alpha.1

This is vtium's first pre-release. vtium is a terminal for the Linux virtual console, written in Rust. It runs on a VT, one of the full-screen text consoles the kernel provides, takes the display through KMS/DRM or the older fbdev framebuffer, and draws the terminal itself. It needs no display server and does not rely on systemd. Its tests compare its screens and replies, as text and pixel for pixel, with saved results from the C programs vtium started from, the terminal `kmscon` and its library `libtsm`. vtium is a program of its own: it installs under its own names, reads its own configuration, and runs beside a `kmscon` package without touching it.

If you are new to vtium, [Why VTium](https://github.com/vtium/vtium/blob/v0.1.0-alpha.1/docs/why-vtium.md) says why you might choose it over the kernel's console, `kmscon` or a desktop terminal, and [the concepts page](https://github.com/vtium/vtium/blob/v0.1.0-alpha.1/docs/concepts.md) introduces vtium's pieces and how they fit together.

An alpha is for people who want to try vtium on their own machines and report what they find. Each problem the packaged vtium shows becomes an issue, so please file one at https://github.com/vtium/vtium/issues.

## Installing it

vtium is packaged for Arch Linux on the AUR (the Arch User Repository) as two packages:

- `vtium` builds this release from the tag `v0.1.0-alpha.1`. makepkg checks the tag's signature against the maintainer's key, `33F9B54FD2A4B6A4110749B3BA464FC9847A832A`, so import that key into your keyring before the first build, with `gpg --recv-keys 33F9B54FD2A4B6A4110749B3BA464FC9847A832A`, or with `gpg --import keys/pgp/33F9B54FD2A4B6A4110749B3BA464FC9847A832A.asc` in a clone of the AUR repository.
- `vtium-git` builds the tip of vtium's `main` branch.

The two conflict, so a machine holds one of them. Each also installs `vtium-terminfo` (or `vtium-terminfo-git`), the terminfo entry `xterm-vtium` that vtium's sessions name in `TERM`. Build either one with your AUR helper, or by hand with `makepkg -si` in a clone of its AUR repository. The packages build vtium's minspec console, its default and smallest build; `VTIUM_FEATURES='images logind' makepkg -si` builds the console with other features.

The packages install what `make install` stages in a checkout, so a package and a hand install hold the same files:

- `/usr/bin/vtium` and the glyph helper `/usr/bin/vtium-vitrify`;
- the units `vtium@.service` and `vtium-getty@.service`, its getty fallback;
- `/etc/vtium/vtium.conf.example`, an example configuration with every key and its default.

Installing the package gives vtium no VT. You choose the VTs with `vtium console`:

```sh
sudo vtium console enable --all     # every VT is vtium's from its next start
sudo vtium console enable 3         # or only VT 3
sudo vtium console disable --all    # every VT goes back as vtium console found it
```

`vtium console enable --all` leaves VT 1 to a display manager that starts there, leaves every VT that kmscon or a graphical session holds, and refuses while `autovt@.service` links to kmscon's unit. It also refuses while someone is logged in on VT 6, logind's reserved VT, outside a vtium running there. `vtium console disable` restores each unit it changed as it was. An upgrade replaces the files and never restarts a running vtium, so the new build runs from each VT's next start. The section [Setting it up](https://github.com/vtium/vtium/blob/v0.1.0-alpha.1/crates/vtium/README.md#setting-it-up) in the console's README covers sharing VTs with kmscon and using ssh from vtium.

vtium reads its configuration from `/etc/vtium/vtium.conf` only, and never from kmscon's `/etc/kmscon/kmscon.conf`, so a change to one program's file never changes the other's. Copy the example to `/etc/vtium/vtium.conf` to start one. The keys are the ones kmscon used, and [docs/config.md](https://github.com/vtium/vtium/blob/v0.1.0-alpha.1/docs/config.md) says how to move a kmscon file across.

To build from a checkout, vtium needs Rust 1.88 or later. The checkout's `rust-toolchain.toml` names the toolchain vtium is tested with, 1.99.1, which rustup installs on the first build.

## What works

- **Displays.** vtium draws into DRM dumb buffers, plain memory buffers the display scans out, with atomic modesetting where the card offers it and the legacy calls where it does not. On fbdev it draws at 32, 24, 16 or 1 bit. It follows displays as they are plugged in and out, powers them down after an idle time, and draws in four orientations.
- **Sharing the card.** vtium hands the display over cleanly when you switch to another VT, whether that VT runs a Wayland compositor, an X server, a getty or another vtium, and takes it back when you return.
- **Heads.** One vtium process drives every display it finds. A head is a terminal for one or more displays, with its own grid, font and consoles, and a console is one session with its own login, screen and scrollback. With no configuration, vtium runs one head on every display. The head file, `/etc/vtium/heads.conf`, puts displays, keyboards and pointers into heads by first-match rules, and its closed policy isolates each head for a kiosk. `vtium check-config FILE` checks a head file before you install it.
- **Input.** vtium reads keyboards and pointers from their devices, with libxkbcommon for the keymap. The pointer selects text, the middle button and Shift+Insert paste it, and programs can copy into the selection with OSC 52. Keys can be bound to reboot, power off and suspend.
- **Fonts.** A frit (a font set file) lists a font's sources in order. The helper `vtium-vitrify` reads PSF, kbd, BDF and outline fonts, color emoji included, and rasterizes them outside the console. When vtium runs as root, the helper runs as `nobody`. Unifont and Unscii-8 are built into the console and draw every character a frit lacks. `vtium-vitrify set` switches the running console's font, and Ctrl+= and Ctrl+- zoom it. vtium's source tree holds [`tiny5.vtfrit`](https://github.com/vtium/vtium/blob/v0.1.0-alpha.1/crates/vtium-vitrify/frits/tiny5.vtfrit), an example frit for Tiny5 Mono, a pixel font whose capitals are 5 pixels tall. It shows the smallest font vtium draws: at its 6x9 cell a 320x240 display holds 53x26 cells, where the built-in 8x8 font gives 40x30. It is never a default; a person who wants it installs the frit and the font by hand. Its [specimen](https://github.com/vtium/vtium/tree/v0.1.0-alpha.1/docs/specimens/320x240-tiny5) is provisional.
- **The terminal.** vtium draws 24-bit color, the 256-color palette and named palettes, bold, faint, strike, blink, reverse, and underline in five styles with colors of their own. It cuts text into grapheme clusters and draws wide characters and emoji. It reports the mouse, focus, bracketed pastes and in-band resizes, holds frames for synchronized output, and answers XTGETTCAP, XTVERSION and DECRQM. A reply to a query is built from vtium's own state and never repeats bytes a program sent. ADR-1000 lists every mode and feature vtium supports, ignores or refuses.
- **Identity.** Sessions get `TERM=xterm-vtium`. vtium answers terminal queries the way programs that know kmscon, xterm and kitty expect, so they keep working on vtium instead of falling back to an unknown terminal.
- **Scrollback and reflow.** Each console's scrollback is bounded in bytes, and when the width changes vtium rewraps the screen and its scrollback and carries the cursor, the selection and the view with them. The bound holds after any resize.
- **Small machines.** The minspec build is made for a single-board computer with ARM cores of the Cortex-A53 class or older and 512 MB of memory or less. On a guest with 1 vCPU and 512 MB, its binary is 3,216,864 bytes and its peak resident memory at 640x480 is 7.77 MiB.
- **Without systemd.** Another init can run `vtium --vt=ttyN --no-switchvt` where it ran a getty. Tier 3 boots vtium under sysvinit on Debian 13.

## Security

- The glyph helper's zstd decoder is `ruzstd` 0.9.1, which fixes RUSTSEC-2026-0344. The helper reads a zstd-compressed font whose window is 16 MiB or less, which covers `zstd` at its default levels and at `-19`. It refuses a font with a larger window as it reads the frame's header, with a warning that names the window and says the font needs recompressing with a window of 16 MiB or less.

## Known limits

- **Pictures from files and shared memory are not drawn yet.** In a build with the `images` feature, vtium decodes sixel and kitty graphics sent as raw pixels and draws them on the CPU. The image helper, the separate program that is to decode files, shared memory, PNG and zlib as the session's user, is not part of this release, so vtium answers each such kitty request as it would with no helper running. iTerm2 inline images have no handler yet. The packaged minspec build carries no picture code.
- **The GPU renderer is not built.** Every build draws on the CPU, and the `hwaccel` key only warns at start.
- **No libseat.** vtium opens the VT, the cards and the input devices itself, as root.
- **Links on screen.** Ctrl+click copies an OSC 8 link's address, Ctrl+Shift+Up and Ctrl+Shift+Down move the view between the prompts OSC 133 marks, and the link under the pointer draws a dashed underline, but the renderer does not yet show the link's address while Ctrl is held.
- **Not built yet:** glyph ink reaching into the next cell, ligatures and shaping across cells, the bold and italic faces of outline fonts, the kitty keyboard protocol, bidirectional text, input methods, `vtiumctl`, `vtium-clipboard`, the font builder and preview, and reloading the head file without a restart. `font-hinting` and `font-line-spacing` are accepted and checked, but nothing reads them yet.
- **Packages.** The AUR packages are built for x86_64. The minspec build also cross-builds for aarch64 and armv7 with `make arm` in a checkout.

## How this release is judged

vtium's gates are the unit tests, tier 1's conformance replays against goldens saved from the C programs vtium started from, the capability probes, tier 2's pixel tests, the ARM builds, and a build at Rust 1.88. Tier 3 boots vtium's install tree on a VT of a QEMU/KVM guest and compares its screens to goldens pixel for pixel. Where vtium differs from a golden, the difference is a listed departure or the test fails. vtium's own tier 3 goldens are provisional until the maintainer reviews them. Before the tag, the maintainer checked this build by eye on a real VT.
