# VTium 0.1.0-alpha.8

This is vtium's eighth pre-release. vtium is a terminal for the Linux virtual console, written in Rust. It runs on a VT in place of getty, and it renders each frame itself, on the CPU or on the GPU. [Why VTium](../why-vtium.md) explains why you might choose it.

This release is about scripts that need room, and about a VT switch that no longer waits for slow display work.

## What is new

### Font sets for other scripts

A font set, or frit, is a short text file in `/etc/vtium/fonts` that lists the fonts vtium renders text with.

- **Font sets for scripts with marks.** vtium ships five font sets: `arabic`, `hebrew`, `indic`, `thai-lao` and `vietnamese`. Each one names the Noto font for its script and makes the rows taller. The script's marks then use the added room, so they stay clear of the next row. Box drawing still stretches over the whole row, so the lines of a box still join.
- **Font sets for Chinese, Japanese and Korean.** vtium ships four more font sets: `cjk-sc`, `cjk-tc`, `cjk-jp` and `cjk-kr`. Each one uses the Noto Sans CJK face for one region's forms of Han characters. Every one of them renders Chinese, Japanese and Korean text, so you choose the set for the forms you read.
- The guide [Fonts for other scripts](../fonts-for-scripts.md) says how to install a set, use it on one head or on all of them, and change its line spacing. See [the issue for ready-made font sets](https://github.com/vtium/vtium/issues/204) for what is still to come.
- **vtium checks who owns a font set.** vtium reads a font set only when root owns it and no other user can change it or a folder above it. This is the same check that vtium.conf passes. `vtium check-config` reports a font set that fails it. See [the font set ownership issue](https://github.com/vtium/vtium/issues/388).

### Indic and Arabic text

- **A syllable takes the width programs expect.** In Tamil, Devanagari and other scripts of South and Southeast Asia, some syllables now take two character cells. These are the syllables with a spacing vowel sign, and those where a virama joins two consonants. The rule is Python wcwidth's, so a shell's line editor counts the same cells that vtium renders. For example, the Tamil syllable கொ takes two cells and renders at full size.
- **The `cluster-width` setting.** `cluster-width = single` keeps each syllable in one cell and squeezes it to fit. This suits programs that count one cell for each syllable, such as Neovim. The default is `double`.
- **A syllable is shaped as one piece.** Unicode's rules sometimes split one syllable into several clusters. vtium now shapes such a syllable once and renders it across all of its cells. A bitmap font shows each piece in its own cell. See [the syllabic scripts issue](https://github.com/vtium/vtium/issues/144) for these three changes.
- **Indic letters fit their cells.** An Indic letter or cluster that is wider than its cells is squeezed sideways to fit, at full height. Its vowel signs and conjuncts no longer overlap or get cut ([the Devanagari issue](https://github.com/vtium/vtium/issues/261)).
- **Arabic in narrow cells.** An Arabic letter that is narrower than its cell keeps its own width, and the font's tatweel fills the rest of the cell. A lam-alef ligature stands against the right edge of its two cells ([the Arabic issue](https://github.com/vtium/vtium/issues/389)).

### Glyphs wider than their cells

- **A wide bitmap glyph is squeezed, not cut.** A glyph from a bitmap font that is wider than its character cells is now squeezed into them. For example, Unifont's 16-pixel Devanagari letters now show whole in one 8-pixel cell. See [the squeeze issue](https://github.com/vtium/vtium/issues/245).
- **No glyph loses a column.** vtium renders a font set's own glyph first, and squeezes any glyph that is too wide. A color emoji that takes one cell, such as ❤ with no variation selector, is shrunk to fit. It may reach one pixel into each neighbouring cell.

### VTs and displays

- **Switching away no longer waits for slow display work.** vtium now checks for a VT release between the steps of its display work. A display manager therefore gets its VT without waiting for a slow mode change or a slow probe of the connectors. See [the VT release issue](https://github.com/vtium/vtium/issues/296).
- **A graphical program can borrow vtium's displays.** A program in a console sends `OSC setBackground ST` to hand a head's displays to a graphical program, such as a video player or a kiosk application. It sends `OSC setForeground ST` to take them back. vtium also takes them back when that console's session ends, when you switch away and back, or when vtium restarts. The `allow-display-ops` setting turns this on or off.
- **Focus reports.** A program that asks for focus reports learns when it loses the display and when it gets the display back. This happens at a hand-over and at a VT switch.
- **vtium keeps trying to take its displays back.** When vtium fails to wake its displays, it tries again once a second for as long as its VT is shown. See [the display hand-back issue](https://github.com/vtium/vtium/issues/36) for these three changes.
- **Very large displays render on the GPU.** A display larger than the GPU's largest texture now renders on the GPU too. A head that stays on the CPU gives its GPU memory back. See [the large display issue](https://github.com/vtium/vtium/issues/297).
- **A graphics card that arrives late.** The kernel announces a new graphics card before vtium can open it. vtium now opens such a card at the card's next event, instead of dropping it ([the multi-monitor issue](https://github.com/vtium/vtium/issues/35)).
- **A VT where no head runs.** Under the open policy, when vtium.conf has errors, vtium lights the default terminal on the boot display of such a VT. That terminal shows a login prompt and the error line. Under the closed policy, the boot display shows the notice alone. The rescue key's notice now shows on each display too.
- **Seat mode waits for its VT.** With seatd, vtium opens the seat when the kernel says vtium's VT is shown. vtium tries a busy seat again only while that VT is shown.

### The closed policy and the font helper's sandbox

- **Displays that no rule places stay blank.** Under a closed vtium.conf, a display that no rule names stays blank on every machine. This includes a machine without kernel VTs. See [the unplaced display issue](https://github.com/vtium/vtium/issues/400).
- **`vtium.enable=0` works with a closed vtium.conf.** vtium honors this kernel command line option when it trusts the closed file. The [security page](../concepts/security.md) says what happens when vtium cannot read a closed file.
- **The font helper is sandboxed on every kernel.** The font helper is the separate process that renders glyphs from font files. On a kernel without Landlock, it now installs a fallback seccomp filter. vtium reports which sandbox the font helper runs in. See [the security gaps issue](https://github.com/vtium/vtium/issues/396).

### The on-screen display and the panic screen

- **`osd = silent`.** This new level of the on-screen display hides vtium's status and its ordinary notices. vtium still writes each notice to its log. A panic still shows at every level. A new page, [the on-screen display and notices](../concepts/osd-and-notices.md), explains each level. See [the osd issue](https://github.com/vtium/vtium/issues/399).
- **The panic screen shows a penguin.** A build with image support shows it as a picture, and other builds show it in ASCII. The text always comes first ([the panic screen issue](https://github.com/vtium/vtium/issues/162)).
- **The panic screen fits a small display.** On a small display, the panic screen crops its picture to the monitor.

### The kitty keyboard protocol

- **Repeats, releases and more modifiers.** A program can ask for key repeats and key releases. NumLock, Hyper and Meta count as modifiers, and mode 1035 now sees NumLock ([the NumLock issue](https://github.com/vtium/vtium/issues/356)). vtium's own key bindings ignore Caps Lock.
- **Flags 4, 8 and 16.** vtium now supports the protocol's flags 4, 8 and 16, and its rule for key releases. With flag 2, 4 or 16 alone, keys follow the specification's legacy section. Keypad keys then report as their main keys.
- See [the kitty keyboard issue](https://github.com/vtium/vtium/issues/42) for details.

### Images

- **kitty images sent in chunks.** vtium's handling of a kitty image sent in several chunks is rewritten from the published specification alone. vtium also answers the specification's feature queries.
- **kitty animation fixes.** Editing a frame that is not on show no longer makes vtium redraw cells. A delete that names both `i` and `I` is answered the way a put is.
- **Images respect the left and right margins.** Sixel, kitty and iTerm2 images now place and scroll inside all four margins ([the image margins issue](https://github.com/vtium/vtium/issues/358)).

### The rest

- **OSC 50 can return to the starting font.** A program can switch back to the font a head started in, by the name that OSC 50's query reported ([the starting font issue](https://github.com/vtium/vtium/issues/382)).
- **OSC 52 clipboard text is UTF-8.** vtium stores the text a program sets as UTF-8. It puts U+FFFD in place of bytes that are not valid UTF-8 ([the OSC 52 issue](https://github.com/vtium/vtium/issues/101)).
- **vtium-config refuses a line that is too long.** vtium-config shows a plain message instead of writing a vtium.conf line longer than vtium reads ([the line length issue](https://github.com/vtium/vtium/issues/354)).
- **A restart keeps its sessions after a stop.** When vtium restarts, it takes back the sessions it kept running. If job control or a debugger stops vtium during that step, vtium now resumes and adopts the sessions when it continues.
- **New and expanded pages.** [Security](../concepts/security.md) explains who runs with which rights and what a program in a session can make vtium do. [How vtium works](../concepts/how-vtium-works.md) shows its processes in figures. [Flows](../concepts/flows.md) explains how keyboards reach displays. [Seats and sessions](../concepts/seats-and-sessions.md) shows what each seat mode looks like. [Troubleshooting](../troubleshooting.md) maps each error screen's first line to the section that explains it.

## Known departures from the kitty specifications

vtium departs from the kitty specifications in these places in this release. See [the issue that makes vtium follow the specifications](https://github.com/vtium/vtium/issues/408), which changes them in 0.1.0-alpha.9.

- Under flag 1 or 8, the keypad's Begin key sends `CSI 57427 u`. The specification's table gives `CSI E`.
- With no flags set, Ctrl+Shift+I, Ctrl+`, Ctrl+Backspace, Alt+Shift+Tab and Shift+F3 send bytes that differ from the specification's legacy section.
- A palette change does not recolor an indexed image that vtium has already stored.
- vtium refuses `f=8` and `f=16` images sent from a file, and those compressed with `o=z` ([the image formats issue](https://github.com/vtium/vtium/issues/332)).
- One graphics error reply ends in a line feed.
- A placement named as its own parent gets the reply EINVAL. The specification gives ECYCLE.
- When vtium stacks images, it does not treat an image with no id as id 0.

## Upgrading from 0.1.0-alpha.7

On Arch, upgrade as usual. The optional `vtium-fonts` package now installs the nine font sets in `/etc/vtium/fonts`. It depends on `noto-fonts` and `noto-fonts-cjk`, which hold the fonts the sets name.

Three changes can alter what you see after the upgrade:

- vtium now refuses a font set that root does not own, or that another user can change. vtium then renders with its built-in fonts and logs the reason. Run `vtium check-config` to see whether a font set of yours fails the check.
- Under the default `cluster-width = double`, an Indic syllable with a spacing vowel sign or a joined consonant takes two cells. To keep each syllable in one cell, set `cluster-width = single` in `/etc/vtium/vtium.conf`. vtium reads this key when it starts.
- `allow-display-ops` is on by default. A program in the console that a head shows can then hand that head's displays to a graphical program. To turn this off, write `no-allow-display-ops` in vtium.conf.

An upgrade never restarts a running vtium. Each VT runs the new build from its next start, for example after `sudo systemctl restart vtium@tty3.service` for VT 3, run from another VT or over ssh. A logged-in shell on that VT survives the restart.

makepkg checks this tag's signature against the same key as before, `33F9B54FD2A4B6A4110749B3BA464FC9847A832A`.

Please report what you find at https://github.com/vtium/vtium/issues, with the output of `vtium-config report`. Reports from people who read Indic, Arabic, Hebrew, Thai, Lao, Vietnamese, Chinese, Japanese or Korean text on the console are especially welcome.
