# VTium 0.1.0-alpha.3

This is vtium's third pre-release. vtium is a terminal for the Linux virtual console, written in Rust: it runs on a VT, takes the display through KMS/DRM or fbdev, and draws the terminal itself, with no display server. [Why VTium](https://github.com/vtium/vtium/blob/v0.1.0-alpha.3/docs/why-vtium.md) says why you might choose it.

## What is new

- **A VT that comes back after the desktop.** A vtium that has run a while wakes its display again after a desktop has held it and moved the screen to another display engine (a CRTC). Before, it could stay black until restarted. This showed on multi-stream DisplayPort monitors and cards with several display engines (#249).
- **Kitty graphics sent in chunks.** Inside an upload sent in pieces, vtium now treats each command the way kitty does, so programs such as kitty-doom draw. vtium also ends an unfinished upload when other output arrives between its pieces, at a reset, when the program exits, or when a piece names another image, so a program that dies mid-picture cannot spoil the next one (#251).
- **Draws only when the screen changed.** A flood of output no longer redraws frames that look the same (#242).
- **`vtium-config`.** Run with no command, it prints its help; `vtium-config tui` opens the interactive tool, and `vtium-config --help TOPIC` explains a topic.
- **vtium.conf** is laid out in sections and groups, with each setting explained in wrapped paragraphs.
- **Text.** Spacing marks stand beside their letter, and outline fonts draw the underline and strike at the font's own lines.
- **A GPU renderer, not yet switched on.** The groundwork of vtium's GPU path is in, behind the `gpu` feature: it draws every test screen the same as the CPU path, pixel for pixel, under Mesa's software renderer. It is not used on a VT yet.
- **Fixes** to the glyph helper's late answers, the VT tools, and the fake VT used by tests.

## Upgrading from 0.1.0-alpha.2

Upgrade the `vtium` package as usual. An upgrade never restarts a running vtium. Each VT runs the new build from its next start, for example after you log out of it, or after `sudo systemctl restart vtium@tty3.service` for VT 3. makepkg checks this tag's signature against the same key as before, `33F9B54FD2A4B6A4110749B3BA464FC9847A832A`.

Please report what you find at https://github.com/vtium/vtium/issues.
