# VTium 0.1.0-alpha.4

This is vtium's fourth pre-release. vtium is a terminal for the Linux virtual console, written in Rust: it runs on a VT, takes the display through KMS/DRM or fbdev, and draws the terminal itself, with no display server. [Why VTium](../why-vtium.md) says why you might choose it.

This release is about making vtium easier to try and easier to report on.

## What is new

- **A documentation site,** at https://vtium.github.io/vtium/. It is sorted by what you are doing: a tutorial that tries vtium on one VT and puts everything back, how-to guides for installing, configuring and choosing fonts, reference pages, and the reasoning behind vtium's design. Its showcase shows vtium drawing text, emoji, pictures and several fonts.
- **`vtium-config report`.** It gathers what a bug report needs into one text file: the vtium builds installed and their features, the kernel and distribution, the state of each vtium console, the displays the kernel sees, vtium's configuration, and each vtium console's log. It leaves out the machine's hostname and each monitor's serial number, and it changes nothing on the machine. `vtium-config report --save` writes the file; run as root, it writes no file, so save its output with `sudo vtium-config report > vtium-report.txt`. `--previous-boot` gathers the logs of the boot before this one, for a vtium that left the screen black.
- **What to try when something goes wrong.** The [troubleshooting guide](../troubleshooting.md) covers getting back to your desktop, a VT that shows nothing or stays black after you switch back to it, a font that does not load, and pictures that do not show. The bug report form on GitHub asks for the report.
- **`vtium --version`** now also prints the commit it was built from and the features it was built with.
- **The GPU renderer, still off.** Behind the `gpu` feature, it now draws pictures the way the CPU path does and limits the memory its glyph textures take. It is not used on a VT yet.

## Upgrading from 0.1.0-alpha.3

Upgrade the `vtium` package as usual. An upgrade never restarts a running vtium. Each VT runs the new build from its next start, for example after you log out of it, or after `sudo systemctl restart vtium@tty3.service` for VT 3. makepkg checks this tag's signature against the same key as before, `33F9B54FD2A4B6A4110749B3BA464FC9847A832A`.

Please report what you find at https://github.com/vtium/vtium/issues, with the output of `vtium-config report`.
