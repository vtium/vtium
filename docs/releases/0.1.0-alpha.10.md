# VTium 0.1.0-alpha.10

This is vtium's tenth pre-release. vtium is a terminal for the Linux virtual console, written in Rust. It runs on a VT in place of getty, and it renders each frame itself, on the CPU or on the GPU. [Why VTium](../why-vtium.md) explains why you might choose it.

This release is about making the console's colors fit the person who reads it. Presets correct the colors for color blindness, and a brightness floor keeps dark text readable under a single-color tint. Light color schemes such as Sunny put black text on a white background. All of this works on the Linux console itself, where no display server runs.

## What is new

### Colors that fit the reader

- **Corrections for color blindness.** vtium installs three vtlooks (look files) that correct the screen's colors: `protanopia`, `deuteranopia` and `tritanopia`. Each one moves the differences between colors that such a viewer cannot see into colors the viewer can tell apart. Grays, black and white stay as they are. Name one with `vtlook = deuteranopia` in vtium.conf, or choose it on a look's card in vtium-config. See [Preset vtlooks](../looks.md#preset-vtlooks).
- **Your own correction.** The `color-blind` filter takes a `kind`, a `mode` and an `amount`. With `mode = simulate`, it shows the screen as a viewer with that color vision deficiency sees it, so you can check a program's colors for that viewer. A lower `amount` applies only part of a correction. See [Color filters](../looks.md#color-filters).
- **A brightness floor for dark text.** Under a single-color tint, such as an amber phosphor, each color shows only how light it is. Dark blue text then nearly vanishes into a black background. The tint's `floor` lifts every color above black, while black stays black and the colors keep their order. With a floor of 0.3, the default palette's blue under amber rises from about 27,19,0 to about 95,66,0.
- **Sunny, black text on white.** Sunny, `sunny`, is vtium's own light color scheme, like the white consoles of 1990s Unix workstations. Its foreground and its text colors have a contrast ratio of at least 4.5:1 against the white background, the WCAG level for body text. So its yellow is a dark ochre. Colors 7 and 15 stay light on purpose, because programs paint status bars and highlights with them.
- **Kiln and more light schemes.** Kiln, `kiln`, is vtium's own dark color scheme: a warm near-black background with saturated colors. Every text color but the dim gray, color 8, reaches 4.5:1 against it. Catppuccin Latte, Tokyo Night Day and Gruvbox Light install as light schemes too. See [The color schemes vtium installs](../palettes.md#the-color-schemes-vtium-installs).
- **A color scheme for each display.** Each look can name a color scheme of its own with `palette`, so one display's terminal can show Sunny while another keeps a dark scheme. See [Choose a color scheme](../palettes.md#choose-a-color-scheme).

### Color schemes as files

- **Palette files.** A color scheme is a file, `NAME.palette`, in `/usr/share/vtium/palettes` for the schemes vtium installs or `/etc/vtium/palettes` for your own. vtium reads Ghostty's theme format as it is, so a color scheme written for Ghostty works unchanged. A file sets the 256 colors, the default text and background colors, and the colors of the cursor and the selection. See [The file format](../palettes.md#the-file-format).
- **The schemes vtium installs.** vtium installs 13 color schemes: Kiln and Sunny, Dracula, four Catppuccin flavors, four Tokyo Night styles, and Gruvbox's dark and light schemes. Each comes from its author's own repository under a permissive license, and the file names its source. The nine built-in palettes, such as `nord` and `solarized`, need no file.
- **Set it from the command line.** `vtium-config look set evening --palette catppuccin-mocha` gives the look `evening` that color scheme.

### Effects

- **Frame filters.** A vtlook chooses filters that change the finished picture before the display shows it. vtium has five color filters: `gamma`, `contrast`, `tint`, `color-blind` and `cube`. vtium merges a vtlook's filters into one color table, so each pixel costs one lookup however many filters the vtlook holds. The table reaches the text, the border, the pointer and vtium's own notices, and the CPU and GPU paths draw it alike. See [Looks and effects](../concepts/looks.md).
- **Preset vtlooks.** Beside the three corrections, vtium installs three phosphor presets: `amber`, `green` and `white`, which tint the screen like a monochrome monitor. Your own vtlooks go in `/etc/vtium/looks`, and a file there with a preset's name replaces the preset.
- **Displays a vtlook suits.** A vtlook's `[requires]` section can name the displays it suits, by color depth, size, density, frame rate or rendering path. A display that misses a requirement draws without the effect, and vtium logs which requirement it missed. See [Display requirements](../looks.md#display-requirements).
- **Color maps from .cube files.** Color grading and calibration tools save their corrections as `.cube` files. The `cube` filter maps each color through such a file, a 3D or 1D table in the format of Adobe's Cube LUT Specification 1.0. The file lives in `/etc/vtium/looks` and holds at most 16 MiB. See [Color tables from .cube files](../looks.md#color-tables-from-cube-files).
- **The packages build the effects.** From this release on, the `vtium` and `vtium-git` packages build the `filters` feature, so they apply each look's vtlook. `vtium --version` names `filters` on its `features` line when the build has it. The minspec builds still leave it out. See [the frame filters issue](https://github.com/vtium/vtium/issues/219).

### What vtium may use

- **One list of active resources.** vtium draws only from the resources that `/etc/vtium/batch.conf` lists: fonts, color schemes, `.cube` color maps, shaders and pointer themes. The file holds one absolute path on each line. Only root can change it, so only root decides what the console draws. See [Active resources and the trust rule](../concepts/resources.md).
- **One trust rule for every resource.** Root must own each listed file and every folder above it, and nobody else may write to them. No symbolic link may lie on the path. The file must sit on a filesystem that stays mounted, so a USB stick or a network share fails. vtium treats a file that fails a check as missing, and `vtium check-config` names the check it failed.
- **It works from the first start.** While `batch.conf` does not exist, vtium uses the list of a fresh install. That list holds vtium's own fonts, the console font that `/etc/vconsole.conf` names, the color schemes vtium installs and vtium's pointer pictures. Any other resource waits until you activate it, such as a `.cube` file or a color scheme of your own.
- **Activate from the command line.** `vtium config activate PATH --install` adds a resource to the list through sudo, and `vtium config deactivate PATH` takes it off the same way. `vtium config active` lists what is active now. See [Choosing what vtium may use](../install.md#choosing-what-vtium-may-use).
- **Changes take effect at the next login.** vtium reads `batch.conf` again each time a session ends, before the next login on that head. A font, a color scheme or a color map that you activate or deactivate then takes effect, and vtium needs no restart. A change to vtium.conf itself still waits until vtium next starts on the VT. See [When a change takes effect](../concepts/resources.md#when-a-change-takes-effect).
- **Fonts in your home folder.** vtium never renders a font in your own folder, such as `~/.local/share/fonts`, because root does not own it. `vtium config fonts --install-system FILE` copies such a font into `/usr/local/share/fonts` as root, and asks before it runs sudo. Then activate the installed copy. See [Active fonts](../fonts.md#active-fonts) and [the trust rule issue](https://github.com/vtium/vtium/issues/438).

### vtium-config

- **Six tabs.** `vtium config tui` has six tabs: Fonts, Effects, Looks, Flow, Settings and Help. The TUI opens on Flow, and the keys `1` to `6` go straight to a tab. When the keys of a screen do not fit on the key line, the line shows them in pages, and `.` shows the next page. See [The TUI](../configure.md#the-tui).
- **The Fonts tab finds your fonts.** The Fonts tab lists the font files on this machine, grouped by folder, with filters for bitmap or outline fonts, Nerd Fonts, color emoji and each script. Each font shows whether it is active and whether it passes the trust rule, and Space activates it. Enter opens the font's detail, where a font in your own folder can be installed as a system font. `vtium config fonts --files` lists the same files from the command line. See [The Fonts tab](../configure.md#the-fonts-tab).
- **The Effects tab previews an effect.** The Effects tab lists No filter, the presets and your own vtlooks, then the color maps and the shaders. As you move through the list, it shows a picture of the console with the highlighted effect applied, and leaves the live console alone. In a vtium console that draws a vtlook of its own, the line beside the picture says that the console draws the picture through that vtlook too. The picture needs a terminal that shows images. See [The Effects tab](../configure.md#the-effects-tab).
- **The Looks tab builds a look.** The Looks tab lists your looks, the font sets, the color schemes and the pointer themes. A look's card sets its font set, size, color scheme and vtlook, and its sizes come from the look's font. The tab previews the highlighted color scheme with its 16 colors and a line of text in its own colors. You make a new font set and try a font set on the console here too. See [The Looks tab](../configure.md#the-looks-tab).
- **Settings by section.** The Settings tab groups the settings into sections, such as Fonts and text, Colors and Key bindings, in the order of the example vtium.conf. See [The Settings tab](../configure.md#the-settings-tab).

### Fonts

- **Terminus out of the box.** When neither vtium.conf nor the system names a font, vtium renders in the font set `terminus`, bitmap Terminus at every size from 12 to 32 pixels. Every build installs Terminus, the outline set `cullet-mono` and GNU Unifont, which covers the characters that Terminus lacks. See [Choose a font](../fonts.md).
- **Sizes step through Terminus's sizes.** A font size, a zoom or a program's request for a text area now picks the Terminus size of that height. A zoom from 16 pixels steps through 18, 20, 22 and 24 pixels, and a font size that comes to 24 pixels draws a 12×24 cell.
- **A catalog of font sets.** vtium's font sets come in six categories: console fonts, classic hardware fonts, code-friendly fonts, Nerd Fonts, scripts and regions, and small panels. Each set names the fonts it needs, and shared layers add icons, color emoji and Unifont. The sets for other scripts are named after Noto, such as `noto-arabic` and `noto-cjk-jp`. See [The catalog of font sets](../concepts/fonts.md#the-catalog-of-font-sets) and [the font catalog issue](https://github.com/vtium/vtium/issues/413).
- **The built-in font holds code page 437.** vtium's built-in font now holds every character of IBM code page 437, 410 characters in all, at each of its three sizes.

### Man pages

- **A man page for each program.** `man vtium`, `man vtium-config`, `man vtium-clipboard` and `man vtium.conf` now work. vtium.conf(5) is generated from the same table of keys as [Configuration keys](../config.md), so it lists every setting. See [the man pages issue](https://github.com/vtium/vtium/issues/402).

## Fixes

- **Synchronized output shows every frame.** A program can wrap each frame in a synchronized update, mode 2026, so the screen never shows half a frame. vtium now shows each finished frame, even when the next frame's update starts in the same read. See [the synchronized output issue](https://github.com/vtium/vtium/issues/431).
- **Ink past a double-size line.** A double-size line now shows ink that reaches past its top or bottom edge, such as the ring of Å. Line marks and emoji keep the top of their character cell. See [the issue about ink at a line's edge](https://github.com/vtium/vtium/issues/417).
