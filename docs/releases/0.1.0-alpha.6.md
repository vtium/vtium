# VTium 0.1.0-alpha.6

This is vtium's sixth pre-release. vtium is a terminal for the Linux virtual console, written in Rust. It runs on a VT in place of getty and renders each frame itself, on the CPU or on the GPU, with no display server. [Why VTium](../why-vtium.md) explains why you might choose it.

This release is about text: right-to-left scripts, ink that reaches past its cell, and fonts that line up.

## What is new

- **Right-to-left text.** In a console built with the `bidi` feature, vtium lays out Arabic, Hebrew and other right-to-left text in the order the Unicode bidirectional algorithm gives. It joins Arabic letters, draws mirrored characters such as brackets as their counterparts, and moves the cursor, the selection, mouse reports and the arrow keys in display order. The paragraph modes that programs set (BDSM, DCSM, SCP, SPD and modes 1243, 2500 and 2501) are supported. The bar cursor stands on the side of a character that matches its direction.
- **Ink past the cell.** Accents, marks and tall glyphs now draw up to one row above and below their cell, as well as one cell to each side, so stacked Vietnamese accents and Arabic marks stay whole. Ink that reaches into a neighbouring cell is drawn under that cell's own text, and moving or scrolling text leaves nothing behind.
- **Fonts that line up.** Every font in a font set draws at the first font's size and on the first font's baseline, so CJK text, emoji, Hebrew and Arabic from fallback fonts sit on the same line as the Latin text around them. Emoji with emoji presentation draw from a color font when the font set has one.
- **Sessions survive a restart.** When vtium restarts, through systemd's descriptor store or `vtium hold`, the shells running on it keep running, and the display shows exactly the sessions it had.
- **Keys match xterm.** Every modified key and the keypad send xterm's sequences, and the terminfo entry's function keys F13 to F63 match xterm's.
- **Line spacing.** A look can add space between rows, and the glyphs stay inside each row's band.
- **Kitty graphics** convert 8-bit and 16-bit palette formats on arrival, and vtium's replies follow kitty's own.
- **The GPU path is on by default** in the AUR's `vtium` and `vtium-git` packages. A line holding `no-hwaccel` in `/etc/vtium/vtium.conf` turns it off.
- **Each release carries its dependencies' source**, `vtium-0.1.0-alpha.6-vendor.tar.zst`, so a package build can run with no network.

## Upgrading from 0.1.0-alpha.5

On Arch, upgrade as usual. The AUR packages change shape:

- `vtium` and `vtium-git` build `images logind gpu bidi` and turn the GPU path on by default. If you added a `hwaccel` line to `/etc/vtium/vtium.conf` for alpha.5, you can remove it.
- `vtium-terminfo` and `vtium-terminfo-git` are now packages of their own instead of being built by the console's recipe. Your AUR helper installs them as dependencies.
- `vtium-fonts` is new: a curated set of fonts chosen to go with vtium's font set files. It installs no font file itself; it depends on the distribution's font packages.

An upgrade never restarts a running vtium. Each VT runs the new build from its next start, for example after `sudo systemctl restart vtium@tty3.service` for VT 3; with this release, a logged-in shell on that VT survives the restart. makepkg checks this tag's signature against the same key as before, `33F9B54FD2A4B6A4110749B3BA464FC9847A832A`.

Please report what you find at https://github.com/vtium/vtium/issues, with the output of `vtium-config report`. Reports from people who read Arabic, Hebrew or another right-to-left script are especially welcome.
