# VTium 0.1.0-alpha.2

This is vtium's second pre-release. vtium is a terminal for the Linux virtual console, written in Rust: it runs on a VT, takes the display through KMS/DRM or fbdev, and draws the terminal itself, with no display server. [The first pre-release's notes](https://github.com/vtium/vtium/releases/tag/v0.1.0-alpha.1) introduce it, and [Why VTium](https://github.com/vtium/vtium/blob/v0.1.0-alpha.2/docs/why-vtium.md) says why you might choose it.

## What is new

- **Pictures.** A build with the `images` feature shows kitty graphics placed relative to other pictures and through Unicode placeholders, kitty animation, and iTerm2's inline images, animated GIFs included. Pictures come inline, from files and from shared memory. A sandboxed helper program, `vtium-image-helper`, decodes every picture. It runs as the session's user, or before login as an account that may read no file. The AUR packages build the minspec console by default, so build with `VTIUM_FEATURES=images` to get pictures.
- **`vtium config`.** The font tool is now called `vtium-config`, installed at `/usr/bin/vtium-config` in place of `vtium-vitrify`. Run with no command, it opens a TUI that tries each font on the live console as you move through the list. The TUI needs a terminal of at least 40 by 25 cells. When a session ends, the console's font goes back to the configured one.
- **Fixes.** Displays redraw correctly after the fixes in #216, and the tests no longer race their helpers on slow machines.

## Upgrading from 0.1.0-alpha.1

Upgrade the `vtium` package as usual. pacman removes `/usr/bin/vtium-vitrify` and installs `/usr/bin/vtium-config`. An upgrade never restarts a running vtium. Each VT runs the new build from its next start, for example after you log out of it, or after `sudo systemctl restart vtium@tty3.service` for VT 3. makepkg checks this tag's signature against the same key as before, `33F9B54FD2A4B6A4110749B3BA464FC9847A832A`.

Building from a checkout still needs Rust 1.88 or later. The gates now include `make msrv`, which builds with that version.

Please report what you find at https://github.com/vtium/vtium/issues.
