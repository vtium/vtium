# VTium 0.1.0-alpha.11

This is vtium's eleventh pre-release. vtium is a terminal for the Linux virtual console, written in Rust. It runs on a VT in place of getty, and it renders each frame itself, on the CPU or on the GPU. [Why VTium](../why-vtium.md) explains why you might choose it.

This release is about underlines that leave room for the letters, and about building a look in vtium-config. The Looks tab assembles a look from its font set, size, color scheme, effect and pointer theme. Your draft keeps every font set you make or remove until you install it.

## What is new

### Underlines

- **Underlines skip the ink of descenders.** An underline leaves a small gap wherever a letter's ink crosses it, such as the tail of g, y or p. The line stops one pixel short of the letter and goes on after it, in the underline's own color too. Every style skips ink: single, double, curly, dotted and dashed, and a hovered link's dashes. So does every size of text, on double-size lines and in kitty's sized runs too. The CPU and GPU paths draw the gaps alike. See [the underline issue](https://github.com/vtium/vtium/issues/429).

### Looks in vtium-config

A look is a `[look NAME]` section of vtium.conf. It sets the font set, size, color scheme, vtlook (effect file) and pointer theme of the heads that name it.

- **A card for each look.** In the Looks tab of `vtium config tui`, Enter on a look opens its card. The card has one line each for the look's name, font set, size, color scheme, vtlook and pointer theme. Each line lists its choices, and Left and Right step through them. The card also shows the look's fonts by role and the fonts this machine lacks. See [The Looks tab](../configure.md#the-looks-tab) and [the Looks tab issue](https://github.com/vtium/vtium/issues/379).
- **Only the sizes the fonts supply.** The size line offers the sizes that the look's text font supplies. A bitmap font such as Terminus offers only the sizes of its bitmap files, and an outline font offers vtium-config's usual sizes.
- **A preview of each size.** While the size list is open, a preview of the highlighted size draws below the list and follows the highlight. In a vtium console with `allow-window-ops` on, Enter also tries the size on the console for 10 seconds, and `k` keeps it. `w` asks whether to turn `allow-window-ops` on in the draft.
- **A new font set by role.** The form for a new font set has a row for each role, from the text font through box drawing, symbols and emoji to the fallback. One font can fill every role. A font set that only your draft adds shows in the Looks list, so a look can pick it before you install.
- **Pointer themes in the Looks tab.** The tab lists the installed pointer themes. Space activates or deactivates a theme, by its folder, through the draft.
- **The Flow tab picks a look.** A terminal's card in the Flow tab picks one of the draft's looks, and the Flow tab writes only the head's `look =` line. The font set and the size belong to the look.

### A pointer theme for each look

- **`pointer-theme` in a look.** A `[look NAME]` section accepts the `pointer-theme` key, so each look can draw its own mouse pointer. A look that names no theme takes the top-level `pointer-theme`, so an existing vtium.conf keeps its pointers. See [the pointer theme issue](https://github.com/vtium/vtium/issues/442).
- **check-config checks each look's theme.** `vtium check-config` checks the pointer theme of the top level and of each look. It reports a path that is neither an SVG file nor a cursor theme's folder. It also says when the theme is not active, because vtium then draws its own pictures. See [The pointer file](../reference/pointer-file.md).

### Drafts keep font set changes

- **Font set changes wait in the draft.** A draft keeps the font sets (frits) it adds or replaces, and the installed font sets it removes. They wait in a folder beside the draft, `~/.config/vtium/drafts/NAME.frits/`, so they survive when you leave vtium-config before an install. The TUI writes each change there at once. See [The draft](../configure.md#the-draft) and [the draft issue](https://github.com/vtium/vtium/issues/303).
- **diff, revert and flow show them.** `vtium config diff` prints each font set change under its file in `/etc/vtium/fonts`. `vtium config revert` throws the changes away with the rest of the draft. `vtium config flow` counts them in its first line, as in `draft desk: 2 font set changes`.
- **Install carries them.** `vtium config install` checks the draft with its font sets and installs them with vtium.conf. The check that runs as root reads its copies of the font sets from a private folder under `/run`. vtium-config writes the font sets first and removes the removed ones last, so vtium.conf never names a font set that is not there.
- **new-frit and remove-frit install nothing.** `vtium config new-frit` and `vtium config remove-frit` keep their change in your draft, as the TUI does. `vtium config install` then installs it. See [Choosing a font with vtium config](../fonts.md#choosing-a-font-with-vtium-config).

### Fonts

- **One broken font no longer takes down its font set.** When one font makes the font helper crash or hang, vtium starts the helper again without that font. The font set's other fonts go on drawing, with shaping. vtium leaves that font out until vtium restarts, even after you switch to another font set and back. A boot gives the helper three chances, and after that the built-in fonts draw the whole font set. See [the font helper crash issue](https://github.com/vtium/vtium/issues/461).
- **Damaged fonts are refused.** vtium-config checks each outline font's tables before its font library reads them. The refusal names what is damaged, as in `the font is damaged: its name table points past its own end`. A glyph larger than 4,096 pixels draws as empty. See [the damaged font issue](https://github.com/vtium/vtium/issues/428).
- **Color emoji, read with checks.** vtium-config reads the color bitmap images of fonts such as Noto Color Emoji itself. It checks every count and offset first, so a damaged table draws nothing rather than another glyph's image.
- **A strike's own hash.** In a font set's provenance lines, `sha256=` after `strike=` is the strike's hash. Each strike is a bitmap file of its own, so its line gives that file's SHA-256. See [Install a missing font](../fonts.md#install-a-missing-font).

### Colors

- **Ink, for three-color e-paper.** Ink, `ink`, is vtium's own color scheme for a display of three inks: black and red on white paper. Red, yellow and magenta print in red ink, and the other colors in black. So a program's colored text stays readable on white. See [The color schemes vtium installs](../palettes.md#the-color-schemes-vtium-installs) and [the Ink issue](https://github.com/vtium/vtium/issues/448).

### Typing and the smallest build

- **One frame for each key you type.** A key that changes nothing on screen draws no frame of its own. Only the program's echo draws one. Before, each echoed key cost two frames on the minspec build's test machine. See [the issue about two frames for each key](https://github.com/vtium/vtium/issues/444).
- **The minspec budget.** The minspec build's binary must stay within 4,390,912 bytes (4 MiB + 192 KiB), or tier 3 fails. This release's binary measures 4,364,600 bytes.

### Releases you can check

- **Files with checksums and attestations.** From this release on, each release on GitHub carries its source as `vtium-VERSION.tar.gz` and `vtium-VERSION.zip`, made with `git archive`. It also carries a list of every dependency with its license and checksum, and `SHA256SUMS`. Each file has a build provenance attestation, which `gh attestation verify` checks. See [From a checkout](../install.md#from-a-checkout) and [the release files issue](https://github.com/vtium/vtium/issues/348).

## Fixes

- **The keyboard works without the system's layouts.** On a system without xkb's layout data, vtium crashed with libxkbcommon older than 1.13. vtium now uses its built-in US keymap and logs a line that says why. The `xkb-*` settings then have no effect, and installing xkeyboard-config (`xkb-data` on Debian) adds the layouts.
- **Dotted underlines keep their rhythm.** A dotted underline keeps one period of dots along the whole line. Before, two dots could meet where one character cell ended and the next began.
- **Powerline separators reach their edges.** A Powerline separator stretches to its cell's edge only on a side its ink already touches. Where the font leaves space on a side, the space stays, so a thin divider keeps its place and width.
- **Font queries agree during a switch.** When a program switches the font set with OSC 50, vtium holds the replies to the program's queries until the new font's character cell is known. The font's name and the cell size reports then agree. A hidden console reports the font it last drew in until it is shown.

## Upgrading from 0.1.0-alpha.10

On Arch, upgrade as usual.

Four changes can alter what you see, or what a script does, after the upgrade:

- `vtium config new-frit` and `vtium config remove-frit` no longer take `--install`, and fail with exit status 2 when given it. As root, they no longer install at once. Run `vtium config install` after them.
- The font sets you make or remove in the TUI wait in the draft's folder. So quitting no longer asks whether to install them.
- A terminal's card in the Flow tab picks a look in place of a font set and a size. To change the font set or the size, edit the look in the Looks tab.
- Underlines show small gaps where descenders cross them.

An upgrade never restarts a running vtium. Each VT runs the new build from its next start, for example after `sudo systemctl restart vtium@tty3.service` for VT 3, run from another VT or over ssh. A logged-in shell on that VT survives the restart.
