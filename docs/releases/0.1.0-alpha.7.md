# VTium 0.1.0-alpha.7

This is vtium's seventh pre-release. vtium is a terminal for the Linux virtual console, written in Rust. It runs on a VT in place of getty, and it renders each frame itself, on the CPU or on the GPU. [Why VTium](../why-vtium.md) explains why you might choose it.

This release is about the VTs: a first install gives vtium the free VTs, vtium starts there at boot, and each head can live on VTs of its own.

## What is new

### The VTs vtium takes, and seat mode

- **A first install gives vtium the free VTs.** The package's install script runs `vtium console enable --direct --all`. That gives vtium every VT that no display manager, greeter, graphical session or kmscon holds. vtium then starts at boot on each of those VTs, ahead of the display manager, in place of its getty. On a machine with a display manager, VT 1 stays the display manager's. The install message says what vtium took, and names each VT it left alone and why. See [the install guide](../install.md#what-the-install-does-to-your-vts) for details.
- **Display managers stay off vtium's VTs.** Because vtium holds each VT it takes open from boot, a display manager such as SDDM puts a new desktop session on a VT above them. See [the issue about the display manager that took vtium's VT](https://github.com/vtium/vtium/issues/370).
- **The kernel's messages.** vtium draws over the kernel's own console, so it shows the kernel's warnings and errors itself, on the boot display. While Plymouth, the boot splash program, runs, vtium leaves the messages to it. The vtium.conf key `kernel-messages` changes that.
- **Turning vtium off for one boot.** `vtium.enable=0` on the kernel command line makes vtium exit before it touches the screen, and each VT's getty gives you a login prompt. vtium also steps aside for systemd's rescue and emergency modes, as a getty does.
- **Seat mode.** vtium can now run on a VT in two ways. In direct mode, which the install turns on, vtium opens the screen and the keyboards itself, and a login at its prompt gets an active session, as a login at a getty does. In seat mode, vtium takes the screen, the keyboards and VT switching from logind through libseat, and each login runs in a systemd scope of its own. `vtium console enable` with no mode changes nothing: it says which mode fits your machine and why, and gives the command to run. See [the libseat issue](https://github.com/vtium/vtium/issues/34) for what is still to come.
- **A VT a program holds stays its own.** `vtium console` leaves alone a VT whose program holds it, even when that program runs with no logind session, and its advice never offers a command that the machine would refuse.

### Heads on their own VTs

A head is a group of displays and keyboards that vtium.conf runs as one terminal.

- **Each head runs on VTs of its own.** A vtium builds only the terminals of the VT it runs on. Under the open policy, a display that no rule takes shows a notice and then turns off.
- **Enter switches to a head's VT.** With `switch-on-enter = yes`, Enter on one of a head's own keyboards switches to the head's VT, and the notice on its display says so. Under the open policy, every keyboard's VT keys switch VTs.
- **Displays that come late or stay dark.** A display on a graphics card whose driver loads after vtium starts now matches its rule. A display vtium cannot light stays known but dark, instead of being lost ([the dark display issue](https://github.com/vtium/vtium/issues/298)).
- **The VT on screen stays on screen.** Stopping or restarting vtium on the VT you are looking at leaves that VT on screen.
- `vtium check-config` notes a head whose VTs have no vtium enabled.

### Superscript and subscript

Text that a program marks as superscript or subscript (SGR 73 and 74) draws as a smaller glyph, raised or lowered, from the same font as the text around it. A bitmap font draws it at a smaller whole multiple of its size, or from a smaller size the font has. Its underline and strike follow the small glyph. vtium-config's font preview shows a line of superscript and subscript, with a caption that says how the font makes them. See [the superscript and subscript issue](https://github.com/vtium/vtium/issues/37).

### vtium-config

vtium-config is vtium's configuration tool.

- **The Flow view.** You lay out vtium.conf as paths, from the displays to the keyboards, and each terminal carries its VTs. Changes wait until you save them, and Install asks before it writes a file in which no path is complete. The Looks and Fonts previews show the console's pixels at their real size.
- **Install enables vtium where the file asks.** An install enables vtium on the VTs that a head names, and asks before it starts or restarts vtium there.
- **Trying a font live.** In a vtium console, the font preview shows the test screen's characters. `t` tries a font on the console, and `s` saves it.
- **A lean vtium.conf.** A vtium.conf that vtium-config writes holds a short header and only the keys that are set. Unsetting a key removes its line, and a look that no head uses any more leaves the file.
- Tab and Shift+Tab move between the top tabs on every screen, and the arrow keys move inside a screen ([the tabs issue](https://github.com/vtium/vtium/issues/355)).

### The rest

- **Left and right margins:** DECLRMM, DECSLRM, DECIC, DECDC, DECBI and DECFI ([the margins issue](https://github.com/vtium/vtium/issues/55)).
- **More text styles:** conceal, overline and rapid blink, which blinks faster than ordinary blink.
- **Links:** while you hold Ctrl over an OSC 8 link, its address shows in the overlay row ([the hyperlinks issue](https://github.com/vtium/vtium/issues/40)).
- **Resizing by grid:** `CSI 8 t` asks for a number of rows and columns, behind the `allow-window-ops` key ([the font change issue](https://github.com/vtium/vtium/issues/44)).
- **The keyboard layout follows the system's.** In a build with `logind`, a change made with `localectl` reaches vtium while it runs ([the layout issue](https://github.com/vtium/vtium/issues/80)).
- **The kitty keyboard protocol, first part:** a program can push, pop and query the protocol's flags, and flag 1 sends unambiguous escape codes. The rest of the protocol is still to come ([the kitty keyboard issue](https://github.com/vtium/vtium/issues/42)).
- **Fixes:** a graphics card the kernel removes is let go at once ([#295](https://github.com/vtium/vtium/issues/295)); with three buffers, text that scrolls during a page flip is no longer drawn twice ([#361](https://github.com/vtium/vtium/issues/361), [#366](https://github.com/vtium/vtium/issues/366)); bitmap italic keeps heavy console fonts whole ([#273](https://github.com/vtium/vtium/issues/273)); a double click on an empty cell selects nothing ([#364](https://github.com/vtium/vtium/issues/364)); a soft reset (DECSTR) keeps the tab stops and the margins ([#365](https://github.com/vtium/vtium/issues/365)); a font set loaded later replaces a missing glyph ([#320](https://github.com/vtium/vtium/issues/320)).
- **Each release carries its dependencies' source**, `vtium-0.1.0-alpha.7-vendor.tar.zst`, so a package build can run with no network.

## Upgrading from 0.1.0-alpha.6

On Arch, upgrade as usual. The `vtium` package now builds the `libseat` feature too, so it depends on `seatd`, which holds the library libseat. Installing `seatd` starts no seatd service.

An upgrade changes no VT. The VT claim runs only on a first install, so the VTs stay as you left them. If an earlier install gave vtium its VTs through the template link `autovt@.service` alone, vtium does not start at boot on VTs 2 to 5, and a display manager can put a desktop session there. The upgrade's message then names those VTs. To start vtium at boot on each VT it holds, run:

```
sudo vtium console enable --direct --all
```

`vtium console status` shows what each VT runs.

An upgrade never restarts a running vtium. Each VT runs the new build from its next start, for example after `sudo systemctl restart vtium@tty3.service` for VT 3, run from another VT or over ssh. A logged-in shell on that VT survives the restart.

Four key bindings have new names: `grab-paste` is `key-paste`, `grab-reboot` is `key-reboot`, `grab-power-off` is `key-power-off`, and `grab-suspend` is `key-suspend`. vtium still reads each old name and reports each line that uses it, so that you can rename it. `vtium config set` with the new name moves the line to it for you. The command `vtium config route` is gone; the Flow view does its job.

makepkg checks this tag's signature against the same key as before, `33F9B54FD2A4B6A4110749B3BA464FC9847A832A`.

Please report what you find at https://github.com/vtium/vtium/issues, with the output of `vtium-config report`. Reports from machines with a display manager, and from machines with more than one graphics card, are especially welcome.
