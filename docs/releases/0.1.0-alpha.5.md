# VTium 0.1.0-alpha.5

This is vtium's fifth pre-release. vtium is a terminal for the Linux virtual console, written in Rust: it runs on a VT, takes the display through KMS/DRM or fbdev, and draws the terminal itself, with no display server. [Why VTium](../why-vtium.md) says why you might choose it.

This release is about the GPU: vtium can now draw through it.

## What is new

- **The GPU path.** A console built with the `gpu` feature draws each head whose `hwaccel` switch is on through the GPU, with OpenGL ES 3.0 on the display's render node. A head is a terminal and the displays that show it. Every frame it draws is byte for byte the frame the CPU path draws: the GPU variant of vtium's VM tests passes all 36 of its screens against the CPU path's. When the GPU fails, vtium falls back to the CPU path. One GL error drops that frame to the CPU. Running out of GPU memory or losing the GL context moves the head to the CPU until vtium restarts. A display the GPU cannot set up at its size holds its head on the CPU while that size lasts.
- **A guard against flapping.** A display that keeps failing ends its head's GPU path after two failed frames in a row, or three in its last 60. A head goes back to the GPU path at most three times in a run. Both rules count frames, never time.
- **The AUR package builds the GPU path, pictures and logind,** with `hwaccel` off by default. To draw on the GPU, add a line holding the word `hwaccel` to `/etc/vtium/vtium.conf`. `hwaccel` is a switch, so it takes no value. A later release turns it on by default.
- **VT slots follow the common convention.** `vtium console enable` leaves VT 1 to an enabled display manager and never takes a VT another program holds. When vtium fails, its fallback starts no getty that would stop another program.
- **A hotplug can move a lit display.** When a new display is plugged in and every display controller (CRTC) is already driving a display, vtium can move a lit display to another controller so that the new display lights.
- **Bold and italic** draw through the glyph helper, from the bold and italic faces a frit (a font set file) names, or else from the regular face emboldened and slanted.
- **The first frame waits for its VT.** When another program takes vtium's VT before vtium has drawn its first frame, as X can at boot, vtium waits for the VT to come back instead of giving up.

## Upgrading from 0.1.0-alpha.4

Upgrade the `vtium` package as usual. It now depends on `libglvnd` and `mesa`, which hold the two libraries the GPU path loads, and on `bash`, for the `vtium-gallery` script. It also installs three frits in `/etc/vtium/fonts`. An upgrade never restarts a running vtium. Each VT runs the new build from its next start, for example after you log out of it, or after `sudo systemctl restart vtium@tty3.service` for VT 3. makepkg checks this tag's signature against the same key as before, `33F9B54FD2A4B6A4110749B3BA464FC9847A832A`.

Please report what you find at https://github.com/vtium/vtium/issues, with the output of `vtium-config report`. A report of the GPU path on your hardware, working or not, is especially welcome.
