# VTium 0.1.0-alpha.9

This is vtium's ninth pre-release. vtium is a terminal for the Linux virtual console, written in Rust. It runs on a VT in place of getty, and it renders each frame itself, on the CPU or on the GPU. [Why VTium](../why-vtium.md) explains why you might choose it.

This release is about text at more than one size and font sets that say which fonts they need. A login picture and your own pointer pictures let you make the console yours.

## What is new

### Lines and text at larger sizes

- **Double-width and double-height lines.** A program can make a line double width with `ESC # 6`, or double height with `ESC # 3` and `ESC # 4` on a pair of lines. `ESC # 5` returns a line to single size. Such a line holds half as many characters, and printing, the cursor and editing follow the rules that DEC's manuals give for it.
- **Every kind of glyph at double size.** vtium doubles each pixel of a bitmap font's glyphs. The font helper renders outline glyphs, color emoji and clusters at true double size. Box drawing, blocks, DEC graphics and Powerline symbols fill the doubled cell, so their lines still join.
- **Editing and selecting on double-size lines.** Insert mode, selection, the pointer and reverse wrap work on lines of every size. The cursor covers the whole doubled character. A double-size line still cuts off ink that reaches past its top or bottom edge, such as the ring of Å. See [the double-size lines issue](https://github.com/vtium/vtium/issues/61) and [the issue about ink at a line's edge](https://github.com/vtium/vtium/issues/417).
- **kitty's text sizing protocol.** A program can write a run of text at up to seven times its normal size with OSC 66, or at a fraction of that size. vtium renders the run at its scale and alignment, across a block of character cells. Its underline, strike-through and overline scale with the text.
- **A sized run is one unit.** An edit that would move, clear or overwrite part of a run erases the whole run. A selection over part of a run selects all of it, and the cursor covers the whole block. vtium renders a run by scaling up the font's glyphs at their normal size. See [the text sizing issue](https://github.com/vtium/vtium/issues/60), which tracks rendering runs at their true size.

### Fonts

A font set, or frit, is a short text file in `/etc/vtium/fonts` that lists the fonts vtium renders text with.

- **Programming ligatures.** With `font-ligatures = on`, vtium draws a programming font's ligatures, such as `->` and `!=`, across the character cells of their characters. Each character keeps its own cell, so programs count the same cells as before. A ligature splits into its characters while the cursor is on one of them. The setting is off by default. See [the programming ligatures issue](https://github.com/vtium/vtium/issues/23).
- **Layers that font sets share.** A layer is a file in `/etc/vtium/fonts/layers/` that holds fonts several font sets want, such as a symbol font or color emoji. A font set adds it with a `layer=` line, and `vtium-config new-frit --layer` writes that line for you. See [Layers that frits share](../fonts.md#layers-that-frits-share).
- **A bitmap font with an outline for larger cells.** A `strike=` line under an outline font names one of the font's bitmap files. vtium renders small cells from the bitmap files and larger cells from the outline. See [A bitmap font with an outline for larger cells](../fonts.md#a-bitmap-font-with-an-outline-for-larger-cells).
- **Outline fonts behind a bitmap font look like it.** When a font set starts with a bitmap font, vtium renders the outline fonts after it with sharp edges, fitted to the pixel grid. A `render=` line chooses otherwise for one font. See [the issue about outline fonts behind a bitmap font](https://github.com/vtium/vtium/issues/311).
- **Icons fit the main font's cell.** A symbol font that a font set adds for icons, such as a Nerd Font, now renders its icons scaled to the main font's character cell. See [the font merging issue](https://github.com/vtium/vtium/issues/64).
- **vtium names the fonts it lacks.** A font set can say which font each source needs, with `version=`, `check=`, `sha256=` and `url=` lines. `vtium config fonts` and `vtium check-config` name each missing font and the page where you can get it. vtium logs one line for each missing font, once a boot. [Install a missing font](../fonts.md#install-a-missing-font) says how to install one.
- **vtium's messages have a font of their own.** vtium renders its on-screen display, its notices and the panic screen in a small font built into vtium, cut from Terminus. They then look the same whatever font your session uses, and they show even when no font file can be read. See [The font of vtium's messages](../concepts/osd-and-notices.md#the-font-of-vtiums-messages).

### The cursor

- **The `blink` setting sets the starting cursor.** A session starts with a block that blinks while `blink` is on, and stays steady while it is off. A style that a program chooses with DECSCUSR blinks or stays steady as its number says, whatever `blink` says.
- **DECSCUSR follows the VT510.** `CSI 0 SP q` selects a blinking block, and `CSI 7 SP q` returns to the style vtium.conf sets. vtium's terminfo entry now sends `CSI 7 SP q` for `Se`. So when you quit vim, the cursor is the one the session started with.
- **Mode 12 and the cursor's replies.** Mode 12 turns the starting cursor's blink on and off. DECRQM for mode 12 and DECRQSS for DECSCUSR report the cursor the console shows. [Keep your own cursor style](../configure.md#keep-your-own-cursor-style) shows how to have your shell pick a style at each prompt.
- **The cursor's blink interval.** A program can set how fast the cursor blinks with the Linux console's `CSI 16 ; n ]`. See [the blink interval issue](https://github.com/vtium/vtium/issues/404).
- **A bar cursor keeps its letter.** A bar cursor now lies over the edge of its cell, and the letter in the cell stays in full view, on the CPU and the GPU paths.

### The pointer and links

- **Pointer shapes.** A program can set, push, pop and query the mouse pointer's shape with OSC 22. vtium knows ten shapes, such as the I-beam over text and the hand over a link. See [the pointer shapes issue](https://github.com/vtium/vtium/issues/59).
- **Your own pointer pictures.** `pointer-theme` names an SVG file that you drew, or the folder of a desktop cursor theme such as Adwaita. `pointer-size` sets a cursor theme's size. vtium installs its own pictures as `/usr/share/vtium/pointers.svg`, which you can copy and edit. See [The pointer file](../reference/pointer-file.md).
- **Copy a link without the mouse.** Ctrl+Shift+O puts a short label of letters on each link that a program marks with OSC 8. Type a label, and vtium copies that link's address into the selection. The `key-link-hints` setting changes the key. See [the keyboard link mode issue](https://github.com/vtium/vtium/issues/106).

### The login picture

- **A picture at the login prompt.** `login-image` names a PNG or JPEG picture that vtium shows at each login prompt. `login-image-fit` makes it a background beneath the text or a banner above or below the prompt. `login-image-position` places the picture, `login-image-scale` sizes a background, and `login-image-rows` sizes a banner.
- **The picture stays yours.** The login picture is an ordinary picture on the screen, so it scrolls away with the text, and a screen clear removes it. A program can cover or remove it, but it can never read it. [Remove the login picture when you log in](../configure.md#remove-the-login-picture-when-you-log-in) gives the line for your shell's startup file. See [the login picture issue](https://github.com/vtium/vtium/issues/63).

### Images and the kitty protocols

- **Smoother transparent edges.** vtium blends the partly transparent pixels of a picture in linear light, on the CPU and the GPU paths. Half-transparent areas no longer turn darker than they should. See [the blending issue](https://github.com/vtium/vtium/issues/334).
- **kitty graphics follow the specification.** An indexed-color image is recolored when a color it uses changes. vtium accepts `f=8` and `f=16` images from a file, a temporary file and shared memory, and compressed with `o=z`. An image with no id stacks as id 0, so it lies beneath the images with ids at the same depth.
- **kitty graphics replies.** No reply ends in a line feed. A placement named as its own parent gets the reply ECYCLE.
- **The keypad's Begin key.** Under the kitty keyboard protocol's flags 1 and 8, Begin sends `CSI E`, and `CSI 1 ; modifiers E` with a modifier. See [the issue that makes vtium follow the kitty specifications](https://github.com/vtium/vtium/issues/408).
- These changes settle each departure that the notes of 0.1.0-alpha.8 listed, apart from one. While a program sets no kitty keyboard flags, every key still sends the bytes that xterm's control sequences give. The kitty specification governs the keys once a program turns the protocol on.

### The clipboard tool

- **`vtium-clipboard copy`.** This new tool copies text from a file or a pipe to the console's selection through OSC 52, as `pbcopy` does on macOS. It is also installed as `vticlip`, so `git rev-parse HEAD | vticlip copy` copies a commit's id. Paste is not available yet. See [the vtium-clipboard issue](https://github.com/vtium/vtium/issues/113).

### vtium-config

- **A missing font no longer stops an install.** vtium renders a font set without a font that is missing. So when a draft's only problem is a missing font, vtium-config shows the warning and installs the draft.
- **The leave question keeps your changes.** When font sets that you made or removed wait for an install, `q` asks whether to install before you quit. Both answers first save the changes that are not saved. Ctrl-C saves them and quits without a question. See [the leave question issue](https://github.com/vtium/vtium/issues/411).

### Faster plain text

- **Plain ASCII text takes a shorter path.** vtium reads a run of plain ASCII text without stepping its parser and its character segmenter through each byte. In vtium's benchmarks, this change cuts the time to scroll text from 43.24 to 20.65 ms a MiB. Writing a file as `cat` does drops from 52.09 to 22.38 ms a MiB, and a full-screen program's frame from 0.526 to 0.292 ms.

### The rest

- **COLORTERM follows the display.** vtium sets `COLORTERM=truecolor` in a session only when every display of its head shows color or gray. On a black and white display, it leaves `COLORTERM` out. See [the COLORTERM issue](https://github.com/vtium/vtium/issues/371).
- **A page for each escape sequence.** The [escape sequences](../sequences/index.md) reference lists every sequence vtium knows, with a page that says what vtium does with it and whether vtium supports it. [Escape sequences](../concepts/escape-sequences.md) explains how sequences are put together, for a reader who has never met them. See [the sequence pages issue](https://github.com/vtium/vtium/issues/345).
- **New pages on the site.** The home page leads to eight pages that each describe one area of vtium, such as [Text in any script](../home/text.md). The [showcase](../showcase/README.md) sorts its screens by category. [Releases](index.md) keeps a page for each release. For contributors, [the crates' interfaces](../api/index.md) holds the rustdoc reference of each crate, under `/api/` on the site.

## Fixes

- **Text over a hidden picture.** A cell whose own background hides every picture beneath it now renders as a plain cell. Text on such a cell no longer shifts its color by one level. Selected text over a hidden picture takes the selection's colors, where it was washed-out grey. See [the issue about text over a picture](https://github.com/vtium/vtium/issues/418).

## Upgrading from 0.1.0-alpha.8

On Arch, upgrade as usual.

Four changes can alter what you see, or what a script reads, after the upgrade:

- `vtium check-config` now checks that the fonts your font sets need are installed. It exits 6 when its only warnings are about missing fonts, and 1 for any other error or warning. A script that accepts only 0 sees both as failures. Install the fonts it names, or accept 6 in the script.
- With `no-blink`, a program's blinking cursor style now blinks. `blink` sets only the cursor a session starts with. To keep a steady cursor of your own, have your shell send it at each prompt, as [Keep your own cursor style](../configure.md#keep-your-own-cursor-style) shows.
- On a black and white display, a session no longer gets `COLORTERM=truecolor`. A program then sees no promise of 24-bit color.
- Under kitty keyboard flags 1 and 8, the keypad's Begin key sends `CSI E` in place of `CSI 57427 u`.

An upgrade never restarts a running vtium. Each VT runs the new build from its next start, for example after `sudo systemctl restart vtium@tty3.service` for VT 3, run from another VT or over ssh. A logged-in shell on that VT survives the restart.

makepkg checks this tag's signature against the same key as before, `33F9B54FD2A4B6A4110749B3BA464FC9847A832A`.

Please report what you find at https://github.com/vtium/vtium/issues, with the output of `vtium-config report`. Reports from people who use double-size lines, sized text or programming ligatures on the console are especially welcome.
