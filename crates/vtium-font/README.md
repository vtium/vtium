# vtium-font

vtium's glyph sources: font files, vitrified sets and built-in sets in, glyph bitmaps out. It reads and writes vitrified sets (ADR-1200 D2), the glyph chunk format the helper's glyphs reach the console in; loads PC Screen Fonts (PSF1 and PSF2) and raw console fonts with the `psf` feature, and gzipped ones with the `gzip` feature, which brings `psf`: vtium-config enables `psf` and decodes gzip itself, and the console enables neither, so it parses no font file (ADR-1200 D6), while the crate's own tests take them through a dev-dependency on itself; deflates the chunks it writes with the `deflate` feature, which vtium-config enables and the console does not, so the console carries an inflate and no deflate (ADR-1200 D19); carries GNU Unifont and Unscii-8 built in as sets (the `unifont` and `unscii` features); and draws box drawing, block elements, Braille, sextants, octants and the rest of Symbols for Legacy Computing's block shapes as sprites that fill their cell. A `Font` puts a face and the sprites together, choosing between them for each sprite range by its `SpritePolicy`, and draws any cluster exactly into its cells. It forbids unsafe code. Every glyph is a `Glyph`, a coverage mask or premultiplied RGBA, and its bytes are the same on every host. The console draws no outline font through this crate's faces: vtium-config rasterizes outline and color fonts into vitrified sets, which this crate reads (ADR-1200).

## Behaviour

vtium draws the same pixels for the same font, size, style and character on every host. `tests/digests.rs` holds it to vtium's digests of every sprite at 800 cell sizes, the box-drawing lines at 858 more sizes and thicknesses, every glyph of four PSF fixtures at three scales, every unifont glyph at two, and every character of plane 0 drawn through `Font::glyph`. `tests/sprite.rs` holds the sprites to a box model written apart from `src/sprite.rs`, at every cell size from 1x1 to 32x64.

A sprite's curves and diagonals are supersampled with IEEE 754 `f64` addition, subtraction, multiplication, division and comparison only, which every host rounds the same way and Rust never fuses into one operation, so a sprite is the same bytes on every host. The digests were taken on x86-64 and are checked on whatever host runs the tests.

### PSF fonts

The loader follows kbd's description of the format in Andries Brouwer's "The PSF font format", and settles these readings of it, each with its test in `tests/psf.rs`:

- **A unicode table sequence does not end the glyph's entry.** In PSF1 0xFFFE, and in PSF2 0xFE, starts a sequence; the entry runs to its terminator, 0xFFFF or 0xFF. vtium maps the entry's single codepoints and skips its sequences, as the Linux console loads a table, so a sequence never moves a later glyph's codepoints. Spec: "The PSF font format", `<unicodedescription> := <uc>*<seq>*<term>`, `<seq> := <ss><uc><uc>*`.
- **A PSF2 table is decoded as well-formed UTF-8.** A byte that is not part of a well-formed character maps nothing, and 0xFE and 0xFF always act as marks, so a stray continuation byte, an overlong encoding or a terminator after a lead byte never moves a later glyph's codepoints. Spec: RFC 3629 and the Unicode Standard §3.9 (D92, Table 3-7), whose well-formed UTF-8 never holds 0xFE or 0xFF.
- **A codepoint the table lists for several glyphs maps to the last**, as the Linux console maps it: the console overwrites as it loads a table (`con_insert_unipair` in drivers/tty/vt/consolemap.c).
- **Table entries past the font's last glyph are ignored**, however many there are. Spec: "The PSF font format", the table holds one description per glyph.
- **The fallback `?` is looked up as a character.** A character the font lacks draws U+25A1, else `?`, else glyph 0, and `?` is found through the font's table; in a font without a table, glyph 63 is `?`.
- **A raw (headerless) console font is read.** A file with neither PSF magic nor gzip's, of 256 times a height of 1 to `RAW_HEIGHT_MAX` bytes, is 256 glyphs of one byte a row and 8 pixels across, with no unicode table, as `setfont` and the kernel take it. A raw font is recognised by size alone, as `setfont` recognises it after the magic check, so a 256*N file of 8 KiB or less that is not a font, such as kbd's 256-byte `README.Arabic`, loads as one. Any other size is refused as `PsfError::NotPsf`. Spec: setfont(8), "Raw font files are binary files of size 256*N bytes ... (0 < N <= 32)".
- **A gzip file with bytes after its last member is refused.** Spec: RFC 1952 §2.2, "A gzip file consists of a series of members".

### Sprites

- **Box drawing, block elements, Braille, the sextants, the octants and the rest of Symbols for Legacy Computing's block shapes are sprites** (vtium/vtium#27), drawn to fill the cell at every cell size. The Legacy Computing shapes follow the Unicode 18.0 code charts:
  - U+1CEA0-U+1CEAF, the one quarter blocks: the Symbols for Legacy Computing Supplement chart, <https://www.unicode.org/charts/PDF/U1CC00.pdf>;
  - U+1FB3C-U+1FBAF, U+1FBBD-U+1FBBF and U+1FBCE-U+1FBEF, the smooth mosaics, triangles, eighth, third and quarter blocks (U+1FB82-U+1FB85 and U+1FBE4-U+1FBE7 among them), shades, fills, light diagonals and circles: the Symbols for Legacy Computing chart, <https://www.unicode.org/charts/PDF/U1FB00.pdf>.

  The block's pictographs stay with the face: the pointer, check mark, running man, arrows, folders and squared dot (U+1FBB0-U+1FBBC), the saltire, pointing index, question mark, stick figures, chevrons, cross mark and bracket (U+1FBC0-U+1FBCD), and the segmented digits and alarm bell (U+1FBF0-U+1FBFA). No cell-grid geometry defines them, so they draw from the face, and unifont carries them. `tests/legacy.rs` holds every Legacy Computing sprite to a model built from its Unicode name, at every cell size from 1x1 to 32x64 and in larger cells, and to literal masks; the page digests of `tests/digests.rs` leave these characters out. A tier 2 screen of the ranges waits for the tier 2 goldens (vtium/vtium#17).
- **Each sprite range can be drawn from the font instead** (vtium/vtium#85). A `SpritePolicy` gives each `Range` (box drawing, block elements, Braille, sextants, octants and Legacy Computing) a `Source`:
  - `Sprites`: the sprite, whatever the face holds.
  - `Font`: the face's glyph, and the font's `Missing` glyph for a character the face lacks.
  - `Auto`: the face's glyph, and the sprite for a character the face lacks.

  `Font::coverage` counts the characters of each range the face holds, 874 in all, through `Face::coverage`, which asks `Face::has_glyph` of each; a face that reads a character map can override it. `Coverage::partial` names the ranges a face covers only partly, for the operator's warning. `Font::new` takes the face's own `Face::sprite_policy`, and `Font::with_policy` sets another. `tests/policy.rs` holds each source to stand-in faces that cover a range fully, partly and not at all.
- **A font the operator names draws its own glyphs for each sprite range it covers whole.** `SpritePolicy::default_for` gives a range `Font` when the face holds every character of it and `Sprites` when it misses any, so no range mixes the two; a partly covered range draws sprites and warns. The built-in unifont keeps `Sprites` for every range, though it covers all six, because the sprites line up exactly at every cell size and the goldens show them. Source: the operator's decision on vtium/vtium#85.
- **A sprite's light line follows the cell, not the font's underline.** `sprite::light_line` gives a cell `h` rows tall a light line `h / 16` pixels wide, at least 1 and at most a quarter of the cell, the thickness a face with no line metrics gives its underline; heavy lines are twice it, and double lines are two light strokes a light stroke apart. So a 20x38 cell draws 2-pixel light lines and 4-pixel heavy ones in every font, where DejaVu Sans Mono's own underline, which an outline font states in its `post` table, is 1 pixel at a 38-row cell. The font's measured underline still sets where vtium draws an underline and how thick. Source: the maintainer's decision on vtium/vtium#310, that line weight grows with the cell.
- **A cluster on a sprite character the face lacks draws the sprite.** When the policy draws a cluster's first character as a sprite and the face lacks that character, the cluster draws the character's sprite and drops its marks, so a PSF font without box drawing draws U+2500 + U+0301 as the line and not as U+25A1. A face that holds the character draws the cluster. Source: the operator's decision on vtium/vtium#85, which draws the sprites for a range the font lacks.

### A character the face lacks

A character the face lacks draws as the font's `Missing` glyph (vtium/vtium#85). `Missing::Replacement`, the configuration's `missing = box` and the default, draws U+25A1, `?` or the face's last resort. `Missing::Hex`, `missing = hex`, draws the codepoint in hex digits, in the layout and digit shapes the operator approved on vtium/vtium#85. Every pair of digits differs by at least two pixels, so a program can read the codepoint back:

- a narrow cell is the text color with the digits cut out, two rows of two 3x5 digits up to U+FFFF and three rows of two 3x4 digits past it, b, c and d in lower case;
- a wide cell is a box outline with 3x5 digits inside, two rows of two or of three.

The design is 8x16 narrow and 16x16 wide, scaled by the largest whole factor the cell holds and centred, a narrow cell's margin in the text color; a cell smaller than the design draws U+25A1. `Font::glyph_unscaled` hands it over at its drawn size, as a sprite. `tests/missing.rs` holds it to literal masks.

## Vitrified sets

A vitrified set (ADR-1200 D2) is one buffer, little-endian throughout, written to no file: the `VTGLASS\0` magic, a major and minor version, a section table, then `META` (the provenance as `key=value` lines), `STRK` (each strike's style, pixel format, cell, baseline, underline and strike lines, glyph count; sorted by cell, style and pixel format, so a cell holds a 1-bit, an R8 and an RGBA strike of each style), `CMAP` (each strike's runs of codepoints, a cell's strikes of one style mapping codepoints apart), `POLY` (the sprite policy and each strike's coverage of each sprite range) and `GLYF` (an index of chunks, each with its offset, stored and decoded lengths and raw-or-deflated flag, then the chunks), `CLUS` when the set maps a cluster, and `INKX` when a glyph's ink passes its cells. `src/set/format.rs` lays out every field. Format 2.0 is what this build writes and reads, the helper and the console changing together, so it carries no hash; a set of another major version is refused with `SetError::UnknownMajor`, and a later minor version's sections and record fields are skipped.

- **Writing.** `SetBuilder` takes a name, provenance lines, a sprite policy and `StrikeBuilder`s, each a style at one cell size in one pixel format (1-bit, R8 or premultiplied RGBA), its glyphs and the codepoints that draw them. The bytes depend only on these: strikes and runs are sorted, glyphs are numbered in the order the sorted map first reaches them, a glyph no codepoint maps is dropped, and chunks are deflated at one fixed level, so the same inputs give the same bytes on every host built with the same features, the console's writer storing raw a `compress=yes` strike that vtium-config's deflates (`tests/set.rs` pins a set's SHA-256). Chunks hold at most `SET_CHUNK_BYTES` and never split a glyph; a strike's glyphs start a new chunk. A glyph larger than `SET_CHUNK_BYTES`, as each glyph of an 8x16 bitmap font drawn 33 times its size is at 17,424 bytes, goes in a chunk of its own, exactly its bytes and never deflated, in `GLYF` and in `CLUS` alike (ADR-1302 D6). A set with no such glyph is written byte for byte as before, which a test pins by the SHA-256 of the built-in sets and of sets it writes. By default a strike's chunks are deflated for R8 and RGBA and stored raw for 1-bit, as a frit's `compress=yes` asks (ADR-1200 D13), and `StrikeBuilder::compress(false)` stores them raw. `build.rs` deflates the built-in sets in every build.
- **Reading.** `Set::from_bytes` checks a whole set in memory, as the console checks each of the helper's frames, and `Set::check_chunks` decodes every chunk without keeping it. Every count and size is bounded, and every table is checked against the others before a glyph is drawn: runs sorted and apart, glyph counts, `POLY`'s coverage against `CMAP`, and the chunks against each strike's glyph bytes. A chunk of `GLYF` or `CLUS` larger than `SET_CHUNK_BYTES` is taken only when it is raw and holds exactly one glyph, of exactly that glyph's bytes, so its decoded bytes are bytes the set holds and its size is bounded by the strike's cell; any other chunk past the bound refuses the set, and an `INKX` chunk is held to `SET_CHUNK_BYTES` always. The map, a run and the glyph span it may bring in, takes 36 bytes a run, at most 9 MiB at `SET_RUNS_MAX`, and `CMAP`'s bytes at most 16,777,352 while they are checked. A chunk is inflated to exactly its decoded length the first time a glyph is drawn from it, then kept as stored. A 1-bit glyph is expanded to a mask of 0 and 255 as it is drawn (ADR-1200 D13), as `Psf` expands its glyphs, so a 1-bit chunk costs its own 16 KiB at most, or the bytes of the one glyph larger than that which it holds. A chunk that fails draws its glyphs as missing ones, and `Set::fault` names it.
- **Clusters.** `CLUS` maps clusters, short sequences of scalar values such as an emoji ZWJ sequence, a flag or a letter with its marks, to glyphs drawn for them whole (vtium/vtium#144). Each cluster belongs to a strike, whose cell and pixel format its glyph takes, one or two cells wide; its key is 1 to `CLUSTER_SCALARS_MAX` scalar values, and a strike's clusters are sorted by key with none twice. The section holds its records, the keys end to end, a chunk table as `GLYF`'s and its own chunks, so a reader that does not know the tag skips it whole and the format stays 2.0: `tests/clusters.rs` reads one with the section renamed to a tag the reader does not know. `StrikeBuilder::cluster` maps a cluster to a glyph of the strike's, which may also draw codepoints; a set with no cluster is written without `CLUS`, byte for byte as before. The reader checks every record against its strike and its chunk before a glyph is drawn, and holds 20 bytes a cluster and its key, at most 5.25 MiB at `SET_CLUSTERS_MAX`. `SetFace::cluster` looks a cluster up by its exact scalar values, by binary search in each strike's clusters, choosing a strike as a codepoint's is chosen; a cluster it does not map is `None`, and the console's lookup chain decides what draws then. `Set::clusters` lists the clusters each strike maps, which the console checks against what it asked for.
- **Ink boxes.** `INKX` holds the ink box of each glyph whose ink passes its cells (ADR-1200 D2, ADR-1302 D6), as italic and symbol glyphs' ink does. A box is the columns from its left, the offset of its first column from the left edge of the glyph's first cell, which is 0 or negative, its width across, over the cell's full height, in the strike's pixel format. It spans the glyph's cells and the ink past them, and reaches at most one cell past them on each side, the glyph's reach (ADR-1302 D1). Each record names a strike and either a glyph of `GLYF` by its number or a cluster of `CLUS` by its record's number, so a glyph that draws codepoints and clusters has a record for each, and the box's bytes are stored once in the section's own chunks. A glyph keeps its pixels cut to its cells in `GLYF` or `CLUS` as before, so a reader that does not know `INKX` skips it and draws every glyph cut to its cells, and the format stays 2.0; a set with no box is written without `INKX`, byte for byte as before. Only R8 and 1-bit strikes hold boxes, since a color glyph fits its cells (ADR-1302 D5). `StrikeBuilder::ink` gives a glyph its box; the writer refuses a box in a color strike, one past the reach, one that does not pass the glyph's cells and one larger than `SET_CHUNK_BYTES`, and the reader refuses each of these before a glyph is drawn, so the console's reader of the helper's answers holds every box to its reach (ADR-1200 D15). A glyph whose box would pass a chunk carries none, and is drawn cut to its cells. `SetFace` draws a glyph's box beside its pixels, at the same whole factor, bold widened inside the box, as `Glyph::ink`; a `Glyph` boxed to another width by `Font` loses its box, which was placed for its own cells. The reader holds 24 bytes a box, at most 6 MiB at `SET_INKS_MAX`.
- **Drawing.** `SetFace` draws one cell size of a set: the tallest strike whose whole multiple is the height asked for, else the tallest under it scaled by the largest whole factor that fits, else the smallest at its own size (ADR-1200 D9). A style draws from its own strikes, whichever of them maps the codepoint, in its own pixel format: a 1-bit glyph expanded to an 8-bit mask, an R8 glyph as its mask, an RGBA glyph as premultiplied color, one or two cells wide. A codepoint it lacks, or a style with no strike, draws from the regular strikes, a mask widened for bold as vtium-font's bitmap faces widen it, a pixel set when it or its left neighbour in the same cell is, and a 1-bit glyph sheared for italic as vtium-font's bitmap faces shear it; a color glyph is drawn as it is.

The built-in sets (ADR-1200 D7) are `unifont`, an 8x16 strike compiled in with the `unifont` feature, and `unscii-8`, an 8x8 strike compiled in with the `unscii` feature, 15,486 B as a set. `set::builtin` gives either by name, and `set::builtin_name` the one D7 draws: `unscii-8` for cells under 16 pixels high and `unifont` from 16, and `unifont` in a zh, ja or ko locale, since Unscii-8 holds no CJK. Both draw the sprites for every sprite range.

Choices the format leaves to this crate, each settled here:

- A deflated chunk is stored deflated only when that makes it smaller; otherwise raw, with its flag clear.
- A multi-line `META` value, such as the frit, is one line of its key for each of its lines; `name` and `format` are written first by the builder.
- `POLY` holds each strike's coverage, and the reader refuses a `POLY` whose coverage is not its strike's map's.
- A strike drawn at a whole factor keeps the lines the bitmap faces draw: a strike whose decorations are `Decorations::for_height` of its height, as every bitmap source gives, takes `for_height` of the scaled height. A strike with lines of its own scales them with its glyphs.
- A set face's last resort, drawn when the set holds neither U+25A1 nor `?`, is glyph 0 of the first regular strike at its cell that holds a glyph: the glyph of the lowest codepoint that strike maps. A cell's coverage of each sprite range is its regular strikes' counts summed.

## Glyph storage

**What a draw returns.** Every draw allocates a new `Glyph`: its width, height, the cells it spans (1 or 2) and its pixels row by row, in one of two formats.

| Format | Bytes a pixel | Holds | A narrow 8x16 cell | Two cells at `CELL_SIDE_MAX` (4096x2048) |
|---|---|---|---|---|
| `Format::Mask` | 1 | Coverage, 0 to 255; the renderer blends it in the cell's colors | 128 B | 8 MiB |
| `Format::Rgba` | 4 | Red, green, blue and alpha, the colors premultiplied by alpha | 512 B | 32 MiB |

PSF, unifont and the sprites draw only masks. RGBA is for color faces (vtium/vtium#23, #24).

**What each source keeps.**

| Source | Kept in memory | Cost at minspec |
|---|---|---|
| `Psf` | The glyphs' 1-bit rows as one slice, count x height x ceil(width / 8) bytes, and, when the font has a unicode table, a codepoint table sorted for binary search, 8 bytes an entry. The file's other bytes are dropped after parsing. | kbd's `default8x16`: 4 KiB of glyphs and 282 entries (2.2 KiB). Terminus 16x32: 32 KiB and 627 entries (5 KiB). The largest font the bounds admit keeps up to 16 MiB of glyphs and 8.5 MiB of table, and parsing it holds the file's bytes as well, up to 16 MiB more. The console parses no font file (ADR-1200 D6), so this cost falls on vtium-config's helper. |
| `Unifont` | Compiled into the binary, read-only: the built-in set, 1,344,063 B: the 3.7 MB of 1-bit glyphs deflated in 227 chunks of at most 16 KiB (1.28 MB), its map of 3465 runs at 16 bytes each (54 KiB) and its chunk index (4.4 KiB). In memory: the set's runs, glyph spans and chunk index, read once (about 145 KiB), and each chunk a glyph has been drawn from, inflated once on its first draw and kept 1-bit for the life of the process, shared by every `Unifont`. A chunk is never dropped and never inflated twice. | ASCII and Latin-1 are chunk 0 and U+25A1, drawn for a missing character, is chunk 14, so plain text holds 32,752 B. Text with Latin Extended, Greek and Cyrillic adds chunk 1, and punctuation, arrows and maths chunks 12 and 13. The CJK ideographs U+4E00-U+9FFF span 42 chunks (688,128 B). All 227 hold 3,718,608 B (3.55 MiB), inside the minspec build's memory peak of 16 MiB. |
| `SetFace` | The set's runs, glyph spans and chunk index, and each chunk drawn from, decoded and kept as stored, at most `SET_CHUNK_BYTES` each, or one glyph's bytes for a glyph larger than that. | |
| Sprites | Nothing: each is computed at the size asked for. | |

Scale does not change what a source keeps, only what a draw returns: a font scaled to a cell of 2048 still keeps its 1-bit rows, and each draw returns a glyph of up to 8 MiB as a mask.

**The drawn-glyph cache is vtium-render's** (vtium/vtium#16) and is not decided here. A draw costs an allocation, a bit-to-byte expansion for a 1-bit glyph, and for a set an inflate only the first time a chunk is used, so the cache saves the allocation and never repeats an inflate.

## Line spacing

`spacing` holds what the console and the glyph helper share for added line spacing (ADR-1302 D13). `Band::of` gives the rows a percentage of the text's height adds, rounded to the nearest pixel with a half rounding up, split evenly with the odd pixel above, and cut so the cell stays inside `CELL_SIDE_MAX`. `Fit::default_for` gives a character's fit when its frit's set names none: box drawing, block elements, Braille, Powerline (U+E0A0 to U+E0D7) and the two Legacy Computing blocks are `fill`; Hebrew, Arabic, Syriac, Thaana, N'Ko and any combining mark are `room`; the rest is `natural`. `place` puts a glyph drawn at the text band's height into the taller cell: a `fill` mask stretches, a bitmap's by repeating its top and bottom rows and an outline's by scaling vertically, and everything else, every color glyph included, gets blank rows above and below. A face reports the rows its cell adds through `Face::band`, none by default.

## Notes for vtium-render

- Ask `Font::glyph` for every cell's glyph: it draws the sprites, the face and the fallbacks, and boxes the result to exactly the cells asked for, marked with that cell count. Check its `format()`: a mask is blended in the cell's colors, RGBA is composited as it is. It returns `None` only for an empty cluster or a face that can draw nothing at all.
- A sprite's light line is `sprite::light_line` of the cell's height, a sixteenth of it, so box lines grow with the cell whatever the font (Sprites, above).
- Bold and italic are drawn into the glyph. A bitmap face widens bold by a pixel and shears italic by 0.2 about the font's baseline, one pixel row at a time, at the font's own size before it is scaled (`italic`, ADR-1302 D4). A sheared glyph's pixels are its ink cut to its cells, and the ink that passes them goes to its ink box (`Glyph::ink`, ADR-1302 D6), which a renderer that draws no box leaves out. For bold italic the widening comes first and the shear moves the widened rows; a set with no bold-italic strike draws bold italic from its regular strike, widened and sheared, never from its bold strike (the maintainer, 2026-11-04). A sheared glyph whose box's 1-bit rows would pass a set's chunk, 16 KiB, carries no box and is cut to its cells, as the glyph helper leaves such a box out of a set. A PSF font states no baseline, so `Psf::baseline` takes the row under the lowest ink of its `H`, or the glyph's bottom edge for a font with no `H`; a set's 1-bit strike is sheared about the baseline the strike states, row 14 for the built-in unifont and row 7 for Unscii-8. An R8 or RGBA strike drawn for italic stays upright: an outline's slant is the glyph helper's, drawn before it is rasterised, and color glyphs never lean. Overhang is vtium/vtium#26.
- A glyph's bytes depend only on the font, the size, the style and the character, so a cache may key on those. A `Font`'s policy is fixed when it is built, so a new policy is a new `Font`.
- The configuration (vtium/vtium#21) builds a font's policy from its keys: the one value for all six ranges as `SpritePolicy::all`, else the face's default, then each range's own key with `SpritePolicy::with`. It warns for each range `Font::coverage().partial()` names.
- `Font::glyph_unscaled` hands a bitmap face's glyph over at scale 1 with its scale, for a cache that stores it small and scales it while drawing (ADR-1300 D2). Drawn with each pixel a square `scale` across, it is `Font::glyph`'s glyph exactly. A sprite comes at its drawn size, as does a glyph whose box to its cells centres it in an odd number of spare pixels, which does not scale.

## Bounds

A font file and a set are untrusted input: their sizes are bounded, and a malformed one is refused with a `PsfError` or a `SetError`, never a panic. Each refusal case has its own test in `tests/psf.rs` and `tests/set.rs`, and the fuzz targets feed the loader and the set reader any bytes.
