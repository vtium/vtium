# vtium-vitrify

The program that generates vtium's glyphs at run time (ADR-1200, ADR-1301 D2), its own binary outside the minspec build. Its `serve` command is the helper the console starts: it takes a frit's text from the console, finds and reads the frit's sources, parses each bitmap font and rasterises each outline font, and sends the glyphs at the cell asked for in the glyph chunk format, written with vtium-font's writer. Its `set` command switches the running console's frit. Every decoder lives here; the console reads only the helper's glyphs and its own built-in fonts. The crate forbids unsafe code; the console font ioctls it needs live in vtium-platform's `src/vt/font.rs`.

## Commands

| Command | Runs as | Does |
|---|---|---|
| `set NAME` | the session's user | Switches the running console to a frit or a built-in font (ADR-1200 D5). NAME is checked first as the console checks it, `unifont`, `unscii-8`, or a frit's name whose `NAME.vtfrit` is a regular file in the frits' directory, and the command fails naming that file when it is neither. It then writes `OSC 50 ; NAME ST` and the query `OSC 50 ; ? ST` to `/dev/tty`, reads the reply in raw mode for at most a second, and puts the terminal's mode back, dropping input left unread first; SIGTERM, SIGHUP, SIGINT and SIGQUIT are held while the terminal is raw and act once its mode is back. It prints `set NAME` when the reply names NAME, else `failed`, the name, and the font the console kept or that no reply came, which the console's `allow-font-ops` off or a terminal that is not vtium gives. |
| `serve` | the account ADR-1200 D15 names | The helper ([The helper](#the-helper)). The console starts it; it takes no argument. |

`set` prints one line, tab-separated, and exits 0 on success, 1 on a failure and 2 on a usage error. The store's commands, `create`, `install`, `list`, `verify` and `remove`, are gone with the store (ADR-1200 D3, D12, retired), and each is an unknown command.

The frits are in `/etc/vtium/fonts`, changed at build time with `VTIUM_FONT_FRITS`, as the console's are. `--frits DIR` names another for `set`, and `--kbd-dir DIR` (repeatable), `--font-dir DIR` (repeatable), `--vconsole-conf FILE` and `--kernel-cmdline FILE` replace the paths `serve` finds sources in.

When stdin and stdout are both terminals, the tool opens with a banner of its name in glass (`src/banner.rs`, vtium/vtium#112). `--no-banner` or a non-empty `NO_COLOR` turns it off, and it never precedes `--version`, never shows in a Chinese, Japanese or Korean locale, and never reaches a pipe.

## Frits

One `key=value` a line, blanks around key and value dropped, `#` to the line's end a comment, as kmscon.conf reads; unlike kmscon.conf, an unknown key, a malformed line, a value with a control character or a key this build does not build yet refuses the whole frit, naming the file and line. This slice reads ADR-1200 D1's keys and ADR-1301 D4's `antialias=`: `name=`, `source=` (`font:`, `kbd:`, `file:`, `bdf:`, `outline:`, `vconsole`, `console:VT`, `builtin:`), `unimap=`, `cover=` (`ascii`, `latin-1`, `gb2312`, `gbk`, `big5`, `jis-x-0208`, `ks-x-1001`, `U+XXXX` and `U+XXXX-U+YYYY`), `cp-size=`, `style=regular`, `cell=`, `size=`, `glyph-source=` and `glyph-source-<range>=`, `antialias=` and `license=`. The store's `package=` and `sha256=` are unknown keys. `compress=`, which chose how a stored set was compressed, is accepted with one warning naming the file and line, since refusing it would leave the console on the built-in font for a key that never changed what was drawn.

`cell=WIDTHxHEIGHT`, each side 6 to 96 pixels, states the cell the console draws the frit in and the helper generates for (#145); the console reads it as text before its first frame. `size=`, once, 6 to 96, is an outline frit's starting size in points, from which a zoom steps; the console reads it, converting it at the display's density (`crates/vtium/README.md`), and the helper draws at the cell each request names. `glyph-source=` and `glyph-source-box=`, `-block=`, `-braille=`, `-sextants=`, `-octants=` and `-legacy=` take `font`, `sprites` or `auto`, the configuration's names and values, each once; the console reads them as the frit's sprite policy, its configuration's keys over them. `antialias=` is `auto` or `no`; the engine reads it once ADR-1301 D6's grid is built.

A source's `cover=` lines are one union, sorted and merged. `ascii` is U+0020 to U+007E and `latin-1` adds U+00A0 to U+00FF. Each named set is its standard's own repertoire, the codepoints its Unicode mapping file maps to, with no vendor's extension: `gb2312` from `OBSOLETE/EASTASIA/GB/GB2312.TXT` (7,445 codepoints), `gbk` from `VENDORS/MICSFT/WINDOWS/CP936.TXT` (21,920), `big5` from `OBSOLETE/EASTASIA/OTHER/BIG5.TXT` (13,704), `jis-x-0208` from `OBSOLETE/EASTASIA/JIS/JIS0208.TXT` (6,879) and `ks-x-1001` from `OBSOLETE/EASTASIA/KSC/KSX1001.TXT` (8,224), under unicode.org's `Public/MAPPINGS/`. unicode.org no longer serves `GB2312.TXT`, so it is taken from the Wayback Machine's latest capture of its original URL, of 2004-06-18, pinned by its SHA-256 as the others are. `KSC5601.TXT` beside `KSX1001.TXT` is Unified Hangul, Microsoft's extension, and is not used. `tools/cover-tables` fetches each file once with curl into `$XDG_CACHE_HOME/vtium/cover-tables` and writes `src/cover.rs` and `tools/cover-tables/provenance.tsv`, which pins each file by its URL, its own table version and date, its SHA-256 and its count of codepoints: `cargo run -p vtium-cover-tables -- generate` writes them, refusing a file whose SHA-256 moved unless given `--repin`, and `-- check` fails when the checked-in files differ from what the cached files generate. Nothing fetches at build or run time; the helper reads only the checked-in tables, and a test pins each set's count.

A frit is meant to travel, so a source names a font each machine finds for itself. The `font:` form below is provisional: its syntax is the operator's to choose, and may be renamed before the first release (vtium/vtium#121).

```ini
source=font:Terminus 16      # a family, matched on the machine that draws it
style=regular
```

`font:FAMILY` matches as fontconfig matches a family, with case and blanks ignored. kbd console fonts match it first, by name: the font `setfont` would find by that name, else the first, in each data directory's sorted `consolefonts/`, whose name less its suffixes is the family. A PSF file outside kbd's directories carries no family in its header, so only `file:` names it. With no kbd font of that name, an installed outline font matches: a `.ttf`, `.otf`, `.ttc` or `.otc` file whose name less its extension is the family, or the family and `Regular`, with case, blanks, `-` and `_` ignored, so `font:JetBrains Mono` finds `JetBrainsMono-Regular.ttf`; the plain name first, then the font directories in order (`/usr/share/fonts` and `/usr/local/share/fonts`, or each `--font-dir`), then by path. The engine checks that the file's name table gives that family, typographic or legacy, and in a collection takes the first face of it. `outline:PATH` names an outline file by its absolute path, and `bdf:PATH` a BDF font.

A source missing on this machine, or that cannot be read, is left out, and the next source in the frit's order gives its glyphs. With every source left out, the frit fails, naming each source and why.

Each later source fills only the codepoints the earlier ones lack. A bitmap font is scaled by the largest whole factor at which its cell fits the cell asked for, centred across and placed on the cell's bottom row; one whose cell does not fit at factor 1 fills nothing. The cell holds a strike a pixel format: bitmap fonts give 1-bit glyphs, outline fonts R8 coverage and color glyphs premultiplied RGBA, each stored raw; the strikes' codepoints are apart.

## Outline fonts

The engine rasterises each outline font with swash at the cell asked for, and places each glyph in its cell as the C reference's FreeType backend did (`kmscon/src/font/font_freetype.c:130-189,400-470` at `b1f7a7c5`): the font is sized so its ascent and descent span the cell's height less half a pixel, as a FreeType cell request for that height did; the baseline sits the ascent, rounded up, below the top; and the font that sets the cell sets its width from `W`'s advance or its ink, whichever is wider, then `M`'s or `0`'s. A glyph sits on the baseline at its own bearing, moved left by half of what passes the cell's right edge, and is cut at the cell's edges. Outlines are hinted.

A glyph advancing more than one and a half cells is two cells wide: CJK, emoji, and the wide icons of a Nerd Font that is not a Mono build. A color glyph, a COLR glyph's layers or a CBDT or sbix bitmap, is drawn unhinted, centred across its cells and kept inside the cell's height. COLR layers are laid over each other with the renderer's rounding, premultiplied, and a COLR glyph larger than its cells is drawn again at the size that fits them.

A color bitmap is taken from the font's largest strike holding it, its colors premultiplied by its alpha, and scaled by vitrify itself to the cell's size, or as far under as fits its cells: Lanczos then a light sharpen (an unsharp mask of radius 0.8 at 120 per cent), the operator's choice on vtium/vtium#23 from a comparison of six ways (`vtium-review-images/23/emoji-scaling.png`). Box, plain Lanczos, box with alpha snapped at half and nearest stay in `src/resample.rs`, one chosen when the tool is built with `VTIUM_VITRIFY_COLOR_SCALE=lanczos-sharpen|lanczos|box|box-snap|nearest`, the first the default. It is a build-time setting rather than Cargo features because the methods exclude each other and features add up across a workspace; an unknown value fails the build. Weights, sizes and placement are computed in f64 with IEEE basic operations alone and rounded to 14-bit integers, and pixels are integers, with no `sin`, `exp` or `powf` from the platform, so a glyph is the same bytes on every host.

The parser's answer, which the parent checks, gives, for each cell asked for, the cell, the baseline, every glyph's width, format and pixels and the map; every codepoint is one the request covers, every RGBA pixel premultiplied, and no glyph larger than a set's chunk.

## Sources

- **kbd names** resolve as `setfont` resolves them (kbd's `src/libkbdfile/kbdfile.c`, `src/libkfont/context.c`): in `consolefonts/` of each data directory in turn (`/usr/share/kbd`, `/usr/share`, `/usr/lib/kbd`, or `--kbd-dir`), the name followed by the first of `""`, `.psfu`, `.psf`, `.cp` and `.fnt` for which a file exists, plain before `.gz`, `.bz2`, `.xz` and `.zst`; a name with a `/` looks in the subdirectory its first component names, and an absolute path is taken as given, then with each suffix. Unimaps resolve the same way under `unimaps/` with `""`, `.uni` and `.sfm`. A font or unimap found by name is resolved through its links and read only if it stays under the `consolefonts/` or `unimaps/` of a data directory; a link out of them fails the source, and nothing is read from outside. A `font:` family's scan fails past `FAMILY_ENTRIES_MAX` entries in one directory.
- **A font's map** is the frit's `unimap=` when given, else the font's own table, else kbd's `def.uni`; a font with none is refused, naming `unimap=`.
- **vconsole** reads `FONT=` and `FONT_UNIMAP=` from vconsole.conf, with the kernel command line's `vconsole.font=` and `vconsole.font_unimap=` over them, as systemd-vconsole-setup reads them (`src/vconsole/vconsole-setup.c`). With no `FONT=`, systemd ran no `setfont` and the kernel kept its font, so the source is refused and names `console:VT`. `FONT_MAP=` maps the kernel's 8-bit translation and sets no glyph, so it is not read.
- **console:VT** takes the font the console read from its own VT at start, with `KD_FONT_OP_GET_TALL`, or `KD_FONT_OP_GET` on a kernel without it, and its map with `GIO_UNIMAP`, and handed the helper (ADR-1200 D8); the helper opens no VT.
- **CPI fonts** are the codepage files kbd ships (`.cp`), as `setfont` reads them: one screen codepage, its 28-byte entry header and its info header, then each font's height, width, aspect and glyph count and its glyphs. A CPI file holds a font of each of several heights, so its source takes `cp-size=` 8, 14 or 16, as `setfont` takes `-8`, `-14` or `-16`, and with none the source fails naming `cp-size=`; `cp-size=` on a source that reads as no CPI file fails that source. Its glyphs have no table, so they take `unimap=`, else `def.uni`.
- **BDF fonts** are read by vtium-vitrify's own reader, never through swash (ADR-1200 D14): Adobe's BDF 2.1, plain or compressed, of `CHARSET_REGISTRY` `ISO10646`, whose encodings are codepoints; any other registry fails the source. Its cell is the narrowest advance among its glyphs wide and `FONT_ASCENT` and `FONT_DESCENT` high, else the bounding box's. A glyph advancing that width is one cell wide and one advancing twice it two; a glyph of another advance, or an encoding no Unicode scalar value, is left out, and a codepoint's first glyph is taken. Each glyph sits on the baseline at its `BBX` offsets and is cut at its cells' edges. A BDF font is read where the source is resolved, in the helper, since the glyph form the parser's child answers with holds no glyph two cells wide.
- **Compression** is told by its magic, as kbd tells it, and decoded with its stream's own check value verified: gzip, bzip2, xz and zstd, each refused past `COMPRESSED_BYTES_MAX` before it is decoded and past `PSF_BYTES_MAX` once decoded.

## Decoders

Each is pure Rust, compiles no C and has no build script, and only this binary links it; `cargo tree -p vtium -e normal` lists none of them, so they add nothing to the minspec binary. The operator approved them on 2026-10-28.

| Format | Crate | Licence | Why this one |
|---|---|---|---|
| gzip | `miniz_oxide` 0.8.9 | MIT, Zlib or Apache-2.0 | Already in every vtium build for the built-in sets' deflated chunks; vitrify frames gzip around it. |
| bzip2 | `bzip2` 0.6.1, on `libbz2-rs-sys` 0.2.5 | MIT or Apache-2.0; `libbz2-rs-sys` under libbzip2's BSD-style licence | Trifecta Tech Foundation's Rust port of libbzip2, the default backend of the most used bzip2 crate, maintained (0.2.5, May 2026), `build = false`; its one C file is a header no build compiles. `bzip2-rs`, decoder only, has had no release since 2021. |
| xz | `lzma-rust2` 0.24.0, features `std` and `xz` | Apache-2.0 | Maintained (October 2026), verifies the stream's check, and with no default features adds only `sha2` and its RustCrypto crates (MIT or Apache-2.0). `lzma-rs` has had no release since January 2023; `xz2` and `liblzma` compile liblzma's C. |
| zstd | `ruzstd` 0.8.2, default features | MIT | The pure-Rust zstd decoder (November 2025), `build = false`; `hash` adds `twox-hash` (MIT) to compute each frame's checksum, which vitrify compares with the frame's own, as `ruzstd` leaves that to its caller. 0.8.2 builds on the workspace's Rust 1.85; 0.9 needs 1.87. `zstd` binds the C library. |
| TrueType, OpenType, COLR, CBDT | `swash` 0.2.10, default features | MIT or Apache-2.0; under it `skrifa` 0.44, `read-fonts` 0.41 and `font-types` 0.12 (MIT or Apache-2.0, Rust 1.85), `zeno` 0.3 and `yazi` 0.2 (Apache-2.0 or MIT), and `bytemuck` 1.25 (Zlib, MIT or Apache-2.0) | ADR-1200 D14's decided rasteriser: the only pure-Rust one with hinting, embedded bitmaps and color, `build = false`. ab_glyph has no hinting, bitmaps or color; fontdue holds every glyph at load. |

The tests' xz fixtures take `lzma-rust2`'s encoder as a dev-dependency; bzip2 and zstd fixtures use the encoders the decoding crates carry.

## The parser

`src/child.rs` runs `vtium-vitrify --parse` for a font: an empty environment, `/` as its directory, its three pipes and no other descriptor. Run as root, the parent starts it as `nobody` from `/etc/passwd`, its supplementary groups dropped, and refuses when there is no such account. The parent kills the parser through a pidfd past 60 s by the wall clock and reads its stderr on a thread of its own. The parser sets no-new-privileges, an address space of 512 MiB, 30 s of CPU, no file writes, no processes and no core, refuses to run as root, reads its request, parses, and answers with the glyph form, which the parent checks field by field against the PSF bounds before it trusts it. A parser that fails, faults, passes a limit or answers malformed fails that source. No command runs it since `create` went; it stays for `preview` and `new` (ADR-1200 D4, vtium/vtium#120, vtium/vtium#121), and the helper takes its `PARSER_MEMORY`.

## The helper

`vtium-vitrify serve` is the helper the console starts on its first need for a frit's glyphs (ADR-1301 D2). It sets no-new-privileges, starts the thread that reads its requests, then sets the parser's limits with 300 s of CPU over its life, and refuses to run as root. Each request carries the frit's name and text, so a frit the console makes on the fly needs no file; the helper reads the frit's fonts itself, as the account the console started it as, parses bitmap fonts and rasterises outline ones in its own process, and draws at the cell each request names, the frit's, never another (#145): an outline font drawn at that cell, a bitmap font scaled by the largest whole factor that fits and placed on the cell's bottom row. A frit's `console:` source takes the kernel's font the console read at start and handed over. It takes three requests: an ask, answered whole ahead of anything else with the glyphs of the codepoints it names; a fill, which draws a cell's coverage while nothing is asked, the codepoints it names first, then printable Latin and box drawing, then the rest, 1,024 codepoints a batch, skipping what the console holds and what it sent, a waiting request taken before each batch; and a stop, which ends a cell's fill. Glyphs go as vitrified sets of one strike each. A source that fails as it draws is left out for the helper's life, and the next source in the frit's order gives its glyphs; a fill that never draws a glyph fails, naming each source whose cell does not fit or that failed. Each request is bounded before anything is allocated for it: the frit's name at 64 bytes and its text at `FRIT_BYTES_MAX`, the cell inside `CELL_SIDE_MAX`, the display's capabilities reserved and empty, 32,000 codepoints, each a scalar value, 65,536 held ranges, and the kernel's font inside the kernel's own bounds. A frame's payload is at most 16 MiB, a batch past it cut in two. It exits after `HELPER_IDLE_MS`, 60,000 ms, with no request and no fill, or when the console closes its end and its work is done.

## Departures

- **A relative kbd name is never looked for in the working directory.** `setfont` tried the name as given first, so a file in the directory it ran from shadowed the data directories. The helper runs unattended. Spec: ADR-1200 D1, "resolved as `setfont` resolves it, in the kbd data directories the build names".
- **A named font with no table and no `unimap=` takes `def.uni`.** `setfont` loaded `def.uni` only for its default font, and left the kernel's map in place for a named one; the helper has no kernel map to inherit. Spec: ADR-1200, "Where vtium departs".
- **A unimap entry for a glyph past the font maps nothing.** kbd handed it to the kernel, which kept it.
- **An outline font's cell is the cell asked for.** The C reference's FreeType backend made its cell the font's line height (`kmscon/src/font/font_freetype.c:189`), its ascent, descent and line gap scaled and rounded, which can pass the height asked for; the helper draws at the cell the console names, so the grid never moves for the font. Spec: ADR-1200 D1, "An outline source is drawn at the cell (D17)".
- **A glyph is one or two cells wide by its own advance.** The C reference drew each glyph at the width the terminal gave its cell; the helper draws a glyph before the terminal asks for a width, so a glyph advancing past one and a half cells is sent two cells wide, and `Font` fits it to the width the terminal gives (ADR-1300).

## What this slice leaves for later

- Raw fonts and styles other than regular (an outline font's bold and italic faces, ADR-1000's `text.outline`): each is refused by name.
- `compress=`'s warning is held in the parsed frit; nothing prints it yet.
- ADR-1300's subpixel strikes, and shaping across cells (ligatures, emoji sequences such as flags and families): a set maps single codepoints.
- A collection matched by family needs a file named for that family; a collection of several families is named with `outline:`.
- COLR version 1 glyphs, such as `Noto-COLRv1.ttf`'s, are not drawn in color: swash reads version 0. A COLR layer in the text's color takes swash's mid grey, since a set cannot know the text's color.
- The parser's account is `nobody`; ADR-1400's pre-login account takes its place once vtium/vtium#31 names it.
- A root run is unverified on the maintainer's machine: the drop to `nobody`, `nobody` executing the binary from its install path, and the real `console:VT` ioctls. Tier 3's guest is where they run.

## Bounds

A frit and every source file are opened once, never blocking on a FIFO, refused unless that descriptor is a regular file, and read no further than their bound.

|---|---|---|
| `FRIT_BYTES_MAX` | 64 KiB | The frit is refused |
| `FRIT_LINE_MAX` | 4096 bytes | The frit is refused, naming the line |
| `FRIT_SOURCES_MAX` | 16 | The frit is refused, naming the line |
| `UNIMAP_ENTRIES_MAX` | 65535, kbd's count | The unimap is refused |
| A font file, a unimap | vtium-font's `PSF_BYTES_MAX` | The source is refused before it is parsed |
| `COMPRESSED_BYTES_MAX` | vtium-font's `GZIP_BYTES_MAX`, 1 MiB, in every compression | The source is refused before it is decoded |
| vconsole.conf, the kernel command line | 64 KiB | The source is refused |
| `GLYPHS_BYTES_MAX` | the largest PSF's glyphs and a map of every codepoint | The parser's answer is refused |
| `PARSER_MEMORY`, `PARSER_SECONDS` | 512 MiB, 30 s | The kernel ends the parser; the source fails |
| `PARSER_WALL_SECONDS` | 60 s | The parent kills the parser; the source fails |
| `FAMILY_ENTRIES_MAX` | 65536 | A `font:` scan of a directory past it fails the source |
| `FONT_DEPTH_MAX` | 8 | A font directory's subdirectories deeper than it are not searched |
