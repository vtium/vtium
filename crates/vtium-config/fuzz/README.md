# vtium-config fuzz targets

Seven cargo-fuzz targets in their own workspace, so the main workspace and CI never build them or pull `libfuzzer-sys`. A cluster the helper shapes is text a program wrote to the terminal (ADR-1301 D1), so `shape` drives clusters through HarfRust and swash as the helper does. A BDF font is a file anyone can name in a frit, so `bdf` drives any bytes through vtium-config's own BDF reader (ADR-1200 D14). The glyph helper reads its requests from the other end of a pipe, so its request parser is its attack surface, and `serve` drives any bytes through it (ADR-1301 D2). A `font:` source makes the helper read the name table of each installed font file it considers, and a user can install any file there, so `names` drives any bytes through that reader (ADR-1500 D8). `pointer-theme` names a pointer file that anyone who owns it can write, and the helper parses it in its sandbox, so `xcursor` drives any bytes through the cursor file reader and `pointer_svg` drives any bytes through the SVG pointer drawing (ADR-1309 D4, D6). A frit is a file that its owner writes and the helper reads, so `frit` drives any bytes through the frit reader (ADR-1200 D1, ADR-1204 D7). Run each on nightly from this directory: `cargo +nightly fuzz run shape`, `cargo +nightly fuzz run bdf`, `cargo +nightly fuzz run serve`, `cargo +nightly fuzz run names`, `cargo +nightly fuzz run xcursor`, `cargo +nightly fuzz run pointer_svg`, `cargo +nightly fuzz run frit`.

From the repository's root, `make fuzz FUZZ_TARGETS=vtium-config:shape` runs a target from a fresh corpus outside the repository and appends a row to `runs.tsv`, the record of how long each run lasted, against which commit, and what it found.

| Path | What it is |
|---|---|
| `fuzz_targets/shape.rs` | Any input as clusters for the test font of `tools/testfont/src/ttf.rs`, or as the font itself asked for a fixed set of clusters, rasterised with each cluster shaped: no panic. Its first byte picks which, the style the rasteriser synthesises over the glyphs, so a crafted outline is also emboldened and slanted (ADR-1302 D4), and the script, so a crafted color glyph is also fitted to two thirds of its cells against the cell's top or bottom (ADR-1202 D5). Each cluster is also asked for as a piece of a syllable, and a crafted font for a piece of Kannada ka, virama and ra, so a syllable is placed across its cells and cut into its pieces (ADR-1203 D3). |
| `fuzz_targets/bdf.rs` | Any input as a BDF font, plain or compressed: no panic, and each glyph the reader keeps is exactly its cells' rows. It also reads the font's `FONT_VERSION` with `bdf::version`, and checks that `bdf::read`, which the helper uses when a source asks for a version, gives the same font and version from one decompression. A seed corpus of a few small BDF files, such as the head of a real one cut before its `ENDFONT`, finds the reader's paths faster than an empty one. |
| `fuzz_targets/serve.rs` | Any input as the requests the console writes to the glyph helper, read one after another by `read_request` until it ends or refuses one: no panic, and each request it takes encodes back to bytes it reads as the same request. A glyph request carries its style, its script and the rows line spacing adds above and below its cell among its fields; a pointer ask carries its file kind, shape, size, heights and file. |
| `fuzz_targets/names.rs` | Any input as a font file through `names::faces`, the reader of a font's table directory and `name` table: no panic, at most `FACES_MAX` faces, each read once at a rising index, and no family an empty string. It reaches the reads of a collection's header, each face's table directory and its `name` table, and read-fonts' parse of that table. It also reads the version of the first face and of each family with `serve::outline_version`, which `version=` matches against, from the same `name` table. |
| `fuzz_targets/xcursor.rs` | Any input as one cursor theme file through `xcursor::read`, its first byte the `pointer-size` asked for: no panic, and each picture kept is at most 64 pixels a side, holds exactly its pixels, has its hotspot inside it, and has no color above its alpha. It reaches the header's checks, the table of contents, each image's header, the size rule and the pixels' conversion. |
| `fuzz_targets/pointer_svg.rs` | Any input as an SVG pointer file through `pointer_svg::draw`, its first two bytes the cell height and the shape: no panic, and each picture holds to the same rules as `xcursor`'s. It reaches roxmltree's parse, the symbol's viewBox and `data-hotspot`, the rebuilt document, and usvg's and resvg's parse and drawing of it. |
| `fuzz_targets/frit.rs` | Any input as a frit's text through `Frit::parse`, and as a text with its layers in place through `Frit::parse_spliced`: no panic. In each frit the reader accepts, each source's `check=` ranges are sorted, merged and within Unicode, its `sha256=` is 64 lowercase hexadecimal digits, its `url=` starts with `https://` or `http://`, and its `version=` reads back from its own spelling. Any input as a font's version string gives no version, or one that reads back the same. |
| `Cargo.toml`, `Cargo.lock` | The fuzz crate and its pinned dependencies. |
| `.gitignore` | Leaves out `target`, `corpus`, `artifacts` and `coverage`. |
