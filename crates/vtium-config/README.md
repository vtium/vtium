# vtium-config

The head file of ADR-1401: its reader, its parser, and the evaluator that places each display and input in a head, in the focus, in `ignore` or in `dark`, with the guards over the result. `vtium` and `vtiumctl` both link it, so the verdict before install is the verdict at boot. It depends on neither `vtium` nor `vtium-platform`: a device reaches it as an `Identity` its caller fills, and the guards are functions of a placement and the set of devices. It forbids unsafe code, denies every input-reachable panic, and depends only on rustix, to open the file as the console opens kmscon.conf.

## Behaviour

- **The file.** `HEAD_FILE` is `/etc/vtium/heads.conf`, one file with no drop-ins, ADR-1401 probe 1's recommendation. `inspect` looks the path up with symlinks followed, returns `None` for a file that does not exist, the compiled-in configuration's case, and refuses anything but a regular file before it opens it, since opening a FIFO, a watchdog or a serial port acts on it; it opens without blocking, reads at most `FILE_MAX` bytes and one, and gives the text beside the ownership verdict, so `vtium check-config` can check a candidate that is not yet root's. `read`, the start's reader, refuses a file root does not own or that its group or others can write; a directory above it, on the path given or above any link of its symlink chain, each resolved one link at a time, that root does not own or that its group or others can write; more than `FILE_MAX` bytes; bytes that are not UTF-8; and any control character but tab and newline, a carriage return and the C1 controls among them. Each refusal makes the file invalid. `Trust::owner` trusts a test's own user in place of root, since no test runs as root, and `Trust::below` stops the directory check at a test's fixture directory, so a target directory under `/tmp` passes; `Trust::ROOT` checks every directory up to `/`.
- **The syntax.** The first line that is not blank or a comment is `version = 1`. `#` starts a comment anywhere on a line, so a value holds no `#`; blanks around `=` and between tokens are dropped, so a value holds no blank, and a glob's `?` stands for a space. A switch is `on` or `off`. A key set twice in one section, and a second `[rules]` or `[guards]`, make the file invalid.
- **Rejected whole.** Every line is read whatever came before it, so a check names every error, each with its line, in the file's order, and `at` shows it as `PATH:LINE: WHAT`, as kmscon.conf's reports read, with every control and format character of the path escaped; `ERRORS_MAX` are kept and the rest counted. Text an error quotes is cut at `QUOTE_MAX` characters and shown with every control and format character escaped; a path is quoted whole.
- **Heads.** A name is 1 to 64 of `A-Z a-z 0-9 . _ + -`, and `focus`, `ignore` and `dark` are reserved; a profile's name keeps the same rule. `consoles` is 1 to `CONSOLES_MAX`, and more gets the cap with a warning. `login` is kept as written, for vtium to read as kmscon.conf's `login`. `on-loss` is `nohup`, `hangup`, or `hangup DURATION`, the duration a count of seconds or with an `s`, `m` or `h` suffix, at most `u32::MAX` seconds. `font-size` is 0 to `FONT_SIZE_MAX`. A head's font is its own keys over its profile over kmscon.conf's keys; until profiles have files, the `default` profile states nothing and any other states its frit, the frit of its name.
- **Rules.** A rule is `display MATCH -> TARGET` or `input MATCH -> TARGET`, with `*` alone or at most `TOKENS_MAX` tokens; a rule may name a head declared after it. `focus` and `ignore` are an input's targets, `dark` a display's. `path` matches its `ID_PATH` and every interface below it (`...:3.3` takes `...:3.3:1.0`, never `...:3.30` or `...:3.3.1`); `serial` and `edid` split their value at the first two `:`, so the serial may hold more; `id`, `serial`'s vendor and product and `edid`'s product are hex with or without `0x`; `connector` splits at its last `/`; `name`, `card`, both halves of `connector` and `udev`'s value are globs (`*` and `?`); every other value matches as written. A key of the other kind's devices matches nothing.
- **Warnings and notes.** A rule an earlier rule of its kind shadows (the earlier is `*`, or its tokens are among the later rule's) and a head's consoles past the cap are warnings. A guard turned off, a head's `rescue = off`, and input sent to a head by `id` or `name` alone are notes. `Config::needs_udev` lists the rules using a key that reads udev's database, for `vtium check-config` to note where no daemon runs.
- **Placement.** `walk` places one device by the first rule of its kind that matches it; with none, a display goes dark and an input follows the focus. `place` walks a set and runs the guards: the display guard, when no display reaches a head, lights the boot display (the connector lit at start, else the boot card's first connector in the kernel's order, else the first connector of the other cards in the kernel's order, so a connected display always lights; the boot card, the card's place in the kernel's order, the connector's place and then the whole identity break a tie) in the first head, or the default head where the file has none; then the anti-lockout guard, when no device counted as a keyboard reaches a head with a lit display, sends every keyboard-class device to the focus and moves the focus to the boot display's head, else the first lit head in the file. `place` takes the head holding the focus and returns where it rests: a device following the focus reaches a lit head only when that head is lit; with no focus yet, the focus starts by the same rule; and while a keyboard reaches a lit head the focus stays where it is. A device udev marks `VTIUM_ROLE=token` or `VTIUM_ROLE=numpad` is not counted. `rescue` says whether the rescue key takes a keyboard, `disposition` whether an input is opened, opened for the rescue key alone or left closed, `lockout` the layer 1 warnings of the rules alone, and `idle_rules` the rules no present device matches.
- **Outcomes.** `resolve` answers, for every path, which rules run (the file, its survivors, the shipped rules or none), the effective policy, how the run holds `isolated`, the console line, which displays may light, what the always-on display guard lights when the running rules light none, and what an input no running rule places gets, by three levels asked in order (ADR-1401 D7). A missing file runs the shipped rules silently; a file that fails the ownership check or cannot be opened is never read, and runs them with `invalid config skipped, using builtin`. A trusted file always fails to its policy: `policy = open`, `policy = closed`, nothing, which is open, or no readable closed policy and a `policy` line vtium cannot read, which is no policy and an error. A valid file runs as written; a valid open file that declares nothing runs the shipped rules; a partly broken one runs what survives under its policy with `config partly invalid, running what's valid`, and under open also treats every surviving head as not isolated, so the rescue key reaches its keyboards, its VT keys switch the VT and it may be the active head, and places what its surviving rules do not by the shipped rules' input tail; a broken one with no policy or `open` runs the shipped rules with `invalid config skipped, using builtin`, and with `closed` runs nothing and lights the boot display for `config invalid, closed: input off` alone. `Outcome::switch` gives each switch its rule in the run: the policy alone sets the anti-lockout guard and the rescue key, on under open and off under closed, and a head's `isolated` takes what the file writes, else `no` under open and `yes` under closed. `scope` takes an error inside a head's section to drop that head, a bad rule or top-level line to drop that line, and an error in the file's format, bounds or structure to drop the file, its readable `policy` line still read.
- **A readable closed policy is sticky.** A readable `policy = closed` wins over every other `policy` line, which leaves the file partly broken, and no broken line runs it past closed: a partly broken closed run lets the rescue key reach nothing the policy does not, and under closed the display guard gives no head a display its rules do not claim, lighting the boot display for the notice alone when a file with heads has none lit, `vtium: no display for any head`, the one notice a valid file shows, or has failed, with its line, and nothing for a valid closed file that declares no head, which is dark and silent. `Outcome::reload` applies only a valid trusted file, the owner's deliberate change, and leaves whatever runs as it is for a missing, untrusted, inaccessible, partly broken or broken one, under either policy; the closed policy is sticky for the boot, and a closed file deleted or made untrusted before a reboot starts the shipped rules with the notice. The run-time model in `src/outcome/tests/runtime.rs` explores every state the events while vtium runs can reach from every start outcome and every isolation of its heads, and checks that none opens what a closed file did not grant or what the start outcome does not allow.
- **The kernel command line.** `heads_word` reads the last `vtium.heads=`: `builtin`, or a value vtium logs and ignores.

## Departures

- **An invalid head file is rejected whole.** kmscon.conf's reader, the C reference's and vtium's, takes each line it can and reports the rest; a head file routes input and chooses login commands, so no part of an invalid one applies (ADR-1401 D7).
- **The file must be root's, in root's directories, writable by no one else.** The C reference read any file at its path (ADR-1401 D10).
