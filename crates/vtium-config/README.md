# vtium-config

vtium's configuration tool of ADR-1201 and ADR-1403, which users reach as `vtium config`, and the program that generates vtium's glyphs at run time (ADR-1200, ADR-1301 D2), its own binary outside the minspec build. `vtium-config tui` opens its TUI, a full-screen program drawn in the terminal's text cells, which draws the configuration as a flow from the displays to the input devices, lists the frits (font set files) and the built-in fonts, switches the live console to each font the user highlights, previews sizes as pictures, and writes every change into the user's draft of vtium.conf, which Install installs. Its `serve` command is the helper the console starts: it takes a frit's text from the console, finds and reads the frit's sources, parses each bitmap font and rasterises each outline font, and sends the glyphs at the cell asked for in the glyph chunk format, written with vtium-font's writer. Its `use-frit` command switches the running console's frit. Its flow commands, `flow`, `rule`, `head`, `look`, `set`, `install` and the rest, edit the user's draft of vtium.conf and install it ([The draft](#the-draft)). Every decoder lives here; the console reads only the helper's glyphs and its own built-in fonts. The crate forbids unsafe code; the console font ioctls it needs live in vtium-platform's `src/vt/font.rs`.

The glyph helper finds the sources under its own sandbox, one helper answering a sources query for every frit, each answer waited for at most `HELPER_WAIT`, 5 s, so this process parses no font (ADR-1201 D3). When the helper does not start, fails or stalls, the answers that came are kept and each frit still unanswered prints `reads` and `unknown:` with why, never `draws nothing`. |

Run as root it writes no file and refuses `--save`. ADR-1200 D24 lists its parts, the programs it runs and its privacy rules. `--root DIR` reads the machine under DIR, for the tests. |

Each frit command prints one line a result, tab-separated, and exits 0 on success, 1 on a failure and 2 on a usage error. A frit is a file no draft of vtium.conf holds, so `new-frit` and `remove-frit` do not go through the draft. Run as a user, a frit command that changes something writes an install bundle under `$XDG_STATE_HOME/vtium/drafts` and prints `write PATH` or `remove PATH` for each file the bundle holds, then `draft DIR`, the bundle's directory, and `run COMMAND`, the command that installs it, `sudo /usr/bin/vtium-config apply DIR` for the system's directories; a change that changes nothing prints `unchanged` and writes no bundle. Run as root, it installs at once: it writes the bundle into a directory of root's own under `/tmp` and applies it, printing `apply`'s lines. After the command word, an option the tool does not take for itself is the command's own, as `new-frit --name`. The font store's commands, `create`, `list`, `verify` and `remove`, are gone with the store (ADR-1200 D3, D12, retired), and each is an unknown command; `install` is the flow's command now.

The frits are in the directory `font-frits` names, and where it names none in `/etc/vtium/fonts`, which `VTIUM_FONT_FRITS` changes at build time. vtium-config reads `font-frits` from the top level of the one file the console reads, `vtium.conf` in its configuration directory (ADR-1403 D2). `fonts`, `new-frit`, `remove-frit`, `use-frit`, `preview`, the TUI and `apply` list, write and remove frits in that directory. vtium-config does not see a `font-frits` that the console takes from its own command line, as the VT review's `run-vt.sh` passes it; for that, `--frits DIR` names the directory. vtium-config takes `font-frits` only as an absolute path, as the console does. The console ignores a relative or empty one and says why. vtium-config makes each of those commands fail instead, naming the file and the key, and it does the same for a configuration file it cannot read. `get` and `set` still read and set vtium.conf's key in the draft, so the user can mend a vtium.conf, and `set` refuses a value that is not an absolute path. An install or an install bundle that changes vtium.conf's `font-frits` and also writes or removes a frit is refused, since its frits would go to the directory `font-frits` named before; the user installs the new directory first. `--frits DIR` names another directory in place of `font-frits`; `--configdir DIR` names another directory than `/etc/vtium` for vtium.conf; `--sudo PROGRAM` replaces `sudo` in an install's privileged step; `--vtium PROGRAM` names the console binary `apply` checks files with, `/usr/bin/vtium` unless `VTIUM_PROGRAM` set another at build time; none of these is taken as root ([The privileged step](#the-privileged-step)); and `--kbd-dir DIR` (repeatable), `--font-dir DIR` (repeatable), `--vconsole-conf FILE` and `--kernel-cmdline FILE` replace the paths `serve` finds sources in, `--sys DIR` replaces `/sys`, where the TUI and `preview` measure the displays and the flow's commands read the devices present, `--udev-data DIR` replaces `/run/udev/data`, udev's database, and its directory's `control` names the daemon's socket, and `--helper PROGRAM` replaces the glyph helper the tool starts, this binary's `serve`, as a test's stand-in does.

`vtium-config --help about` draws a banner of its name in glass (`src/banner.rs`, vtium/vtium#112) and says what the program is. `--help` lists `about` among its help topics, and `--help COMMAND` prints one command's own help from the text the usage reads (`src/help.rs`). The picture is drawn only when stdin and stdout are both terminals, never with a non-empty `NO_COLOR`, never in a Chinese, Japanese or Korean locale, and never into a pipe, where `--about` prints plain text. No other command prints the banner. `--no-banner` does nothing now, and vtium-config accepts it so that scripts that pass it keep working.

## The TUI

At start the TUI writes four requests at once, XTVERSION, the OSC 50 query, kitty's graphics query and DA1, and waits at most a second for DA1's reply, which every terminal of the VT100 line sends after the others. In a vtium console that answers the OSC 50 query, each font the user highlights is sent as `OSC 50 ; NAME ST` and the query, one switch at a time: the next goes when the last one's reply comes, and names whatever is highlighted then. A reply that names another font marks the font as kept by the console. With `allow-font-ops` off the TUI says so and offers to turn it on as a change in the draft; in any other terminal it sends no OSC 50 but the query at start. Leaving by `q`, by Ctrl-C, or by SIGINT, SIGTERM, SIGQUIT or SIGHUP switches the console back to the font the start query named and waits for the reply; a panic writes the switch back from the panic hook, since a release build aborts on a panic. Nothing can give the font back after SIGKILL or once the terminal is gone.

Its views are Flow, Looks, Fonts, Settings and Help, in the order Tab steps through them, and `vtium-config tui` opens it on Flow. Flow draws the configuration from the displays to the input devices (ADR-1403 D7): six columns, displays, display rules, heads, looks, input rules and input devices, each in its own color of the console's sixteen, with no blue; displays, heads, looks and input devices as blocks of color, rules as colored text, and lines between them. From 100 columns each line runs in a lane of its own, and a line whose target is scrolled out of sight ends in an arrow at the columns' edge; ADR-1403 D7 says where the lines run. Tab and the arrows move between the columns and within them, Space tags an item, `f` follows its line toward the heads, Enter opens its card below the columns, `?` opens its route card, and Esc clears the tags. The Flow view alone turns on mouse reporting, modes 1000 and 1006: a click selects an item, a second click opens it, and a click on a view's name switches to that view. With `NO_COLOR` set, or a `TERM` that is unset or `dumb`, it draws no color, and each block's text is in brackets. It draws the current draft ([The draft](#the-draft)) with the devices present placed on it, and follows udev's device events while it is open, through vtium-platform's watch, which opens no device node; `d` reads every device again. Every change it makes, through a card, a `new…` item, a delete or `c` on a path of tagged items, goes through `src/ops.rs` into the draft at once, and the top row counts the draft against the installed file and the check's problems. Looks holds the console's sizes until looks are built. Fonts lists the frits and the built-in fonts, and `n` opens the new-frit view. Settings lists vtium.conf's keys. Help holds the keys of each view and the commands, and its About page what `vtium-config --help about` prints. Install, on `i` in every view, is among the actions in the tab bar beside View, Revert, Restore, New and Delete draft. It installs through the same three steps as `vtium config install` (`Session::prepare`, `put` and `finish` in `src/drafts.rs`): it refuses a draft made before the installed file changed and a draft the check fails, asks `Install the draft?` with the lines added and removed and the frits waiting, and gives the terminal to sudo for the privileged step. In the Fonts view, `r` marks the highlighted frit to be removed when the user installs, and a second `r` keeps it. The TUI refuses what `remove-frit` refuses, by the same check (`removal_refusal` in `src/commands.rs`): a built-in font, and a frit a `font-name` of vtium.conf names, at its top level or in a look, both in vtium.conf as it is and as the install leaves it. It also refuses a frit that a new frit in the same install replaces. A frit is a file no draft holds, so a new frit and a frit's removal wait in the TUI and go into the next Install's bundle, before vtium.conf; leaving asks before it drops them. The font list marks a frit to be removed, and `apply` keeps the old file as `NAME.vtfrit.bak`. The settings view lists every key vtium.conf takes, from the console's own key table in vtium-settings, the font keys first (`font-name`, `font-size`, `font-frits`, `font-hinting`, `font-line-spacing`, `allow-font-ops`, `display-dpi` and the sprite policy's `glyph-source` keys) and the rest in the table's order, each with its value or its default, and under the list what the highlighted key does. Enter turns a switch on or off, steps a key of a fixed set of words to its next word, and starts typing any other key's value, which a second Enter writes into the draft; an empty value leaves the key at its default, and moving away drops what was typed. The new-frit view is `new`'s guided flow (ADR-1201 D9): the user types the frit's name, up to three sources, a cell and a size, Enter moving to the next field, and Enter on its last row adds the frit to the next Install once the frit reader takes it. A frit of an installed frit's name replaces it, Install replacing the text the TUI read at start; an installed frit that is not UTF-8 text is not replaced, and the view says to remove it first. While a field or a value is typed, every character is text, `q` and `i` included, and Ctrl-C still leaves. Where the terminal answered kitty's graphics query and the console cannot be switched live, because `allow-font-ops` is off or the terminal is not vtium, the Fonts view shows the highlighted font's specimen as a picture below the list, at the draft's `font-size`, else 12 points, and deletes it as the highlight moves; a frit that does not read gets none. Where the terminal answered kitty's graphics query, each size shows a specimen picture at the pixel height that size gives at the density ADR-1200 D17 orders: vtium.conf's `display-dpi`; else the density down the screen of the first connected display, in the order of its connector's name, whose EDID states its size (`src/display.rs`, which reads each connector's `status`, its first mode and its EDID's base block from sysfs and opens no card); else 96 dots per inch. The TUI says which it used. The specimen is three lines of Latin, digits and box drawing, and a fourth in the locale's letters where `LC_ALL`, else `LC_CTYPE`, else `LANG` names a language whose script takes a cell a character: Cyrillic, Greek, Japanese, Chinese, Korean, and the accented Latin of German, French, Spanish, Portuguese, Polish, Czech and Slovak, Turkish and Vietnamese. A script whose letters join or stack, as Arabic, Hebrew's points, Thai or Devanagari, has no line until the specimen shapes clusters; a CJK character takes two cells, as the console draws it. Where the terminal draws no pictures, a size shows a sentence instead: the cell it gives, the grid that cell gives on that first display, and how many of the specimen's characters the font draws itself. Once the terminal is known, the TUI asks one helper which sources each frit that reads lacks, through the sources query `fonts` uses, on a thread of its own whose answer wakes the loop, so the TUI goes on reading keys, Ctrl-C included, while the helper works, and the font list notes a frit lacking some, as `reads, 1 source missing`, or none of whose sources is on this machine. A frit the helper gives no answer for in its wait, as when it stalls, keeps the answers that came for the others and is noted `reads, sources not checked`. The helper draws the glyphs under its own sandbox ([The helper](#the-helper)), so the TUI's process parses no font, and the picture goes as kitty graphics' raw pixels, `a=T,f=32,t=d`, in chunks, and is deleted with `a=d` when the highlight moves or the TUI leaves. The TUI needs a terminal of at least 80 by 25 cells (`MIN_COLS` and `MIN_ROWS` in `src/tui/view.rs`; ADR-1201 D3). Below that, as a large previewed font can leave, it draws no view: one screen says the size it needs and the terminal's, lists the commands, which work at any size, and keeps the keys `q`, which leaves, and `u`, which puts the console's start font back. Its sentences and keys wrap by words, and every view shows its tab bar, status line, message and keys whole. The words the TUI shows are in `src/tui/words.rs`.

## Reviewing the screens

The maintainer reviews the TUI's screen goldens in `tests/screens/` as pictures and by using the TUI, not as text. Two make targets serve that review, and neither is a gate.

`make tui-shots OUT=DIR` draws every screen golden as a PNG, `DIR/NAME-COLSxROWS.png`, the accepted goldens and the provisional ones alike; without OUT the PNGs go to `target/tui-shots`. It runs the two golden tests of `tests/tui.rs` with `VTIUM_CONFIG_SHOTS=DIR/bytes`, and under that variable each test also writes, for each golden, every byte the TUI wrote to reach the screen and the screen as text. The tool `tui-shots` in `tools/tui-review/` then plays each byte stream through vtium-term and vtium-render in unifont, 8 by 16 pixels a cell, as tier 2 draws its screens, so each PNG shows what a vtium console in unifont shows for those bytes. Before it writes a PNG, it checks that the screen the test read is the committed golden in `tests/screens/`, and that the same bytes, played into a terminal of its own, read as that screen. So each PNG shows its committed golden. A golden that has drifted, as a provisional one can without failing its test, is named and not drawn, and `make tui-shots` fails. The bytes come from the golden tests rather than from the binary on a pty, because the goldens' fixtures reach the TUI through its loop in the test process; the binary writes its screens through the same loop.

`make tui-demo` opens the real binary's TUI in your own terminal on the fixtures of the goldens named `draft-*`: the draft `bench` of their installed vtium.conf, the keyboard `kbd` at `pci-0:3.3`, laid out as a sysfs tree and a udev database, and their stand-in console as the check. `make tui-demo FIXTURE=figure` opens the TUI on the flow of ADR-1403 D7's figure, which the goldens named `flow`, `card` and `route` draw. That flow comes from no draft, so in that demo the view changes nothing. `tools/tui-review/demo` makes a throwaway directory, points `HOME` and every XDG directory into it, and removes it when the TUI leaves. The tool `tui-demo` refuses to start unless that directory is fresh and empty, named by its real path, and neither your home nor a directory above it, and unless `HOME` and every XDG directory lie under it with no `..` in their paths; it also refuses to run as root. vtium.conf and the frits live in that directory too, so Install runs `vtium-config apply` as you into it and never asks for sudo, and the sudo the TUI is given refuses to run. Nothing the demo does reaches your own `~/.config`, `~/.local` or `/etc`.

## The draft

The flow's commands and the TUI change the user's draft, a whole vtium.conf kept in vtium-config's store, and only `install` writes `/etc/vtium/vtium.conf` (ADR-1403 D8). vtium reads only the installed file, so nothing the user edits reaches the console until it is installed.

| Path | What it holds |
|---|---|
| `$XDG_CONFIG_HOME/vtium/drafts/NAME.conf` | Each draft. The first is made from the installed file, or from the shipped example when none is installed, and is named for the machine's hostname, with `-2`, `-3` and so on appended so that no draft is overwritten. |
| `$XDG_CONFIG_HOME/vtium/vtium-config.conf` | `draft = NAME`, the current draft, and `history = N`, how many installed files the history keeps, 10 unless set. |
| `$XDG_CONFIG_HOME/vtium/library.conf` | The library, in vtium.conf's section syntax. |
| `$XDG_CONFIG_HOME/vtium/installed/DRAFT-N.conf` | Each installed file an install of DRAFT replaced. |
| `$XDG_STATE_HOME/vtium/bases/NAME.base` | Each draft's base: the SHA-256 of the installed file it was made from or installed as, or `none`. |
| `$XDG_STATE_HOME/vtium/drafts/` | The install bundles `install` hands to `apply DIR`. |

`XDG_CONFIG_HOME` is `~/.config` and `XDG_STATE_HOME` is `~/.local/state` when unset. Run as root, vtium-config finds root's home from the password database and never from `$HOME` or the XDG variables, which `sudo` can carry over from the user who ran it, so a root draft lands only in root's own home.

Every command that changes the draft reads it afresh, makes its change through `src/ops.rs`, writes it whatever the check says, so a draft may be unfinished, runs `vtium check-config` on it, prints each line the check prints and then the state line, `draft NAME: 3 lines added, 1 removed · 1 problem`. The state says `same as installed`, the lines added and removed, or `made before the installed file changed` once the installed file's hash is no longer the base. With `--dry-run` a command prints the change as a difference and the check's verdict and writes nothing, and with `--install` it then installs the draft. `install` refuses a draft made before the installed file changed, then one the check fails, then builds an install bundle of the draft and runs `sudo vtium-config apply DIR`, or as root installs at once; after a good install it saves the file it replaced in the installed history and makes the draft's base the new installed file. `edit` copies the draft to a file under `$XDG_STATE_HOME/vtium/`, opens it in `$VISUAL`, else `$EDITOR`, else `vi`, makes the edited copy the draft, and asks whether to edit again when the check fails; with `--install` it installs only a draft the check passes.

A rule's number is its place in `[rules]`, counted from 1. `rule add` without `--before` places a rule through vtium-settings's `placement`: a rule that names one device goes before the first rule of its kind that names a kind of device, and a rule that names a kind goes before the first `*` rule of its kind. `flow` prints the draft's flow with the devices present placed on it, read from sysfs and udev's database without privilege, and `flow --json` prints one object whose `version` is 1, with the draft's name, state and problems.

The exit codes 0 to 5 are `src/outcome.rs`'s, and [Configure vtium](../../docs/configure.md#the-commands) lists what each means.

`head rm` removes a head and leaves the rules that send to it, which it names and which the check lists until each is pointed elsewhere or removed. `look rm` refuses a look a head names, naming the heads, unless `--force` sets those heads to the default look first. `--name` on `head set` and `look set` renames the section with every rule or head that names it, in one change. `head active` needs the control socket ADR-1401 D12 plans and says so with exit 2.

A debug build run under cargo, as every test is, refuses the real user's store, `~/.config/vtium` and `~/.local/state/vtium` under the home the password database gives, with exit 5. Every test that runs the binary starts it through `tests/common/home.rs`, which points `HOME`, `XDG_CONFIG_HOME` and `XDG_STATE_HOME` at a directory of the tests' own, and `tests/cli.rs` holds a test that forgets to on purpose and is refused. A release build, the one users install, never refuses. Every path the store builds from a draft's name goes through one check, `store::named`, which refuses a name that is not 1 to 64 letters, digits, `.`, `_`, `+` and `-`, or that starts with `.` or `-`, with exit 2. vtium-config records a draft's base the first time it sees the draft, so a draft copied in from another machine is refused at install once the installed file changes after that.

## The privileged step

An install becomes an install bundle, a directory the user owns under `$XDG_STATE_HOME/vtium/drafts`, named for the time it was made, which holds the whole new vtium.conf, each frit to write under `fonts/`, and a `MANIFEST` that names each file with the SHA-256 of the installed file it replaces, or `new`. When the directories are the system's, vtium-config writes the bundle and runs exactly one command, built as an argv and never as a shell string: `sudo /usr/bin/vtium-config apply BUNDLE`, with no option, so a sudo rule can name it whole. `vtium config install` runs it as a plain child with the terminal as its standard input, so sudo can ask for the password. The TUI leaves its alternate screen while sudo asks, runs the command in a process group of its own in the terminal's foreground so that Ctrl-C reaches sudo and not the TUI, through `--run-with-signals`, which releases the signals the TUI holds in the child alone, and shows what the command printed when it fails. The TUI runs as the user from start to end (ADR-1201 D5): run as root, it does not open, and says to run `vtium config` as yourself, since it asks for sudo when it installs. A command run as root installs at once, writing the bundle into a directory of root's own under `/tmp` and applying it, with no sudo. When `--configdir`, `--frits` or `--vtium` name anything but the system's directories and console, as the tests do, vtium-config offers no privilege at all: it runs `vtium-config` with those options and `apply BUNDLE` as the user.

**Which tools can run apply.** Run as root, apply takes the user an install bundle belongs to from `SUDO_UID`, which sudo sets, `PKEXEC_UID`, which pkexec sets, or `DOAS_USER`, the user's name, which doas sets and apply looks up in the user database. So `sudo`, `pkexec` and `doas` each work as `--sudo PROGRAM`, and a tool that sets none of them can install only a bundle root owns. Each tool sets only its own variable, so when more than one is set, one was kept from the user's environment or forged, and apply refuses the bundle with exit 1 and says so. doas with `permit keepenv`, for example, keeps a `SUDO_UID` the user set, which would otherwise name another user's bundle. Each variable is still only as trustworthy as the tool that sets it: a tool that lets the user set its own variable can make apply read a bundle of any user it names.

**What `sudo vtium-config apply` can change.** Run as root, vtium-config refuses every option that names a path or a program, `--configdir`, `--frits`, `--sudo`, `--vtium`, `--kbd-dir`, `--font-dir`, `--vconsole-conf`, `--kernel-cmdline`, `--sys`, `--udev-data`, `--helper` and `--root`, and refuses `--run-with-signals`, each with exit 2 and the reason. It also refuses, with exit 2 and the words to run it as yourself, the commands that run as the user: `check` and `new-frit --from`, which read a file the user names and would otherwise read any file and could print what is in it, and `fonts` and `preview`, which start the glyph helper, which refuses root. `new-frit FONT...` and `remove-frit` run as root, and so do the flow's commands, on root's own draft, since they write only text they build themselves, through `apply`'s steps. `report` runs as root to read the kernel's display state and the whole journal, writes no file, and refuses `--save` in any form, so that a rule letting a user run the report as root never lets that user create a file where root can; the user's own shell saves what it prints, as in `sudo vtium-config report > vtium-report.txt`. So `sudo vtium-config apply BUNDLE` writes only `/etc/vtium/vtium.conf` and frits in the frits' directory that `/etc/vtium/vtium.conf`'s `font-frits` names, else the one the build names, each only after the frit reader or the console's own `vtium check-config` has accepted it, and runs no program but the console the build names, `/usr/bin/vtium` unless `VTIUM_PROGRAM` set another.

vtium.conf's top level is edited line by line by vtium-settings's `edit_conf`, which reads each line with `key_line`, the console's own reading, and its sections by vtium-settings's section writer, so every comment, blank line and line ending stays (ADR-1403 D8).

`apply BUNDLE`:

1. reads the bundle without following a link, takes only regular files with names it knows and no second name (a hard link), owned like the bundle's directory by root or by the user the privileged tool ran it for, and bounds each, since root is reading a directory the user owns; and since root read those files for the user, what it says of them names a file, a line and a key, and quotes nothing they hold;
2. refuses the bundle, writing nothing, when a file it replaces has changed since the bundle was made, naming the file;
3. checks every file before it writes any: each frit with the helper's frit reader, and vtium.conf, its top level and its sections in one run, with the console's own `vtium check-config`, run on root's copies of exactly the bytes it then writes, made in a new directory of its own under `/tmp`, whatever `TMPDIR` says, with a random name and mode 0700, each copy created through the directory's descriptor without following a link;
4. writes the frits, then vtium.conf, so that vtium.conf never names a frit that is not there, each through vtium-settings's `install_file`: a new file beside the old one, mode 0644, flushed and renamed over it, the old one kept as `NAME.bak`;
5. prints one line a file, `wrote PATH`, `removed PATH`, `failed PATH` with the reason, or `not written PATH` after a failure, and exits 0 when it wrote them all. The bundle stays, so it can be applied again.

The step is one short process. Most of its time goes to the one run of `vtium check-config` in step 3, which reads the devices present for the complete-route check as the user's own check did.

## Frits

One `key=value` a line, blanks around key and value dropped, `#` to the line's end a comment, as vtium.conf reads; unlike vtium.conf, an unknown key, a malformed line, a value with a control character or a key this build does not build yet refuses the whole frit, naming the file and line. This slice reads ADR-1200 D1's keys and ADR-1301 D4's `antialias=`: `name=`, `source=` (`font:`, `kbd:`, `file:`, `bdf:`, `outline:`, `vconsole`, `console:VT`, `builtin:`), `unimap=`, `cover=` (`ascii`, `latin-1`, `gb2312`, `gbk`, `big5`, `jis-x-0208`, `ks-x-1001`, `U+XXXX` and `U+XXXX-U+YYYY`), `cp-size=`, `style=` (`regular`, `bold`, `italic` or `bold-italic`, for the source above it, regular when no line names one; any other value refuses the frit, naming its line), `cell=`, `size=`, `glyph-source=` and `glyph-source-<range>=`, `antialias=`, `hinting=` and `license=`. The store's `package=` and `sha256=` are unknown keys. `compress=`, which chose how a stored set was compressed, is accepted with one warning naming the file and line, since refusing it would leave the console on the built-in font for a key that never changed what was drawn.

`cell=WIDTHxHEIGHT`, each side 6 to 96 pixels, states the cell the console draws the frit in and the helper generates for (#145); the console reads it as text before its first frame. `size=`, once, 6 to 96, is an outline frit's starting size in points, from which a zoom steps; the console reads it, converting it at the display's density (`crates/vtium/README.md`), and the helper draws at the cell each request names. `glyph-source=` and `glyph-source-box=`, `-block=`, `-braille=`, `-sextants=`, `-octants=` and `-legacy=` take `font`, `sprites` or `auto`, the configuration's names and values, each once; the console reads them as the frit's sprite policy, its configuration's keys over them. `antialias=` is `auto` or `no`; the engine reads it once ADR-1301 D6's grid is built. `hinting=`, once, is `light`, the default, which fits outline glyphs to the pixel grid up and down only, or `full`, which also fits them sideways ([Outline fonts](#outline-fonts) says how).

`line-spacing=`, once, is a whole percentage from 0 to 100 of the text's height that the console adds to each row (ADR-1302 D13); the console reads it as text, as it reads `cell=`, and vtium.conf's `font-line-spacing` overrides it. `fit=` says how the set on the `source=` or `cover=` line above it uses the taller row: `fill`, `natural` or `room`, once for each set. A `cover=` line's `fit=` wins over its source's, and a character in no set with a `fit=` takes its default: line and block characters fill, Arabic, Hebrew, Syriac, Thaana, N'Ko and combining marks have room, and the rest is natural.

A source's `cover=` lines are one union, sorted and merged. `ascii` is U+0020 to U+007E and `latin-1` adds U+00A0 to U+00FF. Each named set is the codepoints a Unicode mapping file maps to. `gb2312`, `big5`, `jis-x-0208` and `ks-x-1001` come from the standards' own tables, with no vendor's extension; `gbk` comes from Microsoft's code page 936, whose table also maps U+0000 to U+007F and, at 0x80, U+20AC. The files: `gb2312` from `OBSOLETE/EASTASIA/GB/GB2312.TXT` (7,445 codepoints), `gbk` from `VENDORS/MICSFT/WINDOWS/CP936.TXT` (21,920), `big5` from `OBSOLETE/EASTASIA/OTHER/BIG5.TXT` (13,704), `jis-x-0208` from `OBSOLETE/EASTASIA/JIS/JIS0208.TXT` (6,879) and `ks-x-1001` from `OBSOLETE/EASTASIA/KSC/KSX1001.TXT` (8,224), under unicode.org's `Public/MAPPINGS/`. unicode.org no longer serves `GB2312.TXT`, so it is taken from the Wayback Machine's latest capture of its original URL, of 2004-06-18, pinned by its SHA-256 as the others are. `KSC5601.TXT` beside `KSX1001.TXT` is Unified Hangul, Microsoft's extension, and is not used. `tools/cover-tables` fetches each file once with curl into `$XDG_CACHE_HOME/vtium/cover-tables` and writes `src/cover.rs`, its SHA-256 in `src/cover.rs.sha256`, and `tools/cover-tables/provenance.tsv`, which pins each file by its URL, its own table version and date, its SHA-256 and its count of codepoints: `cargo run -p vtium-cover-tables -- generate` writes them, refusing a file whose SHA-256 moved unless given `--repin`, and `-- check` fails when the checked-in files differ from what the cached files generate. Nothing fetches at build or run time; the helper reads only the checked-in tables. A test pins each set's count, and another holds `src/cover.rs` to `src/cover.rs.sha256`, so a hand edit that keeps every count still fails.

A frit is meant to travel, so a source names a font each machine finds for itself. The `font:` form below is provisional: its syntax is the operator's to choose, and may be renamed before the first release (vtium/vtium#121).

```ini
source=font:Terminus 16      # a family, matched on the machine that draws it
style=regular
```

`font:FAMILY` matches as fontconfig matches a family, with case and blanks ignored. kbd console fonts match it first, by name: the font `setfont` would find by that name, else the first, in each data directory's sorted `consolefonts/`, whose name less its suffixes is the family. A PSF file outside kbd's directories carries no family in its header, so only `file:` names it. With no kbd font of that name, an installed outline font matches: a `.ttf`, `.otf`, `.ttc` or `.otc` file under the font directories (`/usr/share/fonts` and `/usr/local/share/fonts`, or each `--font-dir`) with a face whose name table gives that family, typographic (name ID 16) or legacy (name ID 1), with case, blanks, `-` and `_` ignored (ADR-1500 D8). So `font:JetBrains Mono` finds `JetBrainsMono-Regular.ttf`, and a variable font such as `JetBrainsMono[wght].ttf` too, whatever a distribution names the file. Reading a name table costs a file open, so the search takes two passes. It first takes the files whose name less its extension is the family, or the family and `Regular`, the plain name first, then the font directories in order, then by path, and keeps the first whose name table confirms the family, whatever the style of its face. Only when none does, it reads the name table of every other file in that same order, and takes the first with a face of the family whose subfamily is `Regular` with case ignored, its typographic subfamily (name ID 17) or else its subfamily (name ID 2), and else the first with any face of it. A family's name counts in every language the table holds. The search reads each file's table directory and `name` table alone, through `names::faces` and read-fonts, the table reader under swash, and opens at most `FAMILY_FILES_MAX` files; a search that would open more fails, naming the family and the cap, and names the file of another style it found when it found one. The engine chooses the face it draws with the same reader and the same test, `names::matches`, so it takes every face the search finds; in a collection it takes the family's first Regular face, and else its first face. `outline:PATH` names an outline file by its absolute path, and `bdf:PATH` a BDF font.

A source missing on this machine, or that cannot be read, is left out, and the next source in the frit's order gives its glyphs. A source that is on this machine and is refused, such as a BDF file the reader refuses, is also a warning naming the frit's line and why, which the helper sends the console to log; a missing source is left out quietly, since a frit names fonts a machine may not install. With every source left out, the frit fails, naming each source and why.

Each later source fills only the codepoints the earlier ones lack. A bitmap font is scaled by the largest whole factor at which its cell fits the cell asked for, centred across and placed on the cell's bottom row; one whose cell does not fit at factor 1 fills nothing. The cell holds a strike a pixel format: bitmap fonts give 1-bit glyphs, outline fonts R8 coverage and color glyphs premultiplied RGBA, each stored raw; the strikes' codepoints are apart.

## Outline fonts

The engine rasterises each outline font with swash at the cell asked for, so the console's grid never moves for a font, and places each glyph in its cell: the font is sized so its ascent and descent span the cell's height less half a pixel, as a FreeType cell request for that height does; the baseline sits the ascent, rounded up, below the top, raised by the whole pixels that the lowest ink of the font's printable ASCII, U+0021 to U+007E, as drawn at that cell, passes the cell's bottom edge, so the underscore and the descenders end in the cell's bottom rows (ADR-1302 D3); and the font that sets the cell sets its width by the W rule (ADR-1200 D17), the wider of `W`'s advance, rounded, and the columns its ink covers, then `M`'s or `0`'s for a font with no `W`, then half the cell's height for a font with none of them, so the cell's width never comes from the font's missing-glyph box. An `outline:` source that holds only bitmap strikes is sized the same way, at the height the console names, by its `W`'s advance, and its color strikes are scaled to the cell; the helper reads pixel fonts only from BDF and the kbd formats, never through swash (ADR-1200 D14). The ink is measured on the outline unhinted, whatever the frit's `hinting=` says. Light hinting moves only rows in a TrueType font, so the unhinted measure gives the columns the default hinting draws: DejaVu Sans Mono's `W` at 16 pixels covers 9 columns, where full hinting would snap it to 8. Glyphs are drawn hinted as the frit's `hinting=` says (ADR-1200 D1), and only the W measure that sets the cell is unhinted. With `light`, the default, the rasteriser fits each glyph to the pixel grid up and down only, as FreeType's light load (`FT_LOAD_TARGET_LIGHT`) does: it hints a TrueType font with skrifa's automatic hinter, which moves only rows, and a CFF font by its own hints through skrifa's CFF hinter, which move only rows too, the same choice FreeType makes for a light load. With `full`, the rasteriser runs a TrueType font's own instructions, or the automatic hinter at full strength for a TrueType font that has none, so a glyph can also move sideways onto whole columns. A CFF font's hints move rows only under either setting, as FreeType's CFF hinter's do, so `hinting=full` changes nothing for a CFF font: Nimbus Mono PS and Source Sans 3 draw byte for byte the same both ways. For DejaVu Sans Mono, JetBrains Mono and Liberation Mono at 12 to 32 pixels it draws every printable ASCII glyph as swash's own scaler hinted it before `hinting=` existed. swash's scaler hints in one fixed mode, so the rasteriser hints each outline itself with skrifa, the outline reader under swash, and fills it with zeno, swash's own rasteriser, as swash's scaler does. A glyph is placed by its font (ADR-1302 D2): its advance is rounded to the nearest pixel, and a negative advance counts as none; its pen starts at its cell's left edge, moved right by half of what its cells' width exceeds that advance, rounded down, which is a move left when the advance is wider; and its ink sits on the baseline at its bearing from the pen. A narrow glyph drawn in two cells, as a symbol widened by VS16, is centred across them by the same rule. An Arabic letter draws in its unjoined form, the form its codepoint, or its cluster with its marks, gives, unless a program writes Unicode's presentation forms itself, because choosing a joined form needs the letter's neighbours, which shaping across cells will bring. A letter of a joining script (ADR-1302 D2), any character `ArabicShaping.txt` gives the Joining_Type D, R, L or C, from Arabic and its tatweel to Syriac, N'Ko, Mongolian, Mandaic and Adlam, is stretched sideways before it is rasterised, by its cells' width over its advance as the font gives it, unrounded, its pen on its cell's left edge, so its advance fills its cells and its joining strokes meet the next letter's with no seam. A shaped cluster of one joining letter is stretched as one, the marks HarfRust placed on it and their offsets included, so each mark stays over its letter; the advance is what is stretched, so ink a font designed past its advance stays past it and reaches the neighbour by ADR-1302 D1. A cluster of more than one joining letter, as the lam-alef ligature that shaping across cells will bring, is not stretched and keeps its pen on the cell's left edge; the console asks for no such cluster today, since a grapheme cluster holds one letter. A joining form, a letter keyed with U+200D on the sides it joins, is kept when the glyphs the font draws its letter with, which may be several, as Noto Naskh Arabic draws beh as a body and a dot, all come from one character or one ligature and differ from what the cluster draws with nothing joined. Nothing moves a glyph to keep its ink inside its cells, and its pixels are cut at the cells' edges. A glyph whose ink passes its cells sideways also carries its ink box (ADR-1302 D1, D6): its ink kept up to one cell past its cells on each side and cut there, in the columns that span its cells and its ink, sent in the set's `INKX` beside its cut pixels. A glyph whose box would pass a set's 16 KiB chunk carries none and stays cut to its cells. Color glyphs fit their cells and carry no box.

A shaped cluster's marks are fitted to the row (ADR-1302 D3, the maintainer's decisions of 2026-11-01). A glyph counts as a mark by the character it was shaped from. vtium-config gives HarfRust each character of the cluster numbered by its place in the cluster, and HarfRust tags each glyph it returns with the number of the character it came from, so vtium-config looks that character up. The glyph is a mark when its character has the General_Category Mn or Me or a combining class other than 0 (`MARKS` in `src/shaping/data.rs`). HarfRust returns a right-to-left cluster in visual order, with the marks before their letter, and the lookup by character still finds them there. A mark above or below its base that the shaper leaves at the pen, with no advance and no offset, as HarfRust leaves an acute after a circumflex in DejaVu Sans Mono, is first placed by the helper itself: centred over its base's ink, a row above all the ink since the base, or directly under it. Its base is the letter before it in the order the text is written, as Unicode's combining character sequence and OpenType's mark-to-base attachment do, found on either side of it in a right-to-left cluster, and a letter the font draws as several glyphs, such as a body and its dot, is one base. The marks over the middle of the base letter's ink are one stack and those under it another. A stack whose ink passes the row's top or bottom edge moves toward the baseline until it fits, as long as the move lands no more of its ink on the letter's ink than lies there already and leaves the stack inside the row's other edge. When the move fails either test, the whole cluster, letter and marks together, is scaled vertically just enough to fit the row, keeping the font's arrangement; each row of the result is the average of the rows it covers. The letter's own ink need not reach the row's edge for that. In DejaVu Sans Mono, alef with hamza and damma and jeem with kasratan reach it, and lam with shadda and fatha at 16 pixels has blank rows above the lam but is scaled too, because its marks, moved down, would land on the lam's stem. Otherwise base letters never move, and a mark keeps the sideways place the shaper gave it, its ink reaching sideways as any ink does. A color cluster's glyphs are left as they are.

The helper finds each outline source's baseline at a cell's height once, from its whole printable ASCII set, keeps it for the engine's life, and hands it to every request it rasterises for that source and height, so glyphs sent for different requests, or again after an eviction, stand on one baseline whatever each request held. Each font in a strike stands on its own baseline in its glyphs' pixels; a font with no printable ASCII keeps its ascent rounded up. The strike reports the baseline of the frit's first source, the font that sets the cell, even after that source fails as it draws, so the answers at one cell never change mid-session, and its underline and strike-through follow that baseline: the underline's thickness and centre from the font's `post` table, else a fourteenth of the cell near its bottom, and the strike-through's top and thickness from the `OS/2` table's strikeout when its size is above 0, else as thick as the underline and centred on half the x-height, `OS/2`'s `sxHeight` or the `x` glyph's height, or half the baseline; each at least a row thick, at most a quarter of the cell, and inside it. A strike whose first source is a bitmap font reports the cell's bottom row and the lines of a face with no metrics of its own, as before.

The helper draws a glyph before the terminal asks for its width, so the glyph's own advance sets how many cells it takes, and vtium-font's `Font` fits it to the width the terminal gives (ADR-1300). A glyph advancing more than one and a half cells is two cells wide: CJK, emoji, and the wide icons of a Nerd Font that is not a Mono build. A color glyph, a COLR glyph's layers or a CBDT or sbix bitmap, is drawn unhinted, centred across its cells and kept inside the cell's height. COLR layers are laid over each other with the renderer's rounding, premultiplied, and a COLR glyph larger than its cells is drawn again at the size that fits them.

A color bitmap is taken from the font's largest strike holding it, its colors premultiplied by its alpha, and scaled by vtium-config itself to the cell's size, or as far under as fits its cells: Lanczos then a light sharpen (an unsharp mask of radius 0.8 at 120 per cent), the operator's choice on vtium/vtium#23 from a comparison of six ways (`vtium-review-images/23/emoji-scaling.png`). Box, plain Lanczos, box with alpha snapped at half and nearest stay in `src/resample.rs`, one chosen when the tool is built with `VTIUM_CONFIG_COLOR_SCALE=lanczos-sharpen|lanczos|box|box-snap|nearest`, the first the default. It is a build-time setting rather than Cargo features because the methods exclude each other and features add up across a workspace; an unknown value fails the build. Weights, sizes and placement are computed in f64 with IEEE basic operations alone and rounded to 14-bit integers, and pixels are integers, with no `sin`, `exp` or `powf` from the platform, so a glyph is the same bytes on every host.

The parser's answer, which the parent checks, gives, for each cell asked for, the cell, the baseline, every glyph's width, format, pixels and ink box and the map; every codepoint is one the request covers, every RGBA pixel premultiplied, no box larger than a set's chunk, and every box an R8 glyph's, past its cells and inside its reach.

## Sources

- **kbd names** resolve as `setfont` resolves them (kbd's `src/libkbdfile/kbdfile.c`, `src/libkfont/context.c`): in `consolefonts/` of each data directory in turn (`/usr/share/kbd`, `/usr/share`, `/usr/lib/kbd`, or `--kbd-dir`), the name followed by the first of `""`, `.psfu`, `.psf`, `.cp` and `.fnt` for which a file exists, plain before `.gz`, `.bz2`, `.xz` and `.zst`; a name with a `/` looks in the subdirectory its first component names, and an absolute path is taken as given, then with each suffix. Unimaps resolve the same way under `unimaps/` with `""`, `.uni` and `.sfm`. A font or unimap found by name is resolved through its links and read only if it stays under the `consolefonts/` or `unimaps/` of a data directory; a link out of them fails the source, and nothing is read from outside. The helper never looks for a relative name in the directory it runs from, as `setfont` does first, because the helper runs unattended and a file there would shadow the data directories. A `font:` family's scan fails past `FAMILY_ENTRIES_MAX` entries in one directory. An outline font is opened to read its family only if, its links resolved, it stays under the font directories; one named for the family that leaves them through a link fails the source.
- **A font's map** is the frit's `unimap=` when given, else the font's own table, else kbd's `def.uni`; a font with none is refused, naming `unimap=`. A named font takes `def.uni` too, where `setfont` loads it only for its default font and otherwise leaves the kernel's map in place, because the helper has no kernel map to inherit. A unimap entry for a glyph past the font's last glyph maps nothing.
- **vconsole** reads `FONT=` and `FONT_UNIMAP=` from vconsole.conf, with the kernel command line's `vconsole.font=` and `vconsole.font_unimap=` over them, as systemd-vconsole-setup reads them (`src/vconsole/vconsole-setup.c`). With no `FONT=`, systemd ran no `setfont` and the kernel kept its font, so the source is refused and names `console:VT`. `FONT_MAP=` maps the kernel's 8-bit translation and sets no glyph, so it is not read.
- **console:VT** takes the font the console read from its own VT at start, with `KD_FONT_OP_GET_TALL`, or `KD_FONT_OP_GET` on a kernel without it, and its map with `GIO_UNIMAP`, and handed the helper (ADR-1200 D8); the helper opens no VT.
- **CPI fonts** are the codepage files kbd ships (`.cp`), as `setfont` reads them: one screen codepage, its 28-byte entry header and its info header, then each font's height, width, aspect and glyph count and its glyphs. A CPI file holds a font of each of several heights, so its source takes `cp-size=` 8, 14 or 16, as `setfont` takes `-8`, `-14` or `-16`, and with none the source fails naming `cp-size=`; `cp-size=` on a source that reads as no CPI file fails that source. Its glyphs have no table, so they take `unimap=`, else `def.uni`.
- **BDF fonts** are read by vtium-config's own reader, never through swash (ADR-1200 D14): Adobe's BDF 2.1, plain or compressed, in the character set ISO10646-1, whose encodings are codepoints; any other character set fails the source. The registry and the encoding are the `CHARSET_REGISTRY` and `CHARSET_ENCODING` properties, and where a property is missing, the last two fields of the XLFD name on the `FONT` line, so Tiny5 Mono's BDF, which names `iso10646-1` only there, reads as published. A font that gives the registry `ISO10646` and no encoding at all reads too. Its cell is as wide as the advance most of its glyphs take, the narrower on a tie, so one stray glyph narrower than the rest leaves only itself out, and `FONT_ASCENT` and `FONT_DESCENT` high, else the bounding box's. A glyph advancing that width is one cell wide and one advancing twice it two; a glyph of another advance, or an encoding no Unicode scalar value, is left out, and a codepoint's first glyph is taken. A glyph of `ENCODING -1` has no place in the character set: it is read as any glyph, so a malformed one still refuses the font, then left out and not counted against `CHARS`, which some fonts, Tiny5 Mono's among them, count without such glyphs. Each glyph sits on the baseline at its `BBX` offsets and is cut at its cells' edges. A BDF font's bytes are read where the source is resolved and parsed in `Engine::load`, in the helper's own sandbox with the other fonts, since the glyph form the parser's child answers with holds no glyph two cells wide; `preview` (#120) has no sandboxed place to parse one yet.
- **Compression** is told by its magic, as kbd tells it, and decoded with its stream's own check value verified: gzip, bzip2, xz and zstd, each refused past `COMPRESSED_BYTES_MAX` before it is decoded and past `PSF_BYTES_MAX` once decoded.

## The parser

`src/child.rs` is the side of `vtium-config --parse` that reads the request; the parent's side, which starts it, lives in `tests/common/parser.rs`. The child runs for a font: an empty environment, `/` as its directory, a process group of its own, its three pipes and no other descriptor. Run as root, the parent starts it as `nobody` from `/etc/passwd`, its supplementary groups dropped, and refuses when there is no such account. The parent kills the parser through a pidfd past 60 s by the wall clock and reads its stderr on a thread of its own. Another thread reaps the parser as soon as it exits, even while a process it started still holds its pipes. Just before the reap, that thread kills the parser's process group, so nothing the parser started outlives it; the parser itself may start no process, so the group catches what a stand-in starts in the tests and anything that slips past that limit (vtium/vtium#163). The parser sets no-new-privileges, an address space of 512 MiB, 30 s of CPU, no file writes, no processes and no core, refuses to run as root, reads its request, parses, and answers with the glyph form, which the parent checks field by field against the PSF bounds before it trusts it. A parser that fails, faults, passes a limit or answers malformed fails that source. No command runs it since `create` went; only the tests start it. `preview`, `fonts`, `new` and the TUI hand fonts to the helper, `serve`, which sets the same limits on itself and refuses root, so no command needs the parser's child (ADR-1201 D3, D9). The helper takes its `PARSER_MEMORY`.

## The helper

`vtium-config serve` is the helper the console starts on its first need for a frit's glyphs (ADR-1301 D2). It first sheds every descriptor above standard error its starter left open, as a copy of a terminal a font could write to: it marks them close-on-exec and starts itself again once through `/proc/self/exe`, with `VTIUM_CONFIG_SERVE_SHED` set so it does so once, so it holds only its three pipes. It sets no-new-privileges, installs its socket filter, enters its landlock domain, starts the thread that reads its requests, then sets the parser's limits with 300 s of CPU over its life, and reads its ids from `/proc/self/status`. The socket filter and the landlock domain, which the maintainer decided on 2026-11-04 (ADR-1200 D15), come before any font is read and before the reader's thread starts, which inherits both. The landlock domain, through the Linux landlock maintainers' `landlock` crate 0.4.7, the version the image helper builds, refuses every right to write, create, remove, rename or truncate a file. Reads stay open, since a frit may name a font by an absolute path anywhere, and the pipes the helper already holds are not affected. What the domain refuses on the network depends on the kernel's landlock version: binding and connecting TCP sockets from version 4 (Linux 6.7), reaching an abstract Unix socket made outside the domain, and signalling a process outside it, from version 6, and connecting to a named Unix socket from version 9. It never refuses a UDP socket. The socket filter closes what landlock leaves open: a seccomp filter, built with `seccompiler` 0.5.0 the way the image helper builds its worker's filter, under which `socket`, `socketpair`, `io_uring_setup`, `io_uring_enter` and `io_uring_register` answer EPERM and every other call goes on, so the helper makes no new socket of any kind on any kernel; io_uring is refused whole because its socket operation, from Linux 5.19, makes a socket without calling `socket`. seccompiler builds no filter for 32-bit ARM, so the armv7 helper runs without one. On a kernel without landlock the helper runs without the domain, as it did before; any other failure to install the filter or enter the domain sends a failed frame. It refuses to run as root, when any of its real, effective, saved and filesystem uids is 0, and refuses to run with root's group, when any of those four gids is 0 or its supplementary groups include 0, since a saved id of 0 would let it take root's id back. It sends a failed frame naming why, and the console gives it up for the boot. The helper does not refuse supplementary groups in general: run by a user, as `preview` and `fonts` run it, it holds that user's groups, which give it nothing its starter lacks. The console checks the drop it makes itself. When the console runs as root and starts the helper as `nobody`, std drops the supplementary groups before it sets the uid, and goes on when the kernel refuses it that, so the console reads the helper's ids back from `/proc/<pid>/status` as soon as it runs, before it sends a request, and refuses a helper whose four uids or four gids are not `nobody`'s or that holds any supplementary group (`crates/vtium/src/helper.rs`, `Launcher::dropped`), so the console never sends a request to a helper whose drop to `nobody` did not take. Each request carries the frit's name and text, so a frit the console makes on the fly needs no file; the helper reads the frit's fonts itself, as the account the console started it as, parses bitmap fonts and rasterises outline ones in its own process, and draws at the cell each request names, the frit's, never another (#145): an outline font drawn at that cell, a bitmap font scaled by the largest whole factor that fits and placed on the cell's bottom row. A frit's `console:` source takes the kernel's font the console read at start and handed over. It takes four requests. The first is a cell query, which the console sends for a frit that states no `cell=` before its first frame and, for an outline frit, at each zoom, and which the helper answers at once (ADR-1200 D17). The frit's first source sets the cell. That is the first source in the frit's order that the helper can draw from: as for glyphs, the helper leaves out a source this machine does not have or cannot read, and a source that has failed as it drew, a source whose W rule fails included, and the next source sets the cell instead. ADR-1200 D17 says only that the first source sets the cell; which source counts as first is the helper's own behaviour. A bitmap first source answers its own cell, once every later bitmap source's cell fits in it, and the console takes that cell at whole multiples. An outline first source answers the cell the W rule gives it at the height the query names, which the console takes as it is; a query that names no height gets no cell for it. Later sources of either kind draw into that cell. The helper reads no `cell=` line to answer a query, since the console reads `cell=` itself and asks only where D17 has it ask. The console takes either answer to any query, its own cell (frame 6) or the W rule's (frame 10), whatever the frit's text names first: when an outline first source is missing on this machine, a bitmap source after it answers, and the reverse. The other three requests are an ask, answered whole ahead of anything else with the glyphs of the codepoints and the clusters it names, each cluster shaped with HarfRust from the first outline source in the frit's order that covers its first scalar value other than U+200D, and drawn whole into the frame's cluster map (ADR-1200 D21); a cluster no source shapes as its kind requires is left out, and the console draws it its own way; a fill, which draws a cell's coverage while nothing is asked, the codepoints it names first, then printable Latin and box drawing, then the rest, 1,024 codepoints a batch, skipping what the console holds and what it sent, a waiting request taken before each batch; and a stop, which ends a cell's fill. An ask names a style, regular, bold, italic or bold italic (ADR-1200 D21); a fill, a stop and the queries are regular, so the fill fills only the regular glyphs and the other styles come by ask, and a request of another kind that names a style is malformed. The style and the rows line spacing adds above and below the cell are fields of the request, so the request's magic is `VTVSREQ5`. A request of an earlier layout, `VTVSREQ4` or `VTVSREQ3`, is refused whole, with the reason that the console and the font helper come from different builds and that reinstalling vtium mends it; the console says the same when an older helper refuses its request. Each glyph frame, each fill's end and each stop taken names the band as well, so the console holds glyphs by the cell and its band (Line spacing, below). A fifth request, a sources query, is vtium-config's own and the console never sends it: the helper answers at once with each source of the frit it left out, `missing` when this machine does not have it and `refused` when it has it and cannot read it, with the source's line, spelling and why, which `fonts` lists. For a frit it draws nothing from, because the frit does not read or none of its sources is on this machine, it answers with a frame of its own, kind 12. The failed frame, kind 3, is the helper's own failure, which it also sends when it fails as it starts, so vtium-config never takes it as a frit's answer: every frit still unanswered is unknown, with the helper's reason. Glyphs go as vitrified sets of one cell, each strike in the style the request named. A styled ask's set holds only that style's strikes, which vtium-font's set format allows. Each warning a frit's text gives, such as `compress=`'s, is sent once as the helper first reads the frit, naming the frit and the line, and the console logs it. A source that fails as it draws is left out for the helper's life, and the next source in the frit's order gives its glyphs; a fill that never draws a glyph fails, naming each source whose cell does not fit or that failed. Each request is bounded before anything is allocated for it: the frit's name at 64 bytes and its text at `FRIT_BYTES_MAX`, the cell inside `CELL_SIDE_MAX`, the style one of four, the display's capabilities reserved and empty, 32,000 codepoints, each a scalar value, 32,000 clusters in an ask alone, each 1 to `CLUSTER_SCALARS_MAX` scalar values, 65,536 held ranges, and the kernel's font inside the kernel's own bounds. A frame's payload is at most 16 MiB, a batch past it cut in two. A glyph larger than a set's 16 KiB chunk, as each glyph of an 8x16 bitmap font drawn 33 times its size is, goes in a chunk of its own and is sent like any other (ADR-1302 D6). So that a batch of such glyphs never outgrows the helper's memory limit, the helper draws at most as many glyphs at once as a frame holds at their largest size: two cells of RGBA for a frit with an outline source, since it may draw in color, else two cells of 1-bit rows. A single glyph larger than a frame is left out, and the console draws that character in its built-in font. It exits after `HELPER_IDLE_MS`, 60,000 ms, with no request and no fill, or when the console closes its end and its work is done.

## Styles

A frit gives each source a style with `style=` (ADR-1200 D1). The helper draws a style's glyphs from the sources of that style and synthesises a style the frit gives no source for (ADR-1200 D21, ADR-1302 D4). `serve::steps` lists what each style is drawn from, in order, and each step draws only what the steps before it left:

| Asked | Drawn from, in order |
|---|---|
| regular | the regular sources |
| bold | the bold sources; then the regular sources emboldened |
| italic | the italic sources; then the regular sources slanted |
| bold italic | the bold-italic sources; then the regular sources emboldened and slanted |

Where the frit names a bold or an italic face but no bold-italic face, the helper draws bold italic from the regular glyph, emboldened and then slanted, and not from the bold or the italic face (the maintainer, 2026-11-04). The fill draws regular glyphs alone, and bold and italic come only when the console asks for them (the maintainer, 2026-11-04).

- **Synthetic italic of an outline glyph** slants the outline before it is rasterised: each point moves right by 0.2 of its height above the baseline, so ink above the baseline leans right and descenders lean left. It leans right in every script.
- **Synthetic bold of an outline glyph** grows each contour sideways by a 48th of the size in pixels to the em on each side, a 24th in all, as FreeType's `FT_GlyphSlot_Embolden` grew a glyph, and by half a pixel a side at least, so a whole pixel in all at small sizes (the maintainer, 2026-11-04), but only from side to side: each point moves along the mitre of its two edges' outward normals, sideways only, and a point where its edges fold back by more than 160 degrees stays put. No ink rises above the font's tallest or falls below its lowest, so the row's baseline and lines hold for every style. ADR-1302 D4 leaves how a glyph is emboldened to the helper; vertical growth was left out because it would push ink across the row's edges, which D3 cuts.
- **A bitmap glyph** is widened for bold, a pixel set when it or its left neighbour is, inside the glyph's width, and then sheared for italic at its font's own size, before the whole-factor scale, by vtium-font's rule (`vtium_font::italic`), so the console's own bitmap faces and the helper draw the same glyph. A bitmap font is sheared about the baseline it states, a built-in set's strike's or a BDF font's ascent, else about the row under the lowest ink of its `H`, else its cell's bottom edge.
- **Bold italic** widens first and then slants or shears the widened glyph (ADR-1302 D4).
- A slanted, emboldened or sheared glyph keeps its advance and its cells, and the ink it puts past its cells goes to its ink box (ADR-1302 D6), unless that box's 1-bit rows would pass a set's chunk, 16 KiB, when the glyph is sent with no box, cut to its cells. A color glyph is drawn as it is.
- The baseline, the underline and the strike-through of every style's strike are the frit's first regular source's, so a styled glyph stands on the regular glyphs' baseline. A bitmap first source's strike states the baseline it is sheared about, as its glyphs sit scaled on the cell's bottom row, so vtium-font's set reader, which shears a regular 1-bit strike drawn for italic, leans its glyphs as the helper does; its underline and strike-through stay those of a face with no metrics of its own.
- The W rule's cell takes the frit's bold face too: the first outline source given `style=bold`, the wider of its `W` and the regular face's (ADR-1200 D17). The frit's first regular source sets the cell.

## Line spacing

Each ask and fill names the rows that line spacing adds to its cell above and below the text band (ADR-1302 D13). The helper draws each glyph in the text band, the cell less those rows, exactly as it draws one with no spacing, and then places it in the whole cell by the `fit=` of the set that gives it, or the character's default. A `fill` glyph stretches to the whole cell: a bitmap glyph repeats its top row upward and its bottom row downward, and an outline glyph's coverage is scaled vertically, each new row the weighted average of the rows it covers. A `natural` or `room` glyph keeps its rows, with blank rows above and below, so its ink stays cut at the text band, as ADR-1302 D3 cuts it at the row. A color glyph always keeps its size, whatever `fit=` says. A glyph's ink box is placed the same way, and is left out where it would then pass a set's chunk. The strike's baseline, underline and strike-through move down by the rows added above. A cluster takes the fit of its first character other than U+200D.

## What this slice leaves for later

- The density is the first measured display's, since the TUI cannot tell which display shows the terminal it runs in; it reads the EDID's size in whole centimetres, where the console reads the connector's millimetres, so the two can differ by a dot per inch or two. vtium-platform's EDID reader is private to it; once vtium-platform makes it public, `src/display.rs` takes it in place of its own.
- A session's end returning its console to the configured font (ADR-1201 D11) is the console's, in crates/vtium.
- `fit=room` (ADR-1302 D13) draws as `natural` until it is built. The helper keeps the letter at its size in the text band, and moves or scales its marks into the text band as ADR-1302 D3 says, so no mark reaches into the added rows. Letting the marks use the added rows comes with the Arabic work, in `src/shaping/`.
- vtium.conf's `font-hinting`, and a look's, over the frit's `hinting=` (ADR-1200 D1): the helper hints as the frit says, since no request carries the console's setting yet.
- ADR-1300's subpixel strikes, and shaping across cells (ligatures, Arabic joining forms, syllabic scripts): the helper shapes the clusters the terminal segments, one at a time (#144).
- COLR version 1 glyphs, such as `Noto-COLRv1.ttf`'s, are not drawn in color: swash reads version 0. A COLR layer in the text's color takes swash's mid gray, since a set cannot know the text's color.
- The parser's account is `nobody`; ADR-1400's pre-login account takes its place once vtium/vtium#31 names it.
- A root run is unverified on the maintainer's machine: the drop to `nobody`, `nobody` executing the binary from its install path, and the real `console:VT` ioctls. Tier 3's guest is where they run.

## Bounds

A frit and every source file are opened once, never blocking on a FIFO, refused unless that descriptor is a regular file, and read no further than their bound.

| Bound | Value | Past it |
|---|---|---|
| `FRIT_BYTES_MAX` | 64 KiB | The frit is refused |
| `FRIT_LINE_MAX` | 4096 bytes | The frit is refused, naming the line |
| `FRIT_SOURCES_MAX` | 16 | The frit is refused, naming the line |
| `UNIMAP_ENTRIES_MAX` | 65535, kbd's count | The unimap is refused |
