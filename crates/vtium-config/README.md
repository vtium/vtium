# vtium-config

The font and settings tool of ADR-1201, which users reach as `vtium config`, and the program that generates vtium's glyphs at run time (ADR-1200, ADR-1301 D2), its own binary outside the minspec build. With no command at a terminal it opens its TUI, a full-screen program drawn in the terminal's text cells, which lists the frits (font set files) and the built-in fonts, switches the live console to each font the user highlights, previews sizes as pictures, and saves what the user keeps into vtium.conf and the head file through `apply`. Its `serve` command is the helper the console starts: it takes a frit's text from the console, finds and reads the frit's sources, parses each bitmap font and rasterises each outline font, and sends the glyphs at the cell asked for in the glyph chunk format, written with vtium-font's writer. Its `set` command switches the running console's frit. Every decoder lives here; the console reads only the helper's glyphs and its own built-in fonts. The crate forbids unsafe code; the console font ioctls it needs live in vtium-platform's `src/vt/font.rs`.

## Commands

| Command | Runs as | Does |
|---|---|---|
| none, at a terminal | the user | Opens the TUI ([The TUI](#the-tui)). With no command and stdin or stdout not a terminal, it says that no command was given and exits 2. |
| `fonts` | any user | Lists the frits and the built-in fonts, one line each, tab-separated: the name; its state, `reads`, `built in`, `does not read:` and why, or `draws nothing:` and why when no source of it is on this machine; and the sources this machine lacks, each as the frit spells it, one it has but refuses marked `(refused)`. The glyph helper finds the sources under its own sandbox, one helper answering a sources query for every frit, each answer waited for at most `HELPER_WAIT`, 5 s, so this process parses no font (ADR-1201 D3). When the helper does not start, fails or stalls, the answers that came are kept and each frit still unanswered prints `reads` and `unknown:` with why, never `draws nothing`. |
| `check FILE` | any user | A file named `*.vtfrit` is read strictly by the helper's frit reader, which prints each warning and `ok FILE`, or fails naming the line. Any other file is checked as vtium.conf by the console's own `vtium check-config`, on a copy in a directory of the tool's own under the temporary directory, each problem printed with FILE's own name and line. Writes nothing. |
| `config KEY` | any user | Prints the key, its value and where it comes from, `vtium.conf` or `default`, tab-separated. The key must be one vtium.conf takes, by the console's key table in vtium-settings. |
| `config KEY VALUE`, `config --unset KEY` | the user; root to install | Sets the key, or comments out every line that sets it, one change to vtium.conf made line by line ([Saving](#saving)). A switch takes `on` or `off`, and a key of a fixed set of words one of them; any other value is judged by the console's own check when it is installed. |
| `new FONT...` | the user; root to install | Makes a frit of the fonts, in order, each a source as a frit spells it (`kbd:ter-v16n`, `builtin:unifont`) or else a family, `font:FAMILY`. `--name NAME` names it, else a name made from the first font, lowercase words joined by `-`; `--cell WxH` and `--size POINTS` write `cell=` and `size=`. The frit reader checks it before anything is drafted. |
| `new --from FILE`, `new --template` | the user; root to install | `--from` installs the frit in FILE, named by `--name`, else its `name=`, else FILE's name less `.vtfrit`. `--template` prints a frit with each key explained, to edit for `--from`, and writes nothing. `new` alone at a terminal opens the TUI at its new-frit view, and away from one is a usage error. |
| `preview FONT... [--size POINTS]` | any user | Draws each font's specimen with the glyph helper under its own sandbox, as the TUI draws a size's picture (ADR-1201 D9). A FONT is a frit's name, a built-in font's, or a source as `new` takes it. The size is `--size`, else vtium.conf's `font-size` where it is set and not 0, else 12 points, at the density the TUI uses. Each font prints one line, tab-separated: its name, its size, its cell, and how many of the specimen's characters it draws itself. Where standard output is a terminal that answers kitty's graphics query before DA1, asked on `/dev/tty` in raw mode within a second, the line is followed by the specimen as kitty graphics' raw pixels, one image id a font and with the cursor moved past it; a font that does not draw prints `failed`, its name and why, and the command exits 1. Writes nothing else. |
| `remove-frit NAME` | the user; root to install | Removes the frit `NAME.vtfrit`, refusing a built-in font, a name with no frit, the frit vtium.conf's `font-name` names, and a frit a head's `profile =` line names in `heads.conf`, since a head draws the frit of its profile's name; `apply` refuses the same removals in any draft; `apply` keeps the removed frit as `NAME.vtfrit.bak`. |
| `set NAME` | the session's user | Switches the running console to a frit or a built-in font (ADR-1200 D5). NAME is checked first as the console checks it, `unifont`, `unscii-8`, or a frit's name whose `NAME.vtfrit` is a regular file in the frits' directory, and the command fails naming that file when it is neither. It then asks the terminal what it is with XTVERSION and DA1, and sends nothing more to a terminal that does not name vtium. To vtium it writes `OSC 50 ; NAME ST` and the query `OSC 50 ; ? ST` to `/dev/tty`, reads the reply in raw mode for at most a second, and puts the terminal's mode back, dropping input left unread first; SIGTERM, SIGHUP, SIGINT and SIGQUIT are held while the terminal is raw and act once its mode is back. It prints `set NAME` when the reply names NAME, else `failed`, the name, and why: the font the console kept, no reply because the console's `allow-font-ops` is off, or a terminal that is not vtium. |
| `apply DIR` | root, through `sudo` | Checks the draft in DIR and installs it ([Saving](#saving)). |
| `serve` | the account ADR-1200 D15 names | The helper ([The helper](#the-helper)). The console starts it; it takes no argument. |

Each command but the TUI prints one line a result, tab-separated, and exits 0 on success, 1 on a failure and 2 on a usage error. Run as a user, a command that changes something writes a draft under `$XDG_STATE_HOME/vtium/drafts` and prints `write PATH` or `remove PATH` for each file the draft holds, then `draft DIR` and `run COMMAND`, the command that installs it, `sudo /usr/bin/vtium-config apply DIR` for the system's directories; a change that changes nothing prints `unchanged` and drafts nothing. Run as root, it installs at once: it writes the draft into a directory of root's own under `/tmp` and applies it, printing `apply`'s lines. After the command word, an option the tool does not take for itself is the command's own, as `new --name`. The store's commands, `create`, `install`, `list`, `verify` and `remove`, are gone with the store (ADR-1200 D3, D12, retired), and each is an unknown command.

The frits are in the directory the console reads them from: the directory vtium.conf's `font-frits` names, and where it names none `/etc/vtium/fonts`, which `VTIUM_FONT_FRITS` changes at build time. vtium-config reads `font-frits` from the vtium.conf in its configuration directory, so `fonts`, `new`, `remove-frit`, `set`, `preview`, the TUI and `apply` all list, write and remove frits where the console reads them. `--frits DIR` names another directory in place of it; `--configdir DIR` names another directory than `/etc/vtium` for vtium.conf and `heads.conf`; `--sudo PROGRAM` replaces `sudo` in the TUI's privileged step; `--vtium PROGRAM` names the console binary `apply` checks files with, `/usr/bin/vtium` unless `VTIUM_PROGRAM` set another at build time; none of these is taken as root ([Saving](#saving)); and `--kbd-dir DIR` (repeatable), `--font-dir DIR` (repeatable), `--vconsole-conf FILE` and `--kernel-cmdline FILE` replace the paths `serve` finds sources in, `--sys DIR` replaces `/sys`, where the TUI and `preview` measure the displays, and `--helper PROGRAM` replaces the glyph helper the tool starts, this binary's `serve`, as a test's stand-in does.

When stdin and stdout are both terminals, the tool opens with a banner of its name in glass (`src/banner.rs`, vtium/vtium#112). `--no-banner` or a non-empty `NO_COLOR` turns it off, and it never precedes `--version`, never shows in a Chinese, Japanese or Korean locale, and never reaches a pipe.

## The TUI

At start the TUI writes four requests at once, XTVERSION, the OSC 50 query, kitty's graphics query and DA1, and waits at most a second for DA1's reply, which every terminal of the VT100 line sends after the others. In a vtium console that answers the OSC 50 query, each font the user highlights is sent as `OSC 50 ; NAME ST` and the query, one switch at a time: the next goes when the last one's reply comes, and names whatever is highlighted then. A reply that names another font marks the font as kept by the console. With `allow-font-ops` off the TUI says so and offers to turn it on as a saved change; in any other terminal it sends no OSC 50 but the query at start. Leaving by `q`, by Ctrl-C, or by SIGINT, SIGTERM, SIGQUIT or SIGHUP switches the console back to the font the start query named and waits for the reply; a panic writes the switch back from the panic hook, since a release build aborts on a panic. Nothing can give the font back after SIGKILL or once the terminal is gone.

Its views are the fonts, the sizes, the settings, each head's profile from `heads.conf`, the new-frit view, and the save view, which lists each file a save changes and each line that changes, and the command it runs. The settings view lists every key vtium.conf takes, from the console's own key table in vtium-settings, the font keys first (`font-name`, `font-size`, `font-frits`, `font-hinting`, `font-line-spacing`, `allow-font-ops`, `display-dpi` and the sprite policy's `glyph-source` keys) and the rest in the table's order, each with its value or its default, and under the list what the highlighted key does. Enter turns a switch on or off, steps a key of a fixed set of words to its next word, and starts typing any other key's value, which a second Enter keeps as a change the save makes; an empty value leaves the key at its default, and moving away drops what was typed. The new-frit view is `new`'s guided flow (ADR-1201 D9): the user types the frit's name, up to three sources, a cell and a size, Enter moving to the next field, and Enter on its last row adds the frit to the save once the frit reader takes it, and shows the save view. A frit of an installed frit's name replaces it, the save view showing the text it replaces as the TUI read it at start; an installed frit that is not UTF-8 text is not replaced, and the view says to remove it first. While a field or a value is typed, every character is text, `q` and `s` included, and Ctrl-C still leaves. Where the terminal answered kitty's graphics query and the console cannot be switched live, because `allow-font-ops` is off or the terminal is not vtium, the fonts view shows the highlighted font's specimen as a picture below the list, at the size a save names, else vtium.conf's `font-size`, else 12 points, and deletes it as the highlight moves; a frit that does not read gets none. Where the terminal answered kitty's graphics query, each size shows a specimen picture at the pixel height that size gives at the density ADR-1200 D17 orders: vtium.conf's `display-dpi`; else the density down the screen of the first connected display, in the order of its connector's name, whose EDID states its size (`src/display.rs`, which reads each connector's `status`, its first mode and its EDID's base block from sysfs and opens no card); else 96 dots per inch. The TUI says which it used. The specimen is three lines of Latin, digits and box drawing, and a fourth in the locale's letters where `LC_ALL`, else `LC_CTYPE`, else `LANG` names a language whose script takes a cell a character: Cyrillic, Greek, Japanese, Chinese, Korean, and the accented Latin of German, French, Spanish, Portuguese, Polish, Czech and Slovak, Turkish and Vietnamese. A script whose letters join or stack, as Arabic, Hebrew's points, Thai or Devanagari, has no line until the specimen shapes clusters; a CJK character takes two cells, as the console draws it. Where the terminal draws no pictures, a size shows a sentence instead: the cell it gives, the grid that cell gives on that first display, and how many of the specimen's characters the font draws itself. Once the terminal is known, the TUI asks one helper which sources each frit that reads lacks, through the sources query `fonts` uses, on a thread of its own whose answer wakes the loop, so the TUI goes on reading keys, Ctrl-C included, while the helper works, and the font list notes a frit lacking some, as `reads, 1 source missing`, or none of whose sources is on this machine. A frit the helper gives no answer for in its wait, as when it stalls, keeps the answers that came for the others and is noted `reads, sources not checked`. The helper draws the glyphs under its own sandbox ([The helper](#the-helper)), so the TUI's process parses no font, and the picture goes as kitty graphics' raw pixels, `a=T,f=32,t=d`, in chunks, and is deleted with `a=d` when the highlight moves or the TUI leaves. Every view fits a grid of 40 columns by 25 rows, the TUI's floor (`MIN_COLS` and `MIN_ROWS` in `src/tui/view.rs`), which holds the VGA console's 80x25 and the 320x240 panel's 40 by 30. Its sentences and keys wrap by words, and every view shows its title, tabs, message and keys whole. A grid narrower than 40 columns or shorter than 25 rows, as a large previewed font can leave, shows one line naming the font and the keys that keep it or go back. The words the TUI shows are in `src/tui/words.rs`.

## Saving

A save becomes a draft, a directory the user owns under `$XDG_STATE_HOME/vtium/drafts`, which holds the whole edited vtium.conf and `heads.conf` and a `MANIFEST` that names each file with the SHA-256 of the installed file it replaces. When the TUI's directories are the system's, it writes the draft and runs exactly one command, built as an argv and never as a shell string: `sudo /usr/bin/vtium-config apply DRAFT`, with no option, so a sudo rule can name it whole. It leaves its alternate screen while sudo asks for the password, runs the command in a process group of its own in the terminal's foreground so that Ctrl-C reaches sudo and not the TUI, through `--run-with-signals`, which releases the signals the TUI holds in the child alone, and shows what the command printed when it fails. The TUI runs as the user from start to end (ADR-1201 D5): run as root, it does not open, and says to run `vtium config` as yourself, since it asks for sudo when it saves. When `--configdir`, `--frits` or `--vtium` name anything but the system's directories and console, as the tests do, the TUI offers no privilege at all: it runs `vtium-config` with those options and `apply DRAFT` as the user, and the save view says so.

**Which tools can run apply.** Run as root, apply takes the user a draft belongs to from `SUDO_UID`, which sudo sets, `PKEXEC_UID`, which pkexec sets, or `DOAS_USER`, the user's name, which doas sets and apply looks up in the user database. So `sudo`, `pkexec` and `doas` each work as `--sudo PROGRAM`, and a tool that sets none of them can install only a draft root owns. Each tool sets only its own variable, so when more than one is set, one was kept from the user's environment or forged, and apply refuses the draft with exit 1 and says so. doas with `permit keepenv`, for example, keeps a `SUDO_UID` the user set, which would otherwise name another user's draft. Each variable is still only as trustworthy as the tool that sets it: a tool that lets the user set its own variable can make apply read a draft of any user it names.

**What `sudo vtium-config apply` can change.** Run as root, vtium-config refuses every option that names a path or a program, `--configdir`, `--frits`, `--sudo`, `--vtium`, `--kbd-dir`, `--font-dir`, `--vconsole-conf` and `--kernel-cmdline`, and refuses `--run-with-signals`, each with exit 2 and the reason. It also refuses, with exit 2 and the words to run it as yourself, the commands that run as the user: `check` and `new --from`, which read a file the user names and would otherwise read any file and could print what is in it, and `fonts` and `preview`, which start the glyph helper, which refuses root. `config`, `new FONT...` and `remove-frit` run as root, since they write only text they build themselves, through `apply`'s steps. So `sudo vtium-config apply DRAFT` writes only `/etc/vtium/vtium.conf`, `/etc/vtium/heads.conf` and frits in the frits' directory that `/etc/vtium/vtium.conf`'s `font-frits` names, else the one the build names, each only after the frit reader or the console's own `vtium check-config` has accepted it, and runs no program but the console the build names, `/usr/bin/vtium` unless `VTIUM_PROGRAM` set another.

vtium.conf is edited line by line by vtium-settings's `edit_conf`, which reads each line with `split_line`, the console's own reading, and a head's `profile =` line by `set_profile`, the head file's one writer, so every comment, blank line and line ending stays.

`apply DRAFT`:

1. reads the draft without following a link, takes only regular files with names it knows and no second name (a hard link), owned like the draft's directory by root or by the user the privileged tool ran it for, and bounds each, since root is reading a directory the user owns; and since root read those files for the user, what it says of them names a file, a line and a key, and quotes nothing they hold;
2. refuses the draft, writing nothing, when a file it replaces has changed since the draft was made, naming the file;
3. checks every file before it writes any: each frit with the helper's frit reader, and vtium.conf and the head file with the console's own `vtium check-config`, run on root's copies of exactly the bytes it then writes, made in a new directory of its own under `/tmp`, whatever `TMPDIR` says, with a random name and mode 0700, each copy created through the directory's descriptor without following a link;
4. writes the frits, then the head file, then vtium.conf, each through vtium-settings's `install_file`: a new file beside the old one, mode 0644, flushed and renamed over it, the old one kept as `NAME.bak`;
5. prints one line a file, `wrote PATH`, `failed PATH` with the reason, or `not written PATH` after a failure, and exits 0 when it wrote them all. The draft stays, so it can be applied again.

## Frits

One `key=value` a line, blanks around key and value dropped, `#` to the line's end a comment, as vtium.conf reads; unlike vtium.conf, an unknown key, a malformed line, a value with a control character or a key this build does not build yet refuses the whole frit, naming the file and line. This slice reads ADR-1200 D1's keys and ADR-1301 D4's `antialias=`: `name=`, `source=` (`font:`, `kbd:`, `file:`, `bdf:`, `outline:`, `vconsole`, `console:VT`, `builtin:`), `unimap=`, `cover=` (`ascii`, `latin-1`, `gb2312`, `gbk`, `big5`, `jis-x-0208`, `ks-x-1001`, `U+XXXX` and `U+XXXX-U+YYYY`), `cp-size=`, `style=regular`, `cell=`, `size=`, `glyph-source=` and `glyph-source-<range>=`, `antialias=`, `hinting=` and `license=`. The store's `package=` and `sha256=` are unknown keys. `compress=`, which chose how a stored set was compressed, is accepted with one warning naming the file and line, since refusing it would leave the console on the built-in font for a key that never changed what was drawn.

`cell=WIDTHxHEIGHT`, each side 6 to 96 pixels, states the cell the console draws the frit in and the helper generates for (#145); the console reads it as text before its first frame. `size=`, once, 6 to 96, is an outline frit's starting size in points, from which a zoom steps; the console reads it, converting it at the display's density (`crates/vtium/README.md`), and the helper draws at the cell each request names. `glyph-source=` and `glyph-source-box=`, `-block=`, `-braille=`, `-sextants=`, `-octants=` and `-legacy=` take `font`, `sprites` or `auto`, the configuration's names and values, each once; the console reads them as the frit's sprite policy, its configuration's keys over them. `antialias=` is `auto` or `no`; the engine reads it once ADR-1301 D6's grid is built. `hinting=`, once, is `light`, the default, which fits outline glyphs to the pixel grid up and down only, or `full`, which also fits them sideways ([Outline fonts](#outline-fonts) says how).

A source's `cover=` lines are one union, sorted and merged. `ascii` is U+0020 to U+007E and `latin-1` adds U+00A0 to U+00FF. Each named set is the codepoints a Unicode mapping file maps to. `gb2312`, `big5`, `jis-x-0208` and `ks-x-1001` come from the standards' own tables, with no vendor's extension; `gbk` comes from Microsoft's code page 936, whose table also maps U+0000 to U+007F and, at 0x80, U+20AC. The files: `gb2312` from `OBSOLETE/EASTASIA/GB/GB2312.TXT` (7,445 codepoints), `gbk` from `VENDORS/MICSFT/WINDOWS/CP936.TXT` (21,920), `big5` from `OBSOLETE/EASTASIA/OTHER/BIG5.TXT` (13,704), `jis-x-0208` from `OBSOLETE/EASTASIA/JIS/JIS0208.TXT` (6,879) and `ks-x-1001` from `OBSOLETE/EASTASIA/KSC/KSX1001.TXT` (8,224), under unicode.org's `Public/MAPPINGS/`. unicode.org no longer serves `GB2312.TXT`, so it is taken from the Wayback Machine's latest capture of its original URL, of 2004-06-18, pinned by its SHA-256 as the others are. `KSC5601.TXT` beside `KSX1001.TXT` is Unified Hangul, Microsoft's extension, and is not used. `tools/cover-tables` fetches each file once with curl into `$XDG_CACHE_HOME/vtium/cover-tables` and writes `src/cover.rs`, its SHA-256 in `src/cover.rs.sha256`, and `tools/cover-tables/provenance.tsv`, which pins each file by its URL, its own table version and date, its SHA-256 and its count of codepoints: `cargo run -p vtium-cover-tables -- generate` writes them, refusing a file whose SHA-256 moved unless given `--repin`, and `-- check` fails when the checked-in files differ from what the cached files generate. Nothing fetches at build or run time; the helper reads only the checked-in tables. A test pins each set's count, and another holds `src/cover.rs` to `src/cover.rs.sha256`, so a hand edit that keeps every count still fails.

A frit is meant to travel, so a source names a font each machine finds for itself. The `font:` form below is provisional: its syntax is the operator's to choose, and may be renamed before the first release (vtium/vtium#121).

```ini
source=font:Terminus 16      # a family, matched on the machine that draws it
style=regular
```

`font:FAMILY` matches as fontconfig matches a family, with case and blanks ignored. kbd console fonts match it first, by name: the font `setfont` would find by that name, else the first, in each data directory's sorted `consolefonts/`, whose name less its suffixes is the family. A PSF file outside kbd's directories carries no family in its header, so only `file:` names it. With no kbd font of that name, an installed outline font matches: a `.ttf`, `.otf`, `.ttc` or `.otc` file whose name less its extension is the family, or the family and `Regular`, with case, blanks, `-` and `_` ignored, so `font:JetBrains Mono` finds `JetBrainsMono-Regular.ttf`; the plain name first, then the font directories in order (`/usr/share/fonts` and `/usr/local/share/fonts`, or each `--font-dir`), then by path. The engine checks that the file's name table gives that family, typographic or legacy, and in a collection takes the first face of it. `outline:PATH` names an outline file by its absolute path, and `bdf:PATH` a BDF font.

A source missing on this machine, or that cannot be read, is left out, and the next source in the frit's order gives its glyphs. A source that is on this machine and is refused, such as a BDF file the reader refuses, is also a warning naming the frit's line and why, which the helper sends the console to log; a missing source is left out quietly, since a frit names fonts a machine may not install. With every source left out, the frit fails, naming each source and why.

Each later source fills only the codepoints the earlier ones lack. A bitmap font is scaled by the largest whole factor at which its cell fits the cell asked for, centred across and placed on the cell's bottom row; one whose cell does not fit at factor 1 fills nothing. The cell holds a strike a pixel format: bitmap fonts give 1-bit glyphs, outline fonts R8 coverage and color glyphs premultiplied RGBA, each stored raw; the strikes' codepoints are apart.

## Outline fonts

The engine rasterises each outline font with swash at the cell asked for, and places each glyph in its cell as the C reference's FreeType backend did (`kmscon/src/font/font_freetype.c:130-189,400-470` at `b1f7a7c5`): the font is sized so its ascent and descent span the cell's height less half a pixel, as a FreeType cell request for that height did; the baseline sits the ascent, rounded up, below the top, raised by the whole pixels that the lowest ink of the font's printable ASCII, U+0021 to U+007E, as drawn at that cell, passes the cell's bottom edge, so the underscore and the descenders end in the cell's bottom rows (ADR-1302 D3); and the font that sets the cell sets its width by the W rule (ADR-1200 D17), the wider of `W`'s advance, rounded, and the columns its ink covers, then `M`'s or `0`'s for a font with no `W`. The ink is measured on the outline unhinted, whatever the frit's `hinting=` says, because the C reference loaded glyphs with FreeType's light hinting, which in a TrueType font moves only rows, so DejaVu Sans Mono's `W` at 16 pixels covers 9 columns (`font_get_width`); full hinting would snap it to 8. Glyphs are drawn hinted as the frit's `hinting=` says (ADR-1200 D1), and only the W measure that sets the cell is unhinted. With `light`, the default, the rasteriser fits each glyph to the pixel grid up and down only, as the C reference's `FT_LOAD_TARGET_LIGHT` load did (`kmscon/src/font/font_freetype.c:119`): FreeType gave a light load of a TrueType font to its automatic hinter, which moves only rows, and kept a CFF font's own hints, which move only rows too, and the rasteriser chooses skrifa's automatic hinter and its CFF hinter the same way. On DejaVu Sans Mono at 16 pixels, regular and bold, the light-hinted glyphs come close to the C reference's tier 2 goldens `ascii` and `bold` (kmscon `b1f7a7c5`). Of the 231 cells with ink in those screens' DejaVu text, `ascii`'s and the bold words of `bold`'s first three lines, 79 are identical and 121 are within 2 levels of 255 at every pixel, and no pixel differs by more than 15 levels. That was measured on 2026-11-01 with `rasterise` at a 9x16 cell with the baseline forced to row 13, the C reference's, since at 16 pixels the light-hinted underscore raises vtium's baseline to row 12 (below): each pixel's R8 coverage, scaled by 229/255 to the goldens' gray text and rounded, against the golden's pixel. With `full`, the rasteriser runs a TrueType font's own instructions, or the automatic hinter at full strength for a TrueType font that has none, so a glyph can also move sideways onto whole columns. A CFF font's hints move rows only under either setting, as FreeType's CFF hinter did, so `hinting=full` changes nothing for a CFF font: Nimbus Mono PS and Source Sans 3 draw byte for byte the same both ways. For DejaVu Sans Mono, JetBrains Mono and Liberation Mono at 12 to 32 pixels it draws every printable ASCII glyph as swash's own scaler hinted it before `hinting=` existed. swash's scaler hints in one fixed mode, so the rasteriser hints each outline itself with skrifa, the outline reader under swash, and fills it with zeno, swash's own rasteriser, as swash's scaler does. A glyph is placed by its font (ADR-1302 D2): its advance is rounded to the nearest pixel, as the C reference's `centre_dx` rounded it; its pen starts at its cell's left edge, moved right by half of what its cells' width exceeds that advance, rounded down, which is a move left when the advance is wider; and its ink sits on the baseline at its bearing from the pen. A narrow glyph drawn in two cells, as a symbol widened by VS16, is centred across them by the same rule. A letter of a joining script (ADR-1302 D2), any character `ArabicShaping.txt` gives the Joining_Type D, R, L or C, from Arabic and its tatweel to Syriac, N'Ko, Mongolian, Mandaic and Adlam, is stretched sideways before it is rasterised, by its cells' width over its advance as the font gives it, unrounded, its pen on its cell's left edge, so its advance fills its cells and its joining strokes meet the next letter's with no seam. A shaped cluster of one joining letter is stretched as one, the marks HarfRust placed on it and their offsets included, so each mark stays over its letter; the advance is what is stretched, so ink a font designed past its advance stays past it and reaches the neighbour by ADR-1302 D1. A cluster of more than one joining letter, as the lam-alef ligature that shaping across cells will bring, is not stretched and keeps its pen on the cell's left edge; the console asks for no such cluster today, since a grapheme cluster holds one letter. A joining form, a letter keyed with U+200D on the sides it joins, is kept when the glyphs the font draws its letter with, which may be several, as Noto Naskh Arabic draws beh as a body and a dot, all come from one character or one ligature and differ from what the cluster draws with nothing joined. Nothing moves a glyph to keep its ink inside its cells, and its pixels are cut at the cells' edges. A glyph whose ink passes its cells sideways also carries its ink box (ADR-1302 D1, D6): its ink kept up to one cell past its cells on each side and cut there, in the columns that span its cells and its ink, sent in the set's `INKX` beside its cut pixels. A glyph whose box would pass a set's 16 KiB chunk carries none and stays cut to its cells. Color glyphs fit their cells and carry no box.

A shaped cluster's marks are fitted to the row (ADR-1302 D3, the maintainer's decisions of 2026-11-01). A glyph counts as a mark by the character it was shaped from. vtium-config gives HarfRust each character of the cluster numbered by its place in the cluster, and HarfRust tags each glyph it returns with the number of the character it came from, so vtium-config looks that character up. The glyph is a mark when its character has the General_Category Mn or Me or a combining class other than 0 (`MARKS` in `src/shaping/data.rs`). HarfRust returns a right-to-left cluster in visual order, with the marks before their letter, and the lookup by character still finds them there. A mark above or below its base that the shaper leaves at the pen, with no advance and no offset, as HarfRust leaves an acute after a circumflex in DejaVu Sans Mono, is first placed as the C reference placed it after HarfBuzz's fallback mark positioning (`render_cluster`): centred over its base's ink, a row above all the ink since the base, or directly under it. Its base is the letter before it in the order the text is written, found on either side of it in a right-to-left cluster, and a letter the font draws as several glyphs, such as a body and its dot, is one base. The marks over the middle of the base letter's ink are one stack and those under it another. A stack whose ink passes the row's top or bottom edge moves toward the baseline until it fits, as long as the move lands no more of its ink on the letter's ink than lies there already and leaves the stack inside the row's other edge. When the move fails either test, the whole cluster, letter and marks together, is scaled vertically just enough to fit the row, keeping the font's arrangement; each row of the result is the average of the rows it covers. The letter's own ink need not reach the row's edge for that. In DejaVu Sans Mono, alef with hamza and damma and jeem with kasratan reach it, and lam with shadda and fatha at 16 pixels has blank rows above the lam but is scaled too, because its marks, moved down, would land on the lam's stem. Otherwise base letters never move, and a mark keeps the sideways place the shaper gave it, its ink reaching sideways as any ink does. A color cluster's glyphs are left as they are.

The helper finds each outline source's baseline at a cell's height once, from its whole printable ASCII set, keeps it for the engine's life, and hands it to every request it rasterises for that source and height, so glyphs sent for different requests, or again after an eviction, stand on one baseline whatever each request held. Each font in a strike stands on its own baseline in its glyphs' pixels; a font with no printable ASCII keeps its ascent rounded up. The strike reports the baseline of the frit's first source, the font that sets the cell, even after that source fails as it draws, so the answers at one cell never change mid-session, and its underline and strike-through follow that baseline, as the C reference's `kmscon_font_freetype_get_deco` took them: the underline's thickness and centre from the font's `post` table, else a fourteenth of the cell near its bottom, and the strike-through's top and thickness from the `OS/2` table's strikeout when its size is above 0, else as thick as the underline and centred on half the x-height, `OS/2`'s `sxHeight` or the `x` glyph's height, or half the baseline; each at least a row thick, at most a quarter of the cell, and inside it. A strike whose first source is a bitmap font reports the cell's bottom row and the lines of a face with no metrics of its own, as before.

A glyph advancing more than one and a half cells is two cells wide: CJK, emoji, and the wide icons of a Nerd Font that is not a Mono build. A color glyph, a COLR glyph's layers or a CBDT or sbix bitmap, is drawn unhinted, centred across its cells and kept inside the cell's height. COLR layers are laid over each other with the renderer's rounding, premultiplied, and a COLR glyph larger than its cells is drawn again at the size that fits them.

A color bitmap is taken from the font's largest strike holding it, its colors premultiplied by its alpha, and scaled by vtium-config itself to the cell's size, or as far under as fits its cells: Lanczos then a light sharpen (an unsharp mask of radius 0.8 at 120 per cent), the operator's choice on vtium/vtium#23 from a comparison of six ways (`vtium-review-images/23/emoji-scaling.png`). Box, plain Lanczos, box with alpha snapped at half and nearest stay in `src/resample.rs`, one chosen when the tool is built with `VTIUM_CONFIG_COLOR_SCALE=lanczos-sharpen|lanczos|box|box-snap|nearest`, the first the default. It is a build-time setting rather than Cargo features because the methods exclude each other and features add up across a workspace; an unknown value fails the build. Weights, sizes and placement are computed in f64 with IEEE basic operations alone and rounded to 14-bit integers, and pixels are integers, with no `sin`, `exp` or `powf` from the platform, so a glyph is the same bytes on every host.

The parser's answer, which the parent checks, gives, for each cell asked for, the cell, the baseline, every glyph's width, format, pixels and ink box and the map; every codepoint is one the request covers, every RGBA pixel premultiplied, no glyph and no box larger than a set's chunk, and every box an R8 glyph's, past its cells and inside its reach.

## Sources

- **kbd names** resolve as `setfont` resolves them (kbd's `src/libkbdfile/kbdfile.c`, `src/libkfont/context.c`): in `consolefonts/` of each data directory in turn (`/usr/share/kbd`, `/usr/share`, `/usr/lib/kbd`, or `--kbd-dir`), the name followed by the first of `""`, `.psfu`, `.psf`, `.cp` and `.fnt` for which a file exists, plain before `.gz`, `.bz2`, `.xz` and `.zst`; a name with a `/` looks in the subdirectory its first component names, and an absolute path is taken as given, then with each suffix. Unimaps resolve the same way under `unimaps/` with `""`, `.uni` and `.sfm`. A font or unimap found by name is resolved through its links and read only if it stays under the `consolefonts/` or `unimaps/` of a data directory; a link out of them fails the source, and nothing is read from outside. A `font:` family's scan fails past `FAMILY_ENTRIES_MAX` entries in one directory.
- **A font's map** is the frit's `unimap=` when given, else the font's own table, else kbd's `def.uni`; a font with none is refused, naming `unimap=`.
- **vconsole** reads `FONT=` and `FONT_UNIMAP=` from vconsole.conf, with the kernel command line's `vconsole.font=` and `vconsole.font_unimap=` over them, as systemd-vconsole-setup reads them (`src/vconsole/vconsole-setup.c`). With no `FONT=`, systemd ran no `setfont` and the kernel kept its font, so the source is refused and names `console:VT`. `FONT_MAP=` maps the kernel's 8-bit translation and sets no glyph, so it is not read.
- **console:VT** takes the font the console read from its own VT at start, with `KD_FONT_OP_GET_TALL`, or `KD_FONT_OP_GET` on a kernel without it, and its map with `GIO_UNIMAP`, and handed the helper (ADR-1200 D8); the helper opens no VT.
- **CPI fonts** are the codepage files kbd ships (`.cp`), as `setfont` reads them: one screen codepage, its 28-byte entry header and its info header, then each font's height, width, aspect and glyph count and its glyphs. A CPI file holds a font of each of several heights, so its source takes `cp-size=` 8, 14 or 16, as `setfont` takes `-8`, `-14` or `-16`, and with none the source fails naming `cp-size=`; `cp-size=` on a source that reads as no CPI file fails that source. Its glyphs have no table, so they take `unimap=`, else `def.uni`.
- **BDF fonts** are read by vtium-config's own reader, never through swash (ADR-1200 D14): Adobe's BDF 2.1, plain or compressed, in the character set ISO10646-1, whose encodings are codepoints; any other character set fails the source. The registry and the encoding are the `CHARSET_REGISTRY` and `CHARSET_ENCODING` properties, and where a property is missing, the last two fields of the XLFD name on the `FONT` line, so Tiny5 Mono's BDF, which names `iso10646-1` only there, reads as published. A font that gives the registry `ISO10646` and no encoding at all reads too. Its cell is as wide as the advance most of its glyphs take, the narrower on a tie, so one stray glyph narrower than the rest leaves only itself out, and `FONT_ASCENT` and `FONT_DESCENT` high, else the bounding box's. A glyph advancing that width is one cell wide and one advancing twice it two; a glyph of another advance, or an encoding no Unicode scalar value, is left out, and a codepoint's first glyph is taken. A glyph of `ENCODING -1` has no place in the character set: it is read as any glyph, so a malformed one still refuses the font, then left out and not counted against `CHARS`, which some fonts, Tiny5 Mono's among them, count without such glyphs. Each glyph sits on the baseline at its `BBX` offsets and is cut at its cells' edges. A BDF font's bytes are read where the source is resolved and parsed in `Engine::load`, in the helper's own sandbox with the other fonts, since the glyph form the parser's child answers with holds no glyph two cells wide; `preview` (#120) has no sandboxed place to parse one yet.
- **Compression** is told by its magic, as kbd tells it, and decoded with its stream's own check value verified: gzip, bzip2, xz and zstd, each refused past `COMPRESSED_BYTES_MAX` before it is decoded and past `PSF_BYTES_MAX` once decoded.

## The parser

`src/child.rs` is the side of `vtium-config --parse` that reads the request; the parent's side, which starts it, lives in `tests/common/parser.rs`. The child runs for a font: an empty environment, `/` as its directory, a process group of its own, its three pipes and no other descriptor. Run as root, the parent starts it as `nobody` from `/etc/passwd`, its supplementary groups dropped, and refuses when there is no such account. The parent kills the parser through a pidfd past 60 s by the wall clock and reads its stderr on a thread of its own. Another thread reaps the parser as soon as it exits, even while a process it started still holds its pipes. Just before the reap, that thread kills the parser's process group, so nothing the parser started outlives it; the parser itself may start no process, so the group catches what a stand-in starts in the tests and anything that slips past that limit (vtium/vtium#163). The parser sets no-new-privileges, an address space of 512 MiB, 30 s of CPU, no file writes, no processes and no core, refuses to run as root, reads its request, parses, and answers with the glyph form, which the parent checks field by field against the PSF bounds before it trusts it. A parser that fails, faults, passes a limit or answers malformed fails that source. No command runs it since `create` went; only the tests start it. `preview`, `fonts`, `new` and the TUI hand fonts to the helper, `serve`, which sets the same limits on itself and refuses root, so no command needs the parser's child (ADR-1201 D3, D9). The helper takes its `PARSER_MEMORY`.

## The helper

`vtium-config serve` is the helper the console starts on its first need for a frit's glyphs (ADR-1301 D2). It first sheds every descriptor above standard error its starter left open, as a copy of a terminal a font could write to: it marks them close-on-exec and starts itself again once through `/proc/self/exe`, with `VTIUM_CONFIG_SERVE_SHED` set so it does so once, so it holds only its three pipes. It sets no-new-privileges, starts the thread that reads its requests, then sets the parser's limits with 300 s of CPU over its life, and refuses to run as root. Each request carries the frit's name and text, so a frit the console makes on the fly needs no file; the helper reads the frit's fonts itself, as the account the console started it as, parses bitmap fonts and rasterises outline ones in its own process, and draws at the cell each request names, the frit's, never another (#145): an outline font drawn at that cell, a bitmap font scaled by the largest whole factor that fits and placed on the cell's bottom row. A frit's `console:` source takes the kernel's font the console read at start and handed over. It takes four requests. The first is a cell query, which the console sends for a frit that states no `cell=` before its first frame and, for an outline frit, at each zoom, and which the helper answers at once (ADR-1200 D17). The frit's first source sets the cell. That is the first source in the frit's order that the helper can draw from: as for glyphs, the helper leaves out a source this machine does not have or cannot read, and a source that has failed as it drew, a source whose W rule fails included, and the next source sets the cell instead. ADR-1200 D17 says only that the first source sets the cell; which source counts as first is the helper's own behaviour. A bitmap first source answers its own cell, once every later bitmap source's cell fits in it, and the console takes that cell at whole multiples. An outline first source answers the cell the W rule gives it at the height the query names, which the console takes as it is; a query that names no height gets no cell for it. Later sources of either kind draw into that cell. The helper reads no `cell=` line to answer a query, since the console reads `cell=` itself and asks only where D17 has it ask. The console takes either answer to any query, its own cell (frame 6) or the W rule's (frame 10), whatever the frit's text names first: when an outline first source is missing on this machine, a bitmap source after it answers, and the reverse. The other three requests are an ask, answered whole ahead of anything else with the glyphs of the codepoints and the clusters it names, each cluster shaped with HarfRust from the first outline source in the frit's order that covers its first scalar value other than U+200D, and drawn whole into the frame's cluster map (ADR-1200 D21); a cluster no source shapes as its kind requires is left out, and the console draws it its own way; a fill, which draws a cell's coverage while nothing is asked, the codepoints it names first, then printable Latin and box drawing, then the rest, 1,024 codepoints a batch, skipping what the console holds and what it sent, a waiting request taken before each batch; and a stop, which ends a cell's fill. A fifth request, a sources query, is vtium-config's own and the console never sends it: the helper answers at once with each source of the frit it left out, `missing` when this machine does not have it and `refused` when it has it and cannot read it, with the source's line, spelling and why, which `fonts` lists. Glyphs go as vitrified sets of one strike each. Each warning a frit's text gives, such as `compress=`'s, is sent once as the helper first reads the frit, naming the frit and the line, and the console logs it. A source that fails as it draws is left out for the helper's life, and the next source in the frit's order gives its glyphs; a fill that never draws a glyph fails, naming each source whose cell does not fit or that failed. Each request is bounded before anything is allocated for it: the frit's name at 64 bytes and its text at `FRIT_BYTES_MAX`, the cell inside `CELL_SIDE_MAX`, the display's capabilities reserved and empty, 32,000 codepoints, each a scalar value, 32,000 clusters in an ask alone, each 1 to `CLUSTER_SCALARS_MAX` scalar values, 65,536 held ranges, and the kernel's font inside the kernel's own bounds. A frame's payload is at most 16 MiB, a batch past it cut in two. It exits after `HELPER_IDLE_MS`, 60,000 ms, with no request and no fill, or when the console closes its end and its work is done.

## Departures

- **A relative kbd name is never looked for in the working directory.** `setfont` tried the name as given first, so a file in the directory it ran from shadowed the data directories. The helper runs unattended. Spec: ADR-1200 D1, "resolved as `setfont` resolves it, in the kbd data directories the build names".
- **A named font with no table and no `unimap=` takes `def.uni`.** `setfont` loaded `def.uni` only for its default font, and left the kernel's map in place for a named one; the helper has no kernel map to inherit. Spec: ADR-1200, "Where vtium departs".
- **A unimap entry for a glyph past the font maps nothing.** kbd handed it to the kernel, which kept it.
- **An outline font's cell is the cell asked for.** The C reference's FreeType backend made its cell the font's line height (`kmscon/src/font/font_freetype.c:189`), its ascent, descent and line gap scaled and rounded, which can pass the height asked for; the helper draws at the cell the console names, so the grid never moves for the font. Spec: ADR-1200 D1, "An outline source is drawn at the cell (D17)".
- **A CFF outline font's cell can be a column wider.** The C reference's FreeType light hinting moved only rows in a TrueType font, which is what the W rule's unhinted measure follows, but its CFF hinter could also narrow a glyph's ink by a column. Nimbus Mono PS at 21 pixels took a cell 12 wide in the C reference and takes 13 in vtium (measured with libfreetype 2.15.0). Spec: ADR-1200 D17, "as wide as the wider of W's advance and W's ink at that height".
- **A bitmap-only sfnt font is not sized by its strikes.** For a TrueType or OpenType font holding only bitmap strikes, the C reference chose the strike nearest the height asked for and took that strike's height and its `W`'s width (`bitmap_font_select_size`). The helper draws pixel fonts only from BDF and the kbd formats, never through swash (ADR-1200 D14), so an `outline:` source that holds no outlines is sized at the height the console names, by its `W`'s advance; its color strikes, if any, are scaled to the cell. Spec: ADR-1200 D14, "Pixel fonts are read by `vtium-config`'s own BDF reader, never through swash".
- **A font with no `W` takes its cell's width from `M`, then `0`, then half the cell's height.** The C reference's `font_get_width` measured the glyph `FT_Get_Char_Index` gave for `W`, which is the font's missing-glyph box when it has no `W`, so the cell's width came from a glyph no text draws. Spec: ADR-1200 D17, "as wide as the wider of W's advance and W's ink at that height".
- **The underscore stays inside its cell.** The C reference's FreeType engine cut a gray glyph's ink at the cell's bottom edge, so an underscore below the cell was lost, and moved a 1-bit glyph that passed the bottom up on its own (`copy_map`, `copy_mono`, `kmscon/src/font/font_freetype.c:309-380`); its pango engine drew no underscore with DejaVu Sans Mono 24 in a 14x28 cell (aaronsb/kmscon#254). The helper raises a font's whole baseline by the pixels its printable ASCII's lowest ink passes the cell, so where it rises the whole line sits a pixel higher than the C reference drew it. Spec: ADR-1302 D3, and its departure "The underscore stays inside its cell".
- **A mark that does not fit moves toward the baseline, and a letter whose marks cannot is scaled with them.** The C reference's cluster path pushed a mark that did not fit back inside the cell, laying it over its letter where the letter left no room, and cut the rest (`render_cluster`, `kmscon/src/font/font_freetype.c:505-520`). The helper moves a stack of marks in only where its ink stays off its letter's, and otherwise scales the letter and its marks together to fit the row, so the vowel marks of Arabic and the cantillation of Hebrew show whole and apart from their letters. Spec: ADR-1302 D3, and its departure on marks.
- **A right-to-left mark the shaper leaves at the pen is placed over its letter.** The C reference's cluster path took a mark's base only from the glyphs before the mark (`render_cluster`, `kmscon/src/font/font_freetype.c:580`, `:590` at `b1f7a7c5`), so it placed no mark in a right-to-left cluster, where HarfBuzz returns the marks before their letter. The helper takes a mark's base to be the letter before it in the order the text is written, as Unicode's combining character sequence and OpenType's mark-to-base attachment do, so a mark above or below that the font has no anchor for is centred over or under its letter in either direction. Spec: ADR-1302 D3, and its "Beyond the C reference".
- **Arabic letters fill their cells; their joined forms wait on shaping across cells.** The C reference drew a single codepoint by its glyph index without shaping (`kmscon/src/font/font_freetype.c:443`), so Arabic letters drew in their isolated forms, unjoined, unless a program wrote Unicode's presentation forms itself. The helper also draws each letter in the form its codepoint, or its cluster with its marks, gives, since choosing a letter's joined form needs its neighbours, which shaping across cells will bring; it stretches each joining letter's advance to its cells' width (ADR-1302 D2), so the strokes a font draws to the advance reach the cell's edges, and closes the seam of up to 0.72 pixels that DejaVu Sans Mono's letters leave at the W rule's cell. Spec: ADR-1302 D2 and D12, and its departure "Arabic letters join, and fill their cells".
- **A glyph sits where its font puts it.** The C reference's FreeType engine moved a gray glyph that passed its cell's right edge left by half of the overflow, and a 1-bit glyph that passed its left edge right, and cut what still passed (`copy_map`, `copy_mono`, `kmscon/src/font/font_freetype.c:309-380`). The C reference's `centre_dx` centred only a narrow glyph in a two-cell box, its advance clamped at 0 (`kmscon/src/font/font_freetype.c:425-441`); the helper centres every glyph's rounded advance in its cells, clamped at 0 as well, keeps its bearings, and keeps the ink past its cells in its ink box, up to one cell past them, so an italic run keeps its spacing and a letter keeps its place. Spec: ADR-1302 D1, D2, and its departure "A glyph sits where its font puts it". No specification covers glyph overhang.
- **A glyph is one or two cells wide by its own advance.** The C reference drew each glyph at the width the terminal gave its cell; the helper draws a glyph before the terminal asks for a width, so a glyph advancing past one and a half cells is sent two cells wide, and `Font` fits it to the width the terminal gives (ADR-1300).

## What this slice leaves for later

- The density is the first measured display's, since the TUI cannot tell which display shows the terminal it runs in; it reads the EDID's size in whole centimetres, where the console reads the connector's millimetres, so the two can differ by a dot per inch or two. vtium-platform's EDID reader is private to it; once vtium-platform makes it public, `src/display.rs` takes it in place of its own.
- A session's end returning its console to the configured font (ADR-1201 D11) is the console's, in crates/vtium.

- Styles other than regular (an outline font's bold and italic faces, ADR-1000's `text.outline`) are refused by name. So the W rule's cell takes only the first source's face today; ADR-1200 D17 has it take the bold face too, the wider of the two, once `style=` names one, and `outline::cell_width` already takes the widest of the faces it is given.
- vtium.conf's `font-hinting`, and a profile's, over the frit's `hinting=` (ADR-1200 D1): the helper hints as the frit says, since no request carries the console's setting yet.
- ADR-1300's subpixel strikes, and shaping across cells (ligatures, Arabic joining forms, syllabic scripts): the helper shapes the clusters the terminal segments, one at a time (#144).
- A collection matched by family needs a file named for that family; a collection of several families is named with `outline:`.
- COLR version 1 glyphs, such as `Noto-COLRv1.ttf`'s, are not drawn in color: swash reads version 0. A COLR layer in the text's color takes swash's mid grey, since a set cannot know the text's color.
- The parser's account is `nobody`; ADR-1400's pre-login account takes its place once vtium/vtium#31 names it.
- A root run is unverified on the maintainer's machine: the drop to `nobody`, `nobody` executing the binary from its install path, and the real `console:VT` ioctls. Tier 3's guest is where they run.

## Bounds

A frit and every source file are opened once, never blocking on a FIFO, refused unless that descriptor is a regular file, and read no further than their bound.

| `FRIT_SOURCES_MAX` | 16 | The frit is refused, naming the line |
