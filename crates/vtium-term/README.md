# vtium-term

vtium's terminal state: the screen, its cells and lines, the scrollback, the modes, SGR, the character sets and the replies, applied from the actions `vtium-parse` produces; what keys, the pointer, focus and pastes send the program; and the frames a renderer reads. It forbids unsafe code and has no dependency outside the workspace. The cell, line and frame model (vtium/vtium#10, ADR-1001), the screen, scrollback, selection and Unicode tables (vtium/vtium#11), the modes, SGR, the replies and the input encoding (vtium/vtium#12), and the character sets (vtium/vtium#13) are in place.

## Behaviour

The C reference is the floor: vtium does everything it does, and where it departs from a protocol specification, vtium follows the specification. Each departure is listed below with its reason, and with the specification it follows where one covers it. The test of each is named with it.

Text is cut into cells by UAX #29's extended grapheme clusters at the Unicode version the tables carry, or by codepoint width with mode 2027 reset. A codepoint takes no cell when its General_Category is Mn, Me, Cf or Cc (but U+00AD and Prepend characters), or it is a Hangul medial vowel or final consonant; two when its East_Asian_Width is W or F or it has Emoji_Presentation; one otherwise. A VS16 makes an emoji-style base two cells. These are the C reference's rules and tables, so tier 1's goldens judge them unchanged.

The C reference's cluster table took a hash seed from the system's entropy, and logged nothing when it fell back (aaronsb/libtsm#41). vtium keeps each line's clusters in the line's own arena (ADR-1001), so there is no shared table, no hash and no seed: the item has no counterpart.

## Departures

- **Cells past a line's end read in the default style.** A scrollback line narrower than the screen is padded, when drawn, with blank cells in the default style, never the pen. The C reference drew them with the current pen, so an SGR under BCE recoloured them with no change age moving (aaronsb/libtsm#47). No specification covers padding. The reason: padding is not text the program wrote, so the pen has no claim on it, and a pen change that moved no age left a display drawing stale colours. Tests: `cells_past_the_end_read_blank_in_the_default_style` (the line), `a_pen_change_while_scrolled_back_leaves_the_padding_alone` (the screen).
- **A region scroll marks only its rows.** Scrolling inside margins, IL and DL mark the rows that moved and leave the rows outside them unchanged; the C reference marked every cell and every placement of the frame (aaronsb/libtsm#34). No specification covers change tracking. The reason: a renderer redraws what is marked, and the C reference's rule redrew a whole screen for a one-row scroll in a status pane. Tests: `a_region_scroll_marks_only_the_region` (`Damage`'s rule, and the screen's), and the property test `a_frames_changed_set_covers_every_cell_that_differs` (aaronsb/libtsm#48), which a planted skip turns red.
- **Moving the cursor marks nothing.** The frame carries the cursor, and a renderer redraws the cells it left and covers (ADR-1001, "Change tracking"). The C reference marked the cell the cursor left and the cell it reached, so after a cut in the replay view a caller's next `frame-since` counted the cursor's cell: the C reference printed 1 where vtium prints 0, which masking does not hide (vtium/vtium#14). Test: `after_a_checkpoint_nothing_is_changed`.
- **The frame marks the default background.** A frame cell says whether its background is the default one and not inverted, so an image below cell backgrounds shows through exactly there. The C reference resolved the background to RGB with no mark and compared colours, so a background a program set to the default's colour also showed the image (aaronsb/libtsm#35). Spec: the kitty graphics protocol, z-index below -1,073,741,824: drawn "under cells with non-default background colors". Test: `default_bg_marks_only_the_default_background_uninverted`.
- **CHA and VPR keep to the cursor's row in origin mode.** The C reference passed the cursor's absolute row where a row relative to the region was due, so CHA moved the cursor down by the region's top, and VPR by that and its count. Spec: ECMA-48 8.3.9, CHA moves within the active line; 8.3.160, VPR moves relative to it. Test: `cha_and_vpr_in_origin_mode_keep_to_the_cursors_row`.
- **A private marker or an intermediate makes another function.** CUD, CUF, CUB, CNL, CPL, CHA, VPA, VPR, ED, EL, ECH, IL, DL, CHT, CBT and REP act only without either, ED and EL also with `?` (DECSED, DECSEL). The C reference ran them whatever marker or intermediate they carried. Spec: ECMA-48 5.4, "Together with the Final Byte F, [the intermediate bytes] identify the control function", and 5.4.1 b), a private marker makes the parameter string private (vtium-parse's README, "Notes for vtium-term"). Test: `a_marker_or_an_intermediate_makes_another_function`.
- **HPA and HPR move the cursor.** The C reference ignored them. Spec: ECMA-48 8.3.57 (HPA), 8.3.59 (HPR). Test: `hpa_and_hpr_move_the_cursor`.
- **A printed DEL does nothing.** The C reference wrote U+007F to the screen, where it joined the cell before as a character of no width. Spec: vt100.net, "terminals only claiming VT220 compatibility can always ignore 7F"; only a 96-character set in GL draws it, and vtium designates none. Test: `a_printed_del_does_nothing`.
- **A character decoded from UTF-8 prints as itself, whatever G1 to G3 hold.** In UTF-8 input GR plays no part; only in 8-bit input do the bytes A1 to FE map through it. The C reference ran a decoded U+00A1 to U+00FE through GR (`vte_map`, tsm-vte.c:2887-2910), so after `ESC ) 0`, which TERM=linux's `enacs`, GNU screen and elinks send, ñ printed as ─ (`kmscon/kmscon issue 198`, `kmscon/kmscon issue 262`). Spec: xterm's UTF-8 mode. The xterm manual (patch 411), `vt100Graphics`, has xterm "interpret VT100 graphic character escape sequences while in UTF-8 mode", and a black-box run of xterm 411 (`-u8`, under Xvfb, its screen printed through `printerCommand`) shows ñ for `ESC ) 0 ñ` and ─ for `ESC ) 0 SO q SI`. xterm stops decoding UTF-8 while GR holds a set other than ASCII after LS1R, LS2R or LS3R (`ptydata.c`), so the same run shows `Ã±` for `ESC ) 0 ESC ~ ñ`; vtium keeps decoding. Test: `a_utf8_character_prints_as_itself_whatever_g1_to_g3_hold`.
- **The default mapping is the VT220's: G0 to G3 hold ASCII, GL holds G0 and GR holds G2.** DECSCL 62 to 64, which choose 8-bit input, designate DEC supplemental graphics into G2 and G3; DECSCL 61 designates nothing. The C reference started G1 and G3 with the Latin-1 upper half (`tsm_vte_unicode_upper`), gave GR G1, and had DECSCL 61 to 64 designate DEC supplemental graphics into G1, so SO or SS3 with nothing designated turned `q` into ñ, and in 8-bit input `ESC ) 0` turned each byte from A1 to FE into DEC special graphics. Spec: the VT220 manual, 4.4, "The default mapping in VT200 mode is ASCII graphics in GL and DEC supplemental graphics in GR", and 4.4.3, LS2R: "Invoke G2 into GR (VT200 mode only). (default)"; in VT100 mode "Only ASCII, national replacement characters, and DEC special graphics are available". A black-box run of xterm 411 in 8-bit mode (`+u8`) agrees: after `ESC ) 0` the byte F1 prints ñ, and after `ESC * 0` it prints ─. Tests: `shift_out_invokes_g1_into_gl`, `single_shifts_take_the_next_character_only`, `gr_maps_the_upper_half_in_eight_bit_input`, `seven_bit_input_reaches_only_gl`.
- **A single shift is taken by the next printed character, whatever it is.** The C reference kept it until an ASCII graphic character came, so in `ESC N ñ q` it mapped the `q`. Spec: the VT220 manual, 4.4.4, "All single shifts are active for only the next single graphic character"; ctlseqs, SS2: "This affects next character only". A control before the character leaves the shift waiting, as in the C reference and xterm. xterm 411 departs from VT220 4.4.4 and from vtium/vtium#13's rule in UTF-8 mode: after `ESC * 0 ESC N` it stops decoding UTF-8 for the shifted character, so `ñ q` prints `Ã±q` and `€ q` prints `␉¬q` where vtium prints `ñq` and `€q`. Test: `single_shifts_take_the_next_character_only`.
- **REP repeats the character a single shift mapped.** `ESC * 0 ESC N q CSI 2 b` prints `───`, as in the C reference; xterm 411 repeats the unmapped character and prints `─qq`. Spec: ECMA-48 8.3.103, REP repeats "the preceding graphic character", which is the one the shift drew. Test: `rep_repeats_the_character_a_single_shift_mapped`.
- **DECSC saves what G0 to G3 hold and a pending single shift, and DECRC with nothing saved returns the default mapping.** The C reference saved only which of G0 to G3 GL and GR held, and DECRC with nothing saved left the designations. Spec: VT510, DECSC saves the "Character sets (G0, G1, G2, or G3) currently in GL and GR" and "Any single shift 2 (SS2) or single shift 3 (SS3) functions sent"; xterm saves the designations with them and resets the sets when nothing was saved (`cursor.c`, `CursorRestore`), and the black-box run shows ─ for `ESC ( 0 ESC 7 ESC ( B ESC 8 q`. Test: `decsc_saves_the_character_sets`.
- **A national replacement set's final designates ASCII.** The C reference designated the Latin-1 upper half for each (its `TODO: create British charset from DEC`), so after `ESC ( K` an `a` printed as á. ADR-1000 refuses DECNRCM (DEC-42), and xterm draws a national set as ASCII while DECNRCM is reset: the black-box run shows `#a` after `ESC ( A`, and `[` after `ESC ( K` in both modes. Test: `national_replacement_sets_designate_ascii`.
- **DEC special graphics draws 5/15 as a blank, and a reserved position of DEC supplemental graphics prints nothing.** The C reference wrote U+0000 for each, which joined the cell before as a character of no width. Spec: the VT220 manual, table 2-4, 5/15 "(BLANK)"; xterm prints a space. No specification gives a reserved position a character. Tests: `dec_special_graphics_draws_lines`, `dec_supplemental_graphics_only_in_eight_bit_input`, `gr_maps_the_upper_half_in_eight_bit_input`.
- **DEC special graphics draws 6/0 as U+25C6 and 7/14 as U+00B7.** The C reference drew U+2666 and U+22C5. The VT220 manual gives glyphs, not code points; xterm (its manual's table), Konsole (`vt100_graphics`), Ghostty (`charsets.zig`) and the Linux console (`consolemap.c`) all draw U+25C6 and U+00B7. The operator's decision. Test: `dec_special_graphics_draws_lines`.
- **`ESC ( <` designates DEC supplemental graphics only in 8-bit input,** where it is the VT220's default for GR; in UTF-8 and 7-bit input it designates ASCII. The C reference designated DEC supplemental graphics in every input, so in UTF-8 input `ESC ( < q` printed ñ. xterm takes `<` as the user-preferred supplemental set, which "is not available with UTF-8" (`charproc.c`, `resetCharsets`), and designates ASCII: a black-box run of xterm 411 prints `q` for `ESC ( 0 ESC ( < q`. Konsole (finals 0, A, B), Ghostty (`escDispatch`: B, A, 0) and the Linux console (`vc_setGx`: 0, B, U, K) ignore the final instead, so G0 keeps what it held and the same bytes print ─; each prints `q` for `ESC ( < q`. vtium follows xterm. The operator's decision. Test: `dec_supplemental_graphics_only_in_eight_bit_input`.
- **DECSTBM homes the cursor, and an omitted bottom margin is the last row.** The C reference left the cursor where it was, and took an omitted bottom as 0, so `CSI 5 r` made the whole screen the region. Spec: the VT510 manual, DECSTBM: "Default: Pb = current number of lines per screen.", and "DECSTBM moves the cursor to column 1, line 1 of the page."; xterm moves it home, the region's top in origin mode. Test: `decstbm_homes_the_cursor_and_an_omitted_bottom_is_the_last_line`.
- **An inverted or one-row DECSTBM is ignored, and a bottom margin past the screen is its last row.** The C reference made the whole screen the region for each. The VT510 manual says only "The value of the top margin (Pt) must be less than the bottom margin (Pb).", so vtium does as xterm does (`charproc.c`, `CASE_DECSTBM`): the region and the cursor stay, and a bottom past the screen clamps. Test: `an_invalid_decstbm_is_ignored_and_a_bottom_past_the_screen_clamps`.
- **Outside the region, IND, RI, a line feed and a wrap stop at the screen's edge.** The C reference scrolled the region when the cursor reached the screen's last row below the region, or its first row above it. Spec: the VT510 manual, IND: "If the cursor is at the bottom margin, then the screen performs a scroll-up."; DECAWM: "Any text on the page scrolls up if the cursor is at the end of the scrolling region."; the VT220 manual, chapter 4, RI: "If cursor is at top margin, screen performs a scroll down." (the VT510 manual has no RI page). Below the region a wrap on the last row returns to its first column, as a wide character or a widened cluster does, and leaves the row unmarked as wrapped, since its text does not continue. Test: `index_outside_the_region_stops_at_the_screens_edge`.
- **A copied wide character brings no space.** The C reference copied a space for the second column of each wide character in a selection. No specification covers copying; the reason: the space is not text the program wrote. Test: `a_copied_wide_character_brings_no_space`.
- **DA1 reports a VT220 with colour, `CSI ? 62 ; 22 c`.** The C reference sent `CSI ? 60 ; 1 ; 6 ; 9 ; 15 c`: level 60 is none of xterm's, and 1, 6, 9 and 15 claimed 132 columns, selective erase, national replacement sets and the technical set it lacked (aaronsb/libtsm#31). Spec: ctlseqs, DA1, whose levels are 1, 62, 63, 64 and 65; ADR-1000, query.da1. Attribute 4 joins it when sixel is built (vtium/vtium#48). DECID answers the same. Test: `da1_reports_a_vt220_with_colour`.
- **DA3 answers DECRPTUI, a unit id of zeros.** The C reference answered `CSI = c` as DA1. Spec: VT510, DA3 and DECRPTUI; xterm answers `DCS ! | 00000000 ST`. Test: `da3_reports_a_unit_id`.
- **DECRQSS for DECSCL reports the level DECSCL set,** 61 to 64, and 62 until one is set and after DECSTR, with Pc 1 since the replies stay 7-bit. The C reference answered `62;1"p` whatever the level. Spec: VT510, DECRQSS reports the current setting; xterm reports its level and its C1 setting. Test: `decrqss_reports_the_conformance_level`.
- **XTGETTCAP prints each name in uppercase hex from the table.** The C reference echoed the request's spelling. Spec: docs/architecture.md, "Determinism", the reply rule: no reply carries request bytes. Tests: `xtgettcap_answers_from_the_table_in_uppercase`, and `no_reply_carries_the_requests_bytes` in `src/terminal/reply.rs`.
- **An XTGETTCAP reply of exactly 4096 bytes is sent.** The C reference reserved a byte for a `;` the last pair does not take, so it dropped a pair that fit. The bound is `XTGETTCAP_REPLY_MAX`. Test: `xtgettcap_replies_up_to_its_bound`.
- **ENQ answers an empty answerback.** The C reference answered ACK (0x06). Spec: ADR-1000, query.enq, as xterm's empty `answerbackString` and Ghostty's empty `enquiry-response`. Test: `enq_answers_nothing`.
- **A paste is filtered as xterm filters one.** In every paste, bracketed or not, each C0 control but HT, LF and CR, DEL, and each C1 control becomes one space: in UTF-8 input a C1 control is a code point, U+0080 to U+009F, and its two bytes become one space, with ill-formed bytes pasted as U+FFFD; in 7-bit and 8-bit input it is a byte, 0x80 to 0x9F. Since ESC and the C1 controls are filtered, a bracketed paste never carries its own end marker. Spec: the xterm manual (patch 412), `allowPasteControls`, false by default: "Other C0 control characters are suppressed unless this resource is enabled", and `disallowedPasteControls`, which turns each control it lists into a space, by default `BS,DEL,ENQ,EOT,ESC,NUL,STTY`; ADR-1000, input.paste-end-marker. vtium differs from xterm's default in two ways: it filters every C0 control but HT, LF and CR where xterm filters those in its list, and it filters the C1 controls in UTF-8 input too, where xterm filters them only outside UTF-8. Tests: `a_bracketed_paste_never_carries_its_own_end`, `a_paste_keeps_only_the_formatting_controls`, `a_character_whose_bytes_look_like_c1_arrives_whole`, `ill_formed_utf8_in_a_paste_becomes_the_replacement_character`, `eight_bit_input_turns_the_c1_bytes_of_a_paste_into_spaces`, `an_ordinary_paste_arrives_unchanged`.
- **CPR counts rows from the region's top in origin mode, and a pending wrap reports the last column.** The C reference reported the screen's row, and a column one past the last while a wrap was pending. Spec: VT100 User Guide, CPR: "The numbering of lines depends on the state of the Origin Mode (DECOM)"; the cursor stands on the last column while the wrap is pending (VT510, DECAWM). Test: `dsr_reports_the_status_and_the_cursor`.
- **DECXCPR adds the page, and a private DSR other than 6 gets no reply.** The C reference answered `CSI ? 6 n` with the plain CPR and `CSI ? 5 n` as DSR 5. Spec: VT510, DECXCPR: `CSI ? Pl ; Pc ; Pp R`; ECMA-48 5.4.1 b), a private marker makes another function. Tests: `dsr_reports_the_status_and_the_cursor`, `the_other_device_status_reports_are_ignored`.
- **DECSC saves the pending wrap, and DECRC restores the cursor to where it was on the screen, in a slot for each screen.** The C reference lost the wrap, moved the restored row by the region's top when origin mode was on as DECRC ran, and kept one slot for both screens. Spec: VT510, DECSC: it saves the "wrap flag"; xterm keeps a saved cursor for each screen. Test: `decsc_saves_and_decrc_restores_the_cursor_state`.
- **Modes 1048 and 1049 save and restore the cursor as DECSC and DECRC do, the pen included,** so leaving the alternate screen erases with the main screen's pen. The C reference saved the position alone, and a background set on the alternate screen carried over (aaronsb/libtsm#20). Spec: ctlseqs, 1048, "Save cursor as in DECSC", and 1049. Tests: `mode_1048_saves_and_restores_the_cursor_as_decsc_does`, `mode_1049_saves_the_cursor_and_the_pen_around_the_alternate_screen`.
- **RM 1047 clears the screen only on the alternate screen.** The C reference cleared the main screen too. Spec: ctlseqs, 1047: "Clear the screen first if in the Alternate Screen Buffer." Test: `mode_1047_clears_the_alternate_screen_as_it_leaves`.
- **DECSCUSR ignores a value past 6, and DECSC does not save the cursor style.** The C reference stored any value as a style and saved the style with DECSC. Spec: xterm's ctlseqs and its behaviour, the operator's decision (aaronsb/libtsm#78). Test: `decscusr_sets_the_cursor_style`.
- **DECOM moves the cursor home as it is set or reset.** The C reference left it where it was. Spec: VT100 User Guide, DECOM: "The cursor is moved to the new home position when this mode is set or reset"; xterm does the same. DECSTR's reset leaves the cursor, as it clears the mode with the screen's other flags. Test: `decom_addresses_from_the_region`.
- **An empty SGR parameter is 0 wherever it falls.** The C reference skipped one at the end, so `CSI 1 ; m` stayed bold. Spec: ECMA-48 5.4.2 e), an empty parameter is the default, and 8.3.117, SGR's default is 0. Test: `an_empty_sgr_parameter_resets`.
- **`CSI Ps T` scrolls only with one parameter.** With five it is XTHIMOUSE, refused with mode 1001 (ADR-1000); the C reference scrolled the screen. Spec: ctlseqs, `CSI Ps ; Ps ; Ps ; Ps ; Ps T`. Test: `key_formats_user_defined_keys_and_hilite_tracking_are_not_taken`.
- **Mode 1001 answers DECRQM with 4, permanently reset.** The C reference had no row for it and answered 0. Spec: ADR-1000, which refuses hilite tracking and has refused modes answer their fixed default. Test: `ignored_and_refused_modes_answer_their_fixed_state_and_change_nothing`.
- **XTWINOPS reports a size only where the host gave it, 15 reports the display, 14 ; 2 gets no reply, and 21 reports a fixed empty title.** The C reference answered 14 and 16 from a cell size of 0 before the host set one, answered 14 ; 2 as 14, and answered neither 15 nor 21. Spec: ADR-1000, "Replies and policy"; ctlseqs, XTWINOPS. Tests: `xtwinops_reports_the_sizes_vtium_has`, `the_title_report_is_empty`, `window_reports_vtium_has_no_window_for_are_ignored`.
- **OSC 10 with a list goes on to 11.** The C reference answered only the first field. Spec: ctlseqs, OSC 10: each further parameter is the next colour. Test: `osc_10_and_11_report_the_default_colours`.
- **A key's character in 7-bit input is `?` past 0x7F.** The C reference tested bit 7 alone, so U+0100 sent NUL. Spec: none covers it; the reason: a 7-bit program cannot read the character, and NUL is not what was typed. Test: `decscl_resets_and_sets_the_input`.

- **A line keeps 6 bytes of clusters a cell (ADR-1001's cluster budget),** so on a screen one column wide a heart and VS16, 7 bytes with its length byte, keep the heart; the C reference kept both. This moves the golden of the conformance case `insert-wide-one-column`. No specification bounds a cluster; the reason: a program cannot grow a line's memory past its budget. Test: `the_cluster_budget_cuts_a_cluster_on_a_one_column_line`.

## C behaviour kept

- **A line leaving the top of the main screen's scroll region enters the scrollback, wherever the region starts**, as in the C reference (`tsm-screen.c:388-399`); on the alternate screen it is cleared. No specification covers a scrollback, so vtium follows the C reference's flow. xterm keeps only the lines leaving a region at the screen's top. Test: `a_line_leaving_any_region_enters_the_scrollback`.
- **DECSTR resets the mouse modes and mode 1004, as RIS does;** xterm resets them on RIS only. The operator's decision (aaronsb/libtsm#76), recorded in each row's spec column. Test: `decstr_returns_the_modes_to_their_defaults`.
- **S7C1T and S8C1T are taken, and the replies stay 7-bit**, as the C reference sent them. ctlseqs has S8C1T send replies with 8-bit C1 controls, which a program reading UTF-8 takes for ill-formed text. Test: `c1_controls_and_their_announcers`.
- **DECSCL 61 sets 7-bit input and 62 to 64 8-bit input,** after a soft reset, as the C reference took them. Test: `decscl_resets_and_sets_the_input`.
- **Mode 12 under the default cursor style leaves the cursor as the host blinks it,** and DECRQM reports the host's blink, as the C reference did. Test: `mode_12_blinks_a_chosen_cursor_style`.
- **The Linux console's `CSI 16 ; Pn ]` keeps the cursor's blink interval for the host,** as the C reference took it. Test: `the_cursor_blink_interval_is_kept_for_the_host`.
- **LS2, LS3, LS1R, LS2R and LS3R act in every input,** as in the C reference and xterm's UTF-8 mode; the VT220 takes them in VT200 mode only. Test: `locking_shifts_invoke_g2_and_g3_into_gl`.

## Bounds

The byte stream comes from an untrusted program, so nothing it sends grows memory without a bound. A screen is at most `COLUMNS_MAX` by `ROWS_MAX`, and its size comes from the display and the font. Every path that writes, moves or erases cells gives back the cluster bytes it drops through the line, so a line's arena keeps its budget on each of them (`tests/flood.rs`). REP prints at most `PARAM_VALUE_CAP` copies (vtium-parse), as printed text does. The replies and input reports waiting for the host take at most `REPLIES_PENDING_MAX` bytes, and the replies of the byte that reaches the bound, before the input call returns for the host to take them; at the bound the input call takes nothing. XTVERSION's text is at most `VERSION_MAX` bytes; XTGETTCAP's table holds at most `TERMCAP_ENTRIES_MAX` names of `TERMCAP_NAME_MAX` bytes and values of `TERMCAP_VALUE_MAX`, and one request is answered for `XTGETTCAP_NAMES` names in a reply of at most `XTGETTCAP_REPLY_MAX` bytes. DECRQSS keeps the request's first two bytes, as long as any it answers, and a longer one gets the error form. A line's style and link tables hold at most twice its cells before they compact, so a program that writes a new style or link into every cell, over and over, never grows them past that. A grapheme cluster keeps at most `CLUSTER_MAX` codepoints, and the clusters a line's cells name take at most `CLUSTER_BYTES_PER_CELL` bytes a cell of the width the line was written at, with the arena compacting at twice that; a line trimmed for the scrollback keeps what its cells name. Damage tracks at most `COLUMNS_MAX` by `ROWS_MAX` positions, and the scrollback keeps at most `sb-size` lines, capped by default by the machine's memory or by a configured cap, at most `SB_SIZE_MAX`: the screen is made with the cap `sb_size_cap` gives, and clamps `sb-size` to it.
