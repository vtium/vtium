# vtium-settings

vtium-settings holds vtium's configuration. It has three parts:

- The key table. The console reads vtium.conf and its command line by the key table, and vtium-config shows and edits vtium.conf by it (ADR-1201 D1).
- vtium.conf's line syntax, and its line-by-line editor.
- vtium.conf's sections: the looks, heads and rules of ADR-1401 and ADR-1403. A head is a terminal for one or more displays. A look is the font and the font settings that a head draws with. The crate holds the sections' reader, their parser and their one writer. It also holds the evaluator, which places each display and input in a head, lets it roam, or sends it to `ignore` or `off`. Guards then check the result.

The sections, with the `version` and `policy` lines above them, make up the flow: the part of vtium.conf that decides where each display and input goes. `vtium` and vtium-config both link this crate, so the verdict a check gives before install is the verdict vtium reaches at boot. The crate depends on neither `vtium` nor `vtium-platform`. A device reaches it as an `Identity` that its caller fills in. The guards are functions of a placement and the set of devices. The crate forbids unsafe code, and it denies every panic that input can reach. It depends on rustix, to open the file the same way the console opens vtium.conf. It also depends on vtium-font and vtium-term, but only for constants: the bounds and defaults that the key table states.

## Behaviour

- **The file.** `CONF_FILE` is `/etc/vtium/vtium.conf`. It is one file, with no drop-ins (ADR-1403 D3). The notices and their next steps name this file.
- **Inspecting the file.** `inspect` looks the path up with symlinks followed. It returns `None` for a file that does not exist, which is the case where vtium runs the compiled-in configuration. It refuses anything but a regular file before it opens it, because opening a FIFO, a watchdog or a serial port acts on that device. It opens the file without blocking, and it reads at most `FILE_MAX` bytes and one. It gives the bytes and the text beside the ownership verdict. So `vtium check-config` can check a candidate file that root does not own yet.
- **Reading the file at start.** `read` is the reader vtium uses at start. It refuses a file that root does not own, or that its group or others can write. It also refuses the file when a directory above it fails the same test: root does not own the directory, or its group or others can write it. `read` checks the directories on the path given and above each link of the file's symlink chain, and it resolves the chain one link at a time.
- **The whole-file checks.** `text` checks the whole file. It refuses more than `FILE_MAX` bytes, and bytes that are not UTF-8. It also refuses any control character, the C1 controls among them, except a tab, a newline, and a carriage return that ends a line.
- **Whom vtium trusts.** `Trust::running_as` trusts root's files. For a vtium that runs as another user, it also trusts that user's own files, under the same check of who else can write them (ADR-1403 D3). `Untrusted::mend` gives the command that mends the path that fails: `chown root:root PATH` or `chmod go-w PATH`. `Untrusted::refusal` gives the whole message for vtium.conf. `Trust::owner` trusts a test's own user in place of root, because no test runs as root. `Trust::below` stops the directory check at a test's fixture directory, so a target directory under `/tmp` passes. `Trust::ROOT` checks every directory up to `/`.
- **The syntax.** vtium drops a byte-order mark before the first line. Above the first section come `version = 1` and `policy = open` or `policy = closed`, in either order. Anything else there is an error. A line there is a policy line when its bytes, after its leading blanks, begin with `policy` in any case. vtium knows this before it decodes the line's bytes. A CRLF line ending counts as a newline. `#` starts a comment at the start of a line or after a blank. A `#` inside a word is part of the word, so `login = cmd --x#1` keeps its `#`. `\#` after a blank is a literal `#`. vtium drops the blanks around `=` and between tokens, so a value holds no blank. A glob therefore writes a space as `?`. These are errors: a key set twice in one section or among the flow's top-level keys, a second `[rules]`, and a second `[head NAME]` of one name. The file has no `[guards]` section, because the policy sets every guard.
- **What each error drops.** `reading` reads every line, whatever came before the line, and it checks each line's bytes on their own. So a check names every error, each with its line, in the file's order. `at` shows an error as `PATH:LINE: WHAT`, the way vtium.conf's reports read, with every control and format character of the path escaped. A check keeps `ERRORS_MAX` errors and counts the rest. Each error drops what `scope` says:
  - A bad rule, or a bad top-level line, drops that line. A device then walks on to the next rule.
  - An error inside a head's section, or in its heading's name, drops the head with every rule that names it.
  - An unknown section, a second `[rules]`, a second section of a head's name, and a heading vtium cannot read each drop that section. The first section of the name stays.
  - Some errors drop everything but the `policy` lines, which vtium always reads. These are a missing or unknown `version`, a line past `LINE_MAX`, a file past `FILE_MAX`, and a head or rule past its bound.
  - A line that is not UTF-8, or that holds a control character, drops what an error on that line would drop.
- **Errors in the policy lines.** Every `policy` line counts, wherever it sits. A `policy` line inside a section is an error. That line counts as no policy, and the error drops only that line. Above the first section, vtium may find a policy line that it cannot read. Such a line holds a byte that is not UTF-8 or a control character. Or it runs past `LINE_MAX`, or `FILE_MAX` cuts it. Or it names another key, such as `Policy`, or another value. That line makes the file closed and broken. `resolve` then runs nothing of the file, under the closed policy. The boot display shows the panic screen. A second readable `policy` line is a key given twice, which drops that line alone.
- **What survives.** What survives the errors is a `Config`. Its `policy` is closed where a `policy = closed` line is readable, or where a policy line is not. `Reading::trusted` classifies the file for `resolve`. vtium cuts the text an error quotes at `QUOTE_MAX` characters, and it shows that text with every control and format character escaped. A path is quoted whole.
- **The first cut's names.** The first cut was the first design of vtium.conf's sections. Some of its names are now errors: the targets `focus` and `dark`, the head keys `on-loss` and `rescue`, the value `nohup`, and the section `[guards]`. Each error's message names the word that replaced the old one: `roaming`, `off`, `when-display-lost`, `isolated = yes`, `keep` and `policy`. `focus` and `dark` stay reserved. So a head of either name is an error, which drops the head with every rule naming it. A head's `font-name` and `font-size` are errors too. Their message names `[look NAME]`, because a head takes its font from its look.
- **Heads.** A head's name is 1 to 64 characters of `A-Z a-z 0-9 . _ + -`. The names `roaming`, `ignore` and `off` are reserved. A look's name follows the same rule. `consoles` is 1 to `CONSOLES_MAX`. A larger value gets the cap, with a warning. vtium keeps `login` as written, and reads it as vtium.conf's `login`. `when-display-lost` is `keep`, `hangup`, or `hangup DURATION`. The duration is a count of seconds, or a count with an `s`, `m` or `h` suffix, and it is at most `u32::MAX` seconds. `isolated` is `yes` or `no`, kept as written. When `isolated` is unset, the policy decides: `no` under open and `yes` under closed. An isolated head is never the active head. The rescue key leaves an isolated head's keyboards where they are.
- **A head's VTs.** `vt` names the VTs the head runs on. It holds one VT number from 1 to `VT_MAX`, or several separated by blanks, as in `vt = 3 4` (ADR-1403 D4). These are errors: a number outside that range, a word that is not a number, an empty `vt`, and a number named twice. Each of them drops the head with its rules. A head with no `vt` runs on every VT. A head's `vt` is its own key. It never sets the top level's `vt`, which is the VT vtium opens.
- **Rules.** A rule is `display MATCH -> TARGET` or `input MATCH -> TARGET`. Its match is `*` alone, or at most `TOKENS_MAX` tokens. A rule may name a head declared after it. `roaming` and `ignore` are an input's targets, and `off` is a display's target.
- **How a match reads its values.** `path` matches its `ID_PATH` exactly, or followed by `:` or `.`. So `path` takes every interface below it and every device on a hub in its port. For example, `...:3.3` takes `...:3.3:1.0` and `...:3.3.2:1.0`, but never `...:3.30:1.0`. `serial` and `edid` split their value at the first two `:`, so the serial itself may hold more. `id`, the vendor and product of `serial`, and the product of `edid` are hex, with or without `0x`. `connector` splits at its last `/`. `name`, `card`, both halves of `connector`, and the value of `udev` are globs, with `*` and `?`. Every other value matches as written. A key for the other kind of device matches nothing.
- **Warnings and notes.** Two things are warnings: a rule that an earlier rule of its kind shadows, and a head's consoles past the cap. An earlier rule shadows a later one when the earlier rule is `*`, or when its tokens are among the later rule's. Input sent to a head by `id` or `name` alone gets a note. `Config::needs_udev` lists the rules that use a key read from udev's database. `vtium check-config` uses that list to add a note where no udev daemon runs.
- **Placement.** `walk` places one device by the first rule of its kind that matches it. It treats every head as running, whatever the head's `vt` says. With no match, a display goes off. With no match, an input roams under open and is ignored under closed. A roaming input types into the active head, and a key chord moves the active head from one head to another. What survives of an open file with errors walks the shipped rules' input rules instead. The shipped rules are the rules of the compiled-in configuration. Their input rules roam the keyboard, pointer and key classes, and ignore every other input. `place` walks a set of devices and runs the guards over the result.
- **The display guard.** The display guard acts when no display reaches a head. It then lights the boot display. The boot display is the connector lit at start. Without one, it is the boot card's first connector in the kernel's order. Without that, it is the first connector of the other cards in the kernel's order, so a connected display always lights. A tie breaks by the boot card, then by the card's place in the kernel's order, then by the connector's place, and last by the whole identity. Under open, the guard lights the boot display in the first head, or in the default head where the file has no head. Under closed, the guard lights the boot display for a notice alone, which no head holds. For a valid closed file with no head, the guard does not light it at all.
- **The active head at start.** The active head starts on the boot display's head. Without one, it starts on the first lit head in the file. It starts only on a head that can be the active head: a head the file declares that is not isolated, or the default head under open. A head is isolated as its `isolated` line says, and otherwise as the policy leaves it. What survives of an open file with errors isolates no head.
- **The anti-lockout guard.** Under open, the anti-lockout guard acts when no device counted as a keyboard reaches a head with a lit display. The guard then makes every keyboard-class device roam. It moves the active head by the same rule that sets the active head's start. With no lit head that can be the active head, it moves nothing. Under closed, the guard is off. While a keyboard reaches a lit head, the active head stays where it is, lit or not. vtium does not count a device that udev marks `VTIUM_ROLE=token` or `VTIUM_ROLE=numpad`.
- **What else placement reports.** The rescue key is `Ctrl-Alt` and the function key of the VT that is already on screen. `rescue` says whether the rescue key takes a keyboard. The rescue key does so only under open, and never from an isolated head. `disposition` says whether vtium opens an input, opens it for the VT keys alone, or leaves it closed. The rescue key is among the VT keys, and under open vtium opens an ignored keyboard for the VT keys alone. `lockout` gives the layer 1 warnings of the rules alone. `idle_rules` gives the rules that no present device matches.
- **Placement on each VT.** `walk_on` and `place_on` place devices for the vtium that runs on one VT, by the four steps of ADR-1401 D3. A rule whose head runs only on other VTs notes that head, and the walk reads on. Once the walk has noted a head, only a rule whose head's `vt` names this VT can place the device. A head with no `vt`, `roaming`, `ignore` and `off` leave the device alone. When no rule places a device that has a noted head, the device stays with the first head noted, as `Place::Elsewhere`. Such a display stays dark, and such a keyboard types into nothing on this VT. Under open, `disposition` opens such a keyboard for the VT keys alone. Under closed, it does the same where the keyboard's head is not isolated, because the keyboard's VT keys switch the VT (ADR-1401 D3, "Who switches VTs"). Under open, `rescue` lets the rescue key take such a keyboard, as for an ignored keyboard.
- **The guards on each VT.** `place_on`'s guards take only the heads that run on its VT. The display guard lights the boot display for the first of those heads, or for the default head when none of them runs there. Only one of those heads can be the active head. The anti-lockout guard never moves a device that stays with a head on another VT. The display guard lights such a display only when every connected display stays with a head on another VT, so that the VT is not dark. Under open, for what survives of a file with errors, `default_head_on` says that vtium builds the default head on a VT where none of the file's heads runs. The default head can be the active head there.
- **A valid file on each VT.** For a valid file, `place_on` follows the maintainer's table in ADR-1401 D3, in place of the display guard. Under open, vtium shows on each display either a terminal or a notice that says why there is none, unless a rule turns that display off. Under closed, a display that no path names stays blank. When the file defines nothing, no head and no rule, under open `uses_builtin_on` says that vtium runs the built-in default terminal. vtium then builds the default head alone. `walk_on` places every display in `Place::DefaultHead`, and every input by the shipped rules' input rules, by `By::Builtin`.
- **Displays no path catches.** When the file defines paths, under open `place_on` gives `Place::Unused` to each display that no path catches on its VT and that no rule turns off. `Place::Unused` holds the head the display belongs to, whose `vt` names its VTs, or `None` when no rule gives the display a head. That includes a VT where none of the file's heads runs. Under closed, such a display keeps its place, `Place::Elsewhere` or `Place::Off`, and stays blank. A display that a rule sends to `off` stays blank on every VT. What survives of a file with errors keeps the display guard (D7). `heads_on_vt` lists the heads that a VT builds. `walk` and `place` name no VT. `complete_route`, `lockout`, `idle_rules` and the remarks use them.
- **vtium.conf's two parts.** `split` ends the top level at the first line whose first byte that is not a space or a tab is `[`. That includes a heading vtium cannot read. The top level holds vtium's own keys, which the console reads the forgiving way. The top level also holds the flow's `version` and `policy` lines, which `sections` reads. `Split::key_lines` gives the console every top-level line but those. So neither part reads the other's lines, and an error in a section never drops a top-level key.
- **A file with no flow.** A file with no heading and no policy line holds no flow, so `sections` gives `None`. vtium then runs its compiled-in flow, and the top level applies. A policy line alone belongs to the flow. So a file that states `policy = closed` is never read as open, and such a file needs no `version` line. A file with a section needs `version = 1`. Without that line, vtium drops every section but the policy. `value_for` reads what survives of the sections, as vtium runs them. So an error in one section changes only what that error drops.
- **The byte-order mark.** A byte-order mark before the first line belongs to the top level, and it is no part of the top level's first line. That holds for `split`, `sections`, the top level's readers and the line editor alike. The line editor keeps the mark as the file's first bytes.
- **One comment rule.** `comment` finds a line's comment, for the top level and the sections alike. `#` starts a comment at the start of a line or after a blank. A `#` inside a word is part of the word. `\#` after a blank is a literal `#`. A `#` that opens a `#rrggbb` value after the line's first `=` is part of the value. A `#` glued to a value, as in `font-size=12#big`, stays in the value. So `key_line` reads the value `12#big`, and the console reports that value as one it cannot read (ADR-1403 D4).
- **Looks.** `[look NAME]` takes `vtlook`, whose value is a name by the name rule. It also takes the keys that `keys::at(Level::Look)` lists. vtium checks each of those keys against the key table's values and bounds. A value out of bounds is an error in the look, and vtium never clamps it. Any error in a look drops that look, and a head that names the look draws with the default look. A second look of one name drops alone. More than `LOOKS_MAX` looks drop every section but the policy. `[profile NAME]` and a head's `profile` are errors, whose message names `[look NAME]` and `look`. A head may name a look that has no section. That head draws with the default look, and `Warning::NoLook` reports it. When the file has `[look default]`, every head that names no look draws with `[look default]`.
- **A head in vtium.conf** takes `look`, `consoles`, `when-display-lost`, `isolated` and `vt`. It also takes the keys that `keys::at(Level::Head)` lists, which today is `login` alone. vtium checks those keys as it checks a look's keys. A section may set a key of the key table that its kind of section cannot take. That is an error, and its message names where the key may be set.
- **The levels.** A head's own section wins over its look's section. The look's section wins over the top level. The command line has already been laid over the top level's own lines (ADR-1403 D5). `Config::settings` gives a head's section keys, each once, at the most specific level. The caller lays those keys over the top level. `value_for` gives the value and the level of one key from a file's text.
- **Labels.** The lines of the `[labels]` section, `display MATCH = LABEL` and `input MATCH = LABEL`, give a part a name of the person's own (ADR-1403 D4). vtium checks a label's match as it checks a rule's match. A label is at most `LABEL_MAX` characters. A bad line is an error that drops that line alone. `Config::label` finds a device's label. The label comes from the first line of the device's kind whose match matches the device, just as the first matching rule places a device.
- **The complete route.** `complete_route` takes the configuration, and the devices present or `None`. A complete route sends each display present, by the display's first matching rule, to a head that a keyboard present reaches. The keyboard reaches that head by a rule to the head, or by roaming into it when the head is not isolated. With no display or no keyboard present, or with `None`, `complete_route` judges the rules alone. Then a display rule that no earlier rule shadows must send displays to a head that keyboards reach. Keyboards reach the head by `class:keyboard`, by `*`, by the policy, or by a rule naming one device. `Missing` says in words the first thing a route lacks. `Judged` says how `complete_route` judged. The console's start never calls `complete_route`.
- **The section writer.** A draft may be unfinished (ADR-1403 D8). So each writer edits a file whatever `vtium check-config` would say of the file or of the result. For example, the result may hold a value out of bounds, or a rule that sends to a head that no section declares. The check reports those, at an install and in `vtium check-config`. Each writer finds what it edits by the file's lines alone: the section headings and the lines of `[rules]`. A writer changes only the lines it needs.
- **What a writer refuses.** A writer refuses only an edit it cannot place. That is a section or a rule that is not there, a section named twice, or text that it cannot write as one line that reads back as itself. It is also a line longer than `LINE_MAX` bytes, which vtium does not read. The rules are numbered from 1, in the order the lines of `[rules]` list them. A rule that vtium drops keeps its number.
- **Each writer.** `set_key` replaces a value in place, and keeps the blanks and a comment after it. It adds a missing key below its section's heading. It unsets a key by commenting out the key's line. `add_section` puts a look before the first head, and a head before `[rules]`. It gives a file with no flow its `version = 1`. `add_rule` puts a rule before the rule numbered `--before`. Otherwise it puts the rule where `placement` says: just before the first rule of its kind whose rank is lower, or else after the last rule (ADR-1403 D8).
- **The rank.** `Match::rank` gives a match's rank, from 1 for the most specific match to 7 for the catch-all, `*`. The most specific ranks are one device (`serial`, `edid`, `bluetooth`), then a port (`path`, `connector`, `connector-path`), then a graphics card (`card`). Below those come a model (`id`), a device name (`name`), and a device type or udev property (`class`, `udev`). The catch-all comes last. A match of several keys takes the rank of its most specific key.
- **Removing and renaming.** `remove_section` removes a section's heading and its lines, up to the section's last line that holds content. So the comments before the next heading stay. A head's rules stay too, and they then send to a head the file no longer declares. `rename_section` renames a section along with every line that names it. For a head, those are the rules that send to it. For a look, those are the heads' `look` lines.
- **Outcomes.** The module doc of [`src/outcome.rs`](src/outcome.rs) and its items say what runs for each state of vtium.conf's sections. They also say how a readable closed policy stays sticky, and what a reload applies. `outcomes.tsv` is their table, and `src/outcome/tests/runtime.rs` holds the run-time model.
