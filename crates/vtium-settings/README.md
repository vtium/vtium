# vtium-settings

The head file of ADR-1401: its reader, its parser, its one writer, and the evaluator that places each display and input in a head, roaming, in `ignore` or `off`, with the guards over the result. `vtium` and `vtiumctl` both link it, so the verdict before install is the verdict at boot. It depends on neither `vtium` nor `vtium-platform`: a device reaches it as an `Identity` its caller fills, and the guards are functions of a placement and the set of devices. It forbids unsafe code, denies every input-reachable panic, and depends only on rustix, to open the file as the console opens vtium.conf.

## Behaviour

- **The file.** `HEAD_FILE` is `/etc/vtium/heads.conf`, one file with no drop-ins, ADR-1401 probe 1's recommendation. `inspect` looks the path up with symlinks followed, returns `None` for a file that does not exist, the compiled-in configuration's case, and refuses anything but a regular file before it opens it, since opening a FIFO, a watchdog or a serial port acts on it; it opens without blocking, reads at most `FILE_MAX` bytes and one, and gives the bytes and the text beside the ownership verdict, so `vtium check-config` can check a candidate that is not yet root's. `read`, the start's reader, refuses a file root does not own or that its group or others can write, and a directory above it, on the path given or above any link of its symlink chain, each resolved one link at a time, that root does not own or that its group or others can write. `text` refuses, for the whole file, more than `FILE_MAX` bytes, bytes that are not UTF-8, and any control character but tab, newline and a carriage return ending a line, the C1 controls among them. `Trust::owner` trusts a test's own user in place of root, since no test runs as root, and `Trust::below` stops the directory check at a test's fixture directory, so a target directory under `/tmp` passes; `Trust::ROOT` checks every directory up to `/`.
- **The syntax.** A byte-order mark before the first line is dropped. Above the first section come `version = 1` and `policy = open` or `policy = closed`, in either order; anything else there is an error. A line there whose bytes, after its leading blanks, begin with `policy` in any case is a policy line, known before its bytes are decoded. A CRLF line ending is a newline. `#` starts a comment at the start of a line or after a blank, a `#` inside a word is part of it, so `login = cmd --x#1` keeps its `#`, and `\#` after a blank is a literal `#`. Blanks around `=` and between tokens are dropped, so a value holds no blank, and a glob's `?` stands for a space. A key set twice in one section or among the top-level keys, a second `[rules]`, and a second `[head NAME]` of one name are errors. The file has no `[guards]` section: the policy sets every guard.
- **What each error drops.** `reading` reads every line whatever came before it, each line's bytes checked on their own, so a check names every error, each with its line, in the file's order, and `at` shows it as `PATH:LINE: WHAT`, as vtium.conf's reports read, with every control and format character of the path escaped; `ERRORS_MAX` are kept and the rest counted. Each error drops what `scope` says: a bad rule, or a top-level line, drops that line, and a device walks on to the next rule; an error inside a head's section, or in its heading's name, drops the head with every rule naming it; an unknown section, a second `[rules]`, a second section of a head's name and a heading vtium cannot read drop that section, and the first section of the name stays; a missing or unknown `version`, a line past `LINE_MAX`, a file past `FILE_MAX` and a head or rule past its bound drop everything but the `policy` lines, which are always read. A line that is not UTF-8, or holds a control character, drops what an error on that line would. Every `policy` line counts, wherever it sits: one inside a section is an error that counts as no policy and drops only its line. A policy line above the first section that vtium cannot read, for a byte that is not UTF-8, a control character, a line past `LINE_MAX`, a cut at `FILE_MAX`, another key such as `Policy` or another value, makes the file closed and broken: `resolve` runs nothing of it under the closed policy, and the boot display shows the panic screen. A second readable `policy` line is a key given twice, which drops that line alone. What survives is a `Config`, with `policy` closed where a `policy = closed` line is readable or a policy line is not; `Reading::trusted` classifies the file for `resolve`. Text an error quotes is cut at `QUOTE_MAX` characters and shown with every control and format character escaped; a path is quoted whole.
- **The first cut's names.** The targets `focus` and `dark`, the head keys `on-loss` and `rescue`, the value `nohup` and the section `[guards]` are errors, each message naming the word that replaced it: `roaming`, `off`, `when-display-lost`, `isolated = yes`, `keep` and `policy`. `focus` and `dark` stay reserved, so a head of either name is an error that drops it with every rule naming it. A head's `font-name` and `font-size` are errors whose message names `profile`, since a head takes its font from its profile.
- **Heads.** A name is 1 to 64 of `A-Z a-z 0-9 . _ + -`, and `roaming`, `ignore` and `off` are reserved; a profile's name keeps the same rule. `consoles` is 1 to `CONSOLES_MAX`, and more gets the cap with a warning. `login` is kept as written, for vtium to read as vtium.conf's `login`. `when-display-lost` is `keep`, `hangup`, or `hangup DURATION`, the duration a count of seconds or with an `s`, `m` or `h` suffix, at most `u32::MAX` seconds. `isolated` is `yes` or `no`, kept as written, unset left to the policy, `no` under open and `yes` under closed; an isolated head is never the active head, and the rescue key leaves its keyboards where they are. A head's font is its profile's over vtium.conf's keys; until profiles have files, the `default` profile states nothing and any other states its frit, the frit of its name.
- **Rules.** A rule is `display MATCH -> TARGET` or `input MATCH -> TARGET`, with `*` alone or at most `TOKENS_MAX` tokens; a rule may name a head declared after it. `roaming` and `ignore` are an input's targets, `off` a display's. `path` matches its `ID_PATH` exactly or followed by `:` or `.`, so it takes every interface below it and every device on a hub in its port (`...:3.3` takes `...:3.3:1.0` and `...:3.3.2:1.0`, never `...:3.30:1.0`); `serial` and `edid` split their value at the first two `:`, so the serial may hold more; `id`, `serial`'s vendor and product and `edid`'s product are hex with or without `0x`; `connector` splits at its last `/`; `name`, `card`, both halves of `connector` and `udev`'s value are globs (`*` and `?`); every other value matches as written. A key of the other kind's devices matches nothing.
- **Warnings and notes.** A rule an earlier rule of its kind shadows (the earlier is `*`, or its tokens are among the later rule's) and a head's consoles past the cap are warnings. Input sent to a head by `id` or `name` alone is a note. `Config::needs_udev` lists the rules using a key that reads udev's database, for `vtium check-config` to note where no daemon runs.
- **Placement.** `walk` places one device by the first rule of its kind that matches it. With no match a display goes off, and an input roams under open and is ignored under closed; what survives of an open file with errors walks the shipped rules' input rules instead, which roam the keyboard, pointer and key classes and ignore every other input. `place` walks a set and runs the guards over it. The display guard, when no display reaches a head, lights the boot display (the connector lit at start, else the boot card's first connector in the kernel's order, else the first connector of the other cards in the kernel's order, so a connected display always lights; the boot card, the card's place in the kernel's order, the connector's place and then the whole identity break a tie): under open in the first head, or in the default head where the file has none, and under closed for a notice alone, which no head holds, or not at all for a valid closed file with no head. The active head starts on the boot display's head, else the first lit head in the file, and only on a head that can be the active head: a head the file declares that is not isolated, or the default head under open. A head is isolated as it writes `isolated`, else as the policy leaves it, and what survives of an open file with errors isolates no head. Under open, the anti-lockout guard, when no device counted as a keyboard reaches a head with a lit display, makes every keyboard-class device roam and moves the active head by the same rule as its start; with no lit head that can be the active head it moves nothing. Under closed the guard is off. While a keyboard reaches a lit head the active head stays where it is, lit or not. A device udev marks `VTIUM_ROLE=token` or `VTIUM_ROLE=numpad` is not counted. `rescue` says whether the rescue key takes a keyboard, which it does only under open and never from an isolated head; `disposition` whether an input is opened, opened for the rescue key alone, as an ignored keyboard is under open, or left closed; `lockout` the layer 1 warnings of the rules alone; and `idle_rules` the rules no present device matches.
- **Outcomes.** What runs for each state of the head file, how a readable closed policy stays sticky and what a reload applies are [`src/outcome.rs`](src/outcome.rs)'s module doc and its items, with `outcomes.tsv` as their table and the run-time model in `src/outcome/tests/runtime.rs`.

## Departures

- **An error can drop more than its line.** The configuration file's reader, the C reference's and vtium's alike, takes each line it can and reports the rest; a head file routes input and chooses login commands, so an error inside a head's section drops the head with every rule naming it, and an error in the file's structure drops everything but its policy (ADR-1401 D7).
- **The file must be root's, in root's directories, writable by no one else.** The C reference read any file at its path (ADR-1401 D10).
