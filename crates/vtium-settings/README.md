# vtium-settings

vtium's configuration: the key table that the console reads vtium.conf and its command line by and that vtium-config shows and edits it by (ADR-1201 D1), vtium.conf's line syntax and its line-by-line editor, and vtium.conf's sections, the looks, heads and rules of ADR-1401 and ADR-1403: their reader, their parser, their one writer, and the evaluator that places each display and input in a head, roaming, in `ignore` or `off`, with the guards over the result. `vtium` and vtium-config link it, so the verdict before install is the verdict at boot. It depends on neither `vtium` nor `vtium-platform`: a device reaches it as an `Identity` its caller fills, and the guards are functions of a placement and the set of devices. It forbids unsafe code and denies every input-reachable panic. It depends on rustix, to open the file as the console opens vtium.conf, and on vtium-font and vtium-term for the bounds and defaults the key table states, constants only.

## Behaviour

- **The file.** `CONF_FILE` is `/etc/vtium/vtium.conf`, one file with no drop-ins (ADR-1403 D3), which the notices and their next steps name. `inspect` looks the path up with symlinks followed, returns `None` for a file that does not exist, the compiled-in configuration's case, and refuses anything but a regular file before it opens it, since opening a FIFO, a watchdog or a serial port acts on it; it opens without blocking, reads at most `FILE_MAX` bytes and one, and gives the bytes and the text beside the ownership verdict, so `vtium check-config` can check a candidate that is not yet root's. `read`, the start's reader, refuses a file root does not own or that its group or others can write, and a directory above it, on the path given or above any link of its symlink chain, each resolved one link at a time, that root does not own or that its group or others can write. `text` refuses, for the whole file, more than `FILE_MAX` bytes, bytes that are not UTF-8, and any control character but tab, newline and a carriage return ending a line, the C1 controls among them. `Trust::running_as` trusts root's files and, for a vtium that runs as another user, that user's own, under the same check of who else can write them (ADR-1403 D3). `Untrusted::mend` gives the command that mends the path that fails, `chown root:root PATH` or `chmod go-w PATH`, and `Untrusted::refusal` the whole message for vtium.conf. `Trust::owner` trusts a test's own user in place of root, since no test runs as root, and `Trust::below` stops the directory check at a test's fixture directory, so a target directory under `/tmp` passes; `Trust::ROOT` checks every directory up to `/`.
- **The syntax.** A byte-order mark before the first line is dropped. Above the first section come `version = 1` and `policy = open` or `policy = closed`, in either order; anything else there is an error. A line there whose bytes, after its leading blanks, begin with `policy` in any case is a policy line, known before its bytes are decoded. A CRLF line ending is a newline. `#` starts a comment at the start of a line or after a blank, a `#` inside a word is part of it, so `login = cmd --x#1` keeps its `#`, and `\#` after a blank is a literal `#`. Blanks around `=` and between tokens are dropped, so a value holds no blank, and a glob's `?` stands for a space. A key set twice in one section or among the flow's top-level keys, a second `[rules]`, and a second `[head NAME]` of one name are errors. The file has no `[guards]` section: the policy sets every guard.
- **What each error drops.** `reading` reads every line whatever came before it, each line's bytes checked on their own, so a check names every error, each with its line, in the file's order, and `at` shows it as `PATH:LINE: WHAT`, as vtium.conf's reports read, with every control and format character of the path escaped; `ERRORS_MAX` are kept and the rest counted. Each error drops what `scope` says: a bad rule, or a top-level line, drops that line, and a device walks on to the next rule; an error inside a head's section, or in its heading's name, drops the head with every rule naming it; an unknown section, a second `[rules]`, a second section of a head's name and a heading vtium cannot read drop that section, and the first section of the name stays; a missing or unknown `version`, a line past `LINE_MAX`, a file past `FILE_MAX` and a head or rule past its bound drop everything but the `policy` lines, which are always read. A line that is not UTF-8, or holds a control character, drops what an error on that line would. Every `policy` line counts, wherever it sits: one inside a section is an error that counts as no policy and drops only its line. A policy line above the first section that vtium cannot read, for a byte that is not UTF-8, a control character, a line past `LINE_MAX`, a cut at `FILE_MAX`, another key such as `Policy` or another value, makes the file closed and broken: `resolve` runs nothing of it under the closed policy, and the boot display shows the panic screen. A second readable `policy` line is a key given twice, which drops that line alone. What survives is a `Config`, with `policy` closed where a `policy = closed` line is readable or a policy line is not; `Reading::trusted` classifies the file for `resolve`. Text an error quotes is cut at `QUOTE_MAX` characters and shown with every control and format character escaped; a path is quoted whole.
- **The first cut's names.** The targets `focus` and `dark`, the head keys `on-loss` and `rescue`, the value `nohup` and the section `[guards]` are errors, each message naming the word that replaced it: `roaming`, `off`, `when-display-lost`, `isolated = yes`, `keep` and `policy`. `focus` and `dark` stay reserved, so a head of either name is an error that drops it with every rule naming it. A head's `font-name` and `font-size` are errors whose message names `[look NAME]`, since a head takes its font from its look.
- **Heads.** A name is 1 to 64 of `A-Z a-z 0-9 . _ + -`, and `roaming`, `ignore` and `off` are reserved; a look's name keeps the same rule. `consoles` is 1 to `CONSOLES_MAX`, and more gets the cap with a warning. `login` is kept as written, for vtium to read as vtium.conf's `login`. `when-display-lost` is `keep`, `hangup`, or `hangup DURATION`, the duration a count of seconds or with an `s`, `m` or `h` suffix, at most `u32::MAX` seconds. `isolated` is `yes` or `no`, kept as written, unset left to the policy, `no` under open and `yes` under closed; an isolated head is never the active head, and the rescue key leaves its keyboards where they are. `vt` names the VTs the head runs on, one VT number from 1 to `VT_MAX` or several separated by blanks, as in `vt = 3 4` (ADR-1403 D4). A number outside that range, a word that is not a number, an empty `vt` and a number named twice are each an error that drops the head with its rules. A head with no `vt` runs on every VT. A head's `vt` is its own key, and it never sets the top level's `vt`, the VT vtium opens.
- **Rules.** A rule is `display MATCH -> TARGET` or `input MATCH -> TARGET`, with `*` alone or at most `TOKENS_MAX` tokens; a rule may name a head declared after it. `roaming` and `ignore` are an input's targets, `off` a display's. `path` matches its `ID_PATH` exactly or followed by `:` or `.`, so it takes every interface below it and every device on a hub in its port (`...:3.3` takes `...:3.3:1.0` and `...:3.3.2:1.0`, never `...:3.30:1.0`); `serial` and `edid` split their value at the first two `:`, so the serial may hold more; `id`, `serial`'s vendor and product and `edid`'s product are hex with or without `0x`; `connector` splits at its last `/`; `name`, `card`, both halves of `connector` and `udev`'s value are globs (`*` and `?`); every other value matches as written. A key of the other kind's devices matches nothing.
- **Warnings and notes.** A rule an earlier rule of its kind shadows (the earlier is `*`, or its tokens are among the later rule's) and a head's consoles past the cap are warnings. Input sent to a head by `id` or `name` alone is a note. `Config::needs_udev` lists the rules using a key that reads udev's database, for `vtium check-config` to note where no daemon runs.
- **Placement.** `walk` places one device by the first rule of its kind that matches it, with every head running whatever its `vt` says. With no match a display goes off, and an input roams under open and is ignored under closed; what survives of an open file with errors walks the shipped rules' input rules instead, which roam the keyboard, pointer and key classes and ignore every other input. `place` walks a set and runs the guards over it. The display guard, when no display reaches a head, lights the boot display (the connector lit at start, else the boot card's first connector in the kernel's order, else the first connector of the other cards in the kernel's order, so a connected display always lights; the boot card, the card's place in the kernel's order, the connector's place and then the whole identity break a tie): under open in the first head, or in the default head where the file has none, and under closed for a notice alone, which no head holds, or not at all for a valid closed file with no head. The active head starts on the boot display's head, else the first lit head in the file, and only on a head that can be the active head: a head the file declares that is not isolated, or the default head under open. A head is isolated as it writes `isolated`, else as the policy leaves it, and what survives of an open file with errors isolates no head. Under open, the anti-lockout guard, when no device counted as a keyboard reaches a head with a lit display, makes every keyboard-class device roam and moves the active head by the same rule as its start; with no lit head that can be the active head it moves nothing. Under closed the guard is off. While a keyboard reaches a lit head the active head stays where it is, lit or not. A device udev marks `VTIUM_ROLE=token` or `VTIUM_ROLE=numpad` is not counted. `rescue` says whether the rescue key takes a keyboard, which it does only under open and never from an isolated head; `disposition` whether an input is opened, opened for the VT keys alone, the rescue key among them, as an ignored keyboard is under open, or left closed; `lockout` the layer 1 warnings of the rules alone; and `idle_rules` the rules no present device matches.
- **Placement on each VT.** `walk_on` and `place_on` place devices for the vtium on one VT, by the four steps of ADR-1401 D3. A rule whose head runs on other VTs only notes that head, and the walk reads on. Once a head is noted, only a rule whose head's `vt` names this VT can place the device: a head with no `vt`, `roaming`, `ignore` and `off` leave it alone. When no rule places a device with a noted head, it stays with the first head noted, `Place::Elsewhere`: a display stays dark, and a keyboard types nowhere. Under open, `disposition` opens such a keyboard for the VT keys alone, and under closed where its head is not isolated, since its VT keys switch the VT (ADR-1401 D3, "Who switches VTs"); `rescue` lets the rescue key take it under open, as for an ignored keyboard. `place_on`'s guards take only the heads that run on its VT: the display guard lights the boot display for the first of them, or for the default head when none runs there, and only one of them can be the active head. Neither guard moves a device that stays with a head on another VT. For a valid file, `place_on` follows the maintainer's table in ADR-1401 D3, in place of the display guard. Under open, vtium shows on each display either a terminal or a notice that says why there is none, unless a rule turns that display off. Under closed, a display that no path names stays blank. When the file defines nothing, no head and no rule, under open `uses_builtin_on` says that vtium runs the built-in default terminal: it builds the default head alone, and `walk_on` places every display in `Place::DefaultHead` and every input by the shipped rules' input rules, by `By::Builtin`. When the file defines paths, under open `place_on` gives each display that no path catches on its VT, and that no rule turns off, `Place::Unused`: with the head it belongs to, whose `vt` names its VTs, or with `None` when no rule gives it a head. That includes a VT where none of the file's heads runs. Under closed such a display keeps its place, `Place::Elsewhere` or `Place::Off`, and stays blank. A display a rule sends to `off` stays blank on every VT. What survives of a file with errors keeps the display guard (D7). `heads_on_vt` lists the heads a VT builds. `walk` and `place` name no VT, and `complete_route`, `lockout`, `idle_rules` and the remarks use them.
- **vtium.conf's two parts.** `split` ends the top level at the first line whose first byte that is not a space or a tab is `[`, a heading vtium cannot read included. The top level holds vtium's own keys, which the console reads the forgiving way, and the flow's `version` and `policy` lines, which `sections` reads; `Split::key_lines` gives the console every top-level line but those, so neither part reads the other's lines and an error in a section never drops a top-level key. A file with no heading and no policy line holds no flow, so `sections` gives `None`, and vtium runs its compiled-in flow while the top level applies; a policy line alone is the flow's, so a file that states `policy = closed` is never read as open, and such a file needs no `version` line. A file with a section needs `version = 1`, and its absence drops every section but the policy. `value_for` reads what survives of the sections, as vtium runs them, so an error in one section changes only what it drops. A byte-order mark before the first line belongs to the top level and is no part of its first line, for `split`, `sections`, the top level's readers and the line editor alike, which keeps it the file's first bytes.
- **One comment rule.** `comment` finds a line's comment for the top level and the sections alike: `#` starts one at the start of a line or after a blank, a `#` inside a word is part of it, `\#` after a blank is a literal `#`, and a `#` that opens a `#rrggbb` value after the line's first `=` is part of the value. A `#` glued to a value, as in `font-size=12#big`, stays in the value, so `key_line` reads the value `12#big`, which the console reports as one it cannot read (ADR-1403 D4).
- **Looks.** `[look NAME]` takes `vtlook`, a name by the name rule, and the keys `keys::at(Level::Look)` lists, each checked against the key table's values and bounds: a value out of bounds is an error in the look, never clamped. Any error in a look drops that look, and a head that names it draws with the default look; a second look of one name drops alone, and more than `LOOKS_MAX` looks drop every section but the policy. `[profile NAME]` and a head's `profile` are errors whose message names `[look NAME]` and `look`. A head that names a look with no section draws with the default look, which `Warning::NoLook` reports; `[look default]`, when the file has it, is the look every head that names none draws with.
- **A head in vtium.conf** takes `look`, `consoles`, `when-display-lost`, `isolated`, `vt` and the keys `keys::at(Level::Head)` lists, `login` alone today, checked as a look's keys are. A key of the key table that a section kind cannot take is an error whose message names where it may be set.
- **The levels.** A head's own section wins over its look's, and its look's over the top level, which the command line has already set over the file's own lines (ADR-1403 D5). `Config::settings` gives a head's section keys, each once, at the most specific level, for the caller to lay over the top level, and `value_for` gives the value and level of one key from a file's text.
- **Labels.** The `[labels]` section's lines, `display MATCH = LABEL` and `input MATCH = LABEL`, give a part a name of the person's own (ADR-1403 D4). A label's match is checked as a rule's is, the label is at most `LABEL_MAX` characters, and a bad line is an error that drops that line alone. `Config::label` finds a device's label: the first line of its kind whose match matches it, as the first matching rule places a device.
- **The complete route.** `complete_route` takes the configuration and the devices present, or `None`. A display present must go by its first matching rule to a head that a keyboard present reaches, by a rule to that head or by roaming into it when it is not isolated. With no display or no keyboard present, or with `None`, it judges the rules alone: a display rule no earlier rule shadows sends displays to a head that keyboards reach, by `class:keyboard`, `*`, the policy or a rule naming one device. `Missing` says the first thing a route lacks in words, and `Judged` says how it judged. The console's start never calls it.
- **The section writer.** A draft may be unfinished (ADR-1403 D8), so each writer edits a file whatever `vtium check-config` would say of it or of the result, such as a value out of bounds or a rule that sends to a head no section declares; the check reports those, at an install and in `vtium check-config`. Each writer finds what it edits by the file's lines alone, the section headings and the lines of `[rules]`, changes only the lines it needs, and refuses only an edit it cannot place: a section or a rule that is not there, a section named twice, text it cannot write as one line that reads back as itself, or a line it would write longer than `LINE_MAX` bytes, which vtium does not read. The rules are numbered from 1 in the order the lines of `[rules]` list them, a rule vtium drops included. `set_key` replaces a value in place, keeping the blanks and a comment after it, adds a missing key below its section's heading, and unsets by commenting the line out. `add_section` puts a look before the first head and a head before `[rules]`, and gives a file with no flow its `version = 1`. `add_rule` puts a rule before the rule numbered `--before`, or where `placement` says: just before the first rule of its kind whose rank is lower, else after the last rule (ADR-1403 D8). `Match::rank` gives the rank, from 1 for the most specific match: one device (`serial`, `edid`, `bluetooth`), a port (`path`, `connector`, `connector-path`), a graphics card (`card`), a model (`id`), a device name (`name`), a device type or udev property (`class`, `udev`), and 7 for the catch-all, `*`. A match of several keys takes the rank of its most specific key. `remove_section` removes a section's heading and its lines up to its last line that holds content, so the comments before the next heading stay, and a head's rules stay, sending to a head the file no longer declares. `rename_section` renames a section with every line that names it: for a head each rule that sends to it, for a look each head's `look` line.
- **Outcomes.** What runs for each state of vtium.conf's sections, how a readable closed policy stays sticky and what a reload applies are [`src/outcome.rs`](src/outcome.rs)'s module doc and its items, with `outcomes.tsv` as their table and the run-time model in `src/outcome/tests/runtime.rs`.
