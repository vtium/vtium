# vtium-settings fuzz targets

Three cargo-fuzz targets in their own workspace, so the main workspace and CI never build them or pull `libfuzzer-sys`. vtium.conf is text anyone with root can write and any user can hand `vtium check-config`, so their readers are the crate's input surface. `reading` drives any bytes through the section reader of vtium.conf, read whole and as a flow (ADR-1401 D7, ADR-1403 D3), and `split` drives any bytes through the split at the first section heading and the top level's line editor (ADR-1403 D8). `sections` drives the section writer (ADR-1403 D7, D8), which edits drafts that may not pass the check and whose result is installed to /etc/vtium/vtium.conf for root. Run each on nightly from this directory: `cargo +nightly fuzz run reading`, `cargo +nightly fuzz run split`, `cargo +nightly fuzz run sections`.

From the repository's root, `make fuzz FUZZ_TARGETS=vtium-settings:reading` runs a target from a fresh corpus outside the repository and appends a row to `runs.tsv`, the record of how long each run lasted, against which commit, and what it found.

| Path | What it is |
|---|---|
| `fuzz_targets/reading.rs` | Any input as vtium.conf, read whole and as a flow: no panic, every rule that survives sends its devices to a head that survives, and the section reader names no error on a line that holds one of vtium's own top-level keys. It reaches the line checks, the policy line, every section's reader with the key table's values and bounds, the rules and their match tokens, and what each error drops. |
| `fuzz_targets/split.rs` | Any input as vtium.conf: no panic, the top level and the sections are the whole file in order, the top level holds no heading and numbers its lines up to the first heading, and setting a key with the line editor leaves the sections byte for byte while vtium takes the new value. It reaches the split, the one comment rule and the line editor. |
| `fuzz_targets/sections.rs` | A text built from vtium.conf's own lines (headings, keys, rules, comments and blank lines) and from any text, with either line ending and an optional byte-order mark, then up to four of the section writer's edits with generated arguments: `set_key`, `add_section`, `remove_section`, `rename_section`, `add_rule`, `set_rule`, `move_rule` and `remove_rule`. Some of the lines, values and rules are padded with filler to a few bytes either side of `LINE_MAX`, because libFuzzer's input cap of 4096 bytes keeps the target from building a line that long byte by byte. After each edit the writer accepts, the target checks that the result reads with no structural error the text before did not have, such as a heading vtium cannot read, a line in no section's syntax, a control character, a line longer than `LINE_MAX`, or a `version` line inside a section. It checks that the top level keeps its lines in order and gains only a `version = 1` line where it had none. It checks that every line the edit does not need, comments included, stays byte for byte, and that the lines the edit writes are the ones it was asked to write, in the place it was asked to put them. An error on a line the text already held, in a section of the same heading, counts as the text's own, because a heading vtium dropped, such as a second `[rules]`, can hide it from the reader until a rule moves out. It reaches every function of the writer and the reader's checks of what the writer writes. |
| `Cargo.toml`, `Cargo.lock` | The fuzz crate and its pinned dependencies. |
| `.gitignore` | Leaves out `target`, `corpus`, `artifacts` and `coverage`. |
