# vtium-settings fuzz targets

Six cargo-fuzz targets in their own workspace, so the main workspace and CI never build them or pull `libfuzzer-sys`. vtium.conf is text anyone with root can write and any user can hand `vtium check-config`, so their readers are the crate's input surface. `reading` drives any bytes through the section reader of vtium.conf, read whole and as a flow (ADR-1401 D7, ADR-1403 D3), and `split` drives any bytes through the split at the first section heading and the top level's line editor (ADR-1403 D8). `sections` drives the section writer (ADR-1403 D7, D8), which edits drafts that may not pass the check and whose result is installed to /etc/vtium/vtium.conf for root. `vtium-settings`'s other three readers take files root installs: `vtlook` drives any bytes through the vtlook reader, built with the `filters` feature (ADR-1304 D4, D6), `palette` drives any bytes through the palette reader, which reads a color scheme in every build (ADR-1205 D10), and `cube` drives any bytes through the `.cube` reader (ADR-1304 D9, D14). Run each on nightly from this directory: `cargo +nightly fuzz run reading`, `cargo +nightly fuzz run split`, `cargo +nightly fuzz run sections`, `cargo +nightly fuzz run vtlook`, `cargo +nightly fuzz run palette`, `cargo +nightly fuzz run cube`.

From the repository's root, `make fuzz FUZZ_TARGETS=vtium-settings:reading` runs a target from a fresh corpus outside the repository and appends a row to `runs.tsv`, the record of how long each run lasted, against which commit, and what it found.

| Path | What it is |
|---|---|
| `fuzz_targets/reading.rs` | Any input as vtium.conf, read whole and as a flow: no panic, every rule that survives sends its devices to a head that survives, the section reader names no error on a line that holds one of vtium's own top-level keys, and `policy`, the policy read alone as `vtium.enable=0` reads it, equals the policy of the whole reading. It reaches the line checks, the policy line, every section's reader with the key table's values and bounds, the rules and their match tokens, and what each error drops. |
| `fuzz_targets/split.rs` | Any input as vtium.conf: no panic, the top level and the sections are the whole file in order, the top level holds no heading and numbers its lines up to the first heading, and setting a key with the line editor leaves the sections byte for byte while vtium takes the new value. It reaches the split, the one comment rule and the line editor. |
| `fuzz_targets/sections.rs` | A text built from vtium.conf's own lines (headings, keys, rules, comments and blank lines) and from any text, with either line ending and an optional byte-order mark, then up to four of the section writer's edits with generated arguments: `set_key`, `add_section`, `remove_section`, `rename_section`, `add_rule`, `set_rule`, `move_rule` and `remove_rule`. Some of the lines, values and rules are padded with filler to a few bytes either side of `LINE_MAX`, because libFuzzer's input cap of 4096 bytes keeps the target from building a line that long byte by byte. After each edit the writer accepts, the target checks that the result reads with no structural error the text before did not have, such as a heading vtium cannot read, a line in no section's syntax, a control character, a line longer than `LINE_MAX`, or a `version` line inside a section. It checks that the top level keeps its lines in order and gains only a `version = 1` line where it had none. It checks that every line the edit does not need, comments included, stays byte for byte, and that the lines the edit writes are the ones it was asked to write, in the place it was asked to put them. An error on a line the text already held, in a section of the same heading, counts as the text's own, because a heading vtium dropped, such as a second `[rules]`, can hide it from the reader until a rule moves out. It reaches every function of the writer and the reader's checks of what the writer writes. |
| `fuzz_targets/vtlook.rs` | Any input as a vtlook. The first byte chooses the declarations it is read against: vtium's own color filters, or a fixed list with a parameter of every kind and one with no default. The target checks that nothing panics. A vtlook read cleanly against vtium's own declarations holds no spatial filter, and its color filters build their color table. A vtlook that reads cleanly has one value for each declared parameter, of its kind and within its range. A vtlook that fails names at least one error and at most `ERRORS_MAX`, each about the file it was given, on a line the file has. It reaches the line reader, the byte-order mark, the comment rule, the version line, the section headings and their bound, the `[requires]` keys and their pairs, the filters' lookup, the value parsers of every kind, a parameter left unset with no default, the bound on errors and quotes, the error report and log line, and the color table built from vtium's own filters (ADR-1304 D2), which fails at the reading stage only for a `cube` filter, whose file the target gives no batch to read through. |
| `fuzz_targets/cube.rs` | Any input as a `.cube` file. The target checks that nothing panics. A file that reads cleanly has a size within the bounds and builds its color table. A file that fails names at least one fault and at most `ERRORS_MAX`, each on a line the file has, with no control character in its message. It reaches the byte-order mark, UTF-8, the comment rule, each keyword and its checks, a keyword twice or after the data, both sizes in one file, the number grammar with its sign and exponent, the count of data lines, the clamp to 0 to 1, the bound on faults, and the trilinear and linear blends that build the table (ADR-1304 D2, D9). |
| `fuzz_targets/palette.rs` | Any input as a palette file. The target checks that nothing panics. A file that reads cleanly is within `PALETTE_FILE_MAX` bytes, and lists each key vtium ignores once, in the file's order, on a line the file has, and never a key vtium reads. A file that fails names at least one error and at most `ERRORS_MAX`, each on a line the file has, and a file over the bound fails as too large alone. Every reason and the log line print without a control character. It reaches the size bound, the byte-order mark, UTF-8, the comment rule, the `key = value` split and a quoted value, each key vtium reads, the `N=COLOR` entry and its index, the three forms of a color and the X11 names, the cell words, the ignored keys, and the bound on errors. |
| `Cargo.toml`, `Cargo.lock` | The fuzz crate and its pinned dependencies. |
| `.gitignore` | Leaves out `target`, `corpus`, `artifacts` and `coverage`. |
